从「弱教强」到「验证即 scaling」：今天 arXiv 上 LLM 推理训练的三大新范式

📌 核心摘要：今天的 arXiv 上，三篇来自不同顶级团队的论文不约而同地指向同一个方向——LLM 推理训练的效率革命。ByteDance/Tsinghua 的 Direct-OPD 提出用弱模型的策略偏移信号教强模型，4 小时内让 Qwen3-1.7B 在 AIME 2024 上飙升 14 个百分点；Microsoft 的 ReOPD 解决了多轮 Agent 蒸馏中的"前缀陷阱"，实现零工具调用、4 倍加速；Berkeley/Stanford 的 LLM-as-a-Verifier 则彻底改写了验证的定义——用连续评分取代离散判断，将"验证"推向与预训练并肩的新 scaling axis。这三篇放在一起，正在描绘一幅清晰的图景：后训练效率的下一站，不在更大的模型，而在更聪明的信号传递。

一、研究背景与动机

当 RL 本身成为瓶颈

LLM 的推理能力在过去一年经历了飞跃，核心推手之一是 RLVR（Reinforcement Learning with Verifiable Rewards）。从 DeepSeek-R1 到今天的 OpenThoughts，GRPO 等无评论家策略优化几乎成为了推理模型的标配。然而有一个问题越来越尖锐：RLVR 的训练成本随模型规模爆炸式增长。

每轮 RL 更新都需要目标模型在环境中产生海量 rollout——对于 70B+ 的模型，这意味数十万美元的算力消耗。当模型家族从 1.7B 一路延伸到 235B，光是做一轮完整的 RL 后训练就可能掏空一个中小团队的预算。

更致命的问题：每次升级到更大的模型，RL 过程必须从头再来。

弱到强：诱人但实操中翻车的想法

一个朴素的想法因此浮现：既然小模型做 RL 成本低，能不能在小模型上跑完 RL，然后把"成果"蒸馏给大模型？

听起来很美。但研究人员发现，直接蒸馏 RL 后的小模型效果很差。原因是 teacher 的最终策略混杂了两种成分——真正的 RL 增益和小模型的固有局限。学生模型比老师强，反而不知道该信哪个。

ByteDance/Tsinghua 团队在 Direct-OPD 中提出的洞察是：你需要搬的是 RL 过程本身留下的"痕迹"，而不是 RL 结果。

一组需要被串联的问题

如果把三篇论文放在一起看，它们回答的是推理训练效率革命的不同侧面：

问题对应论文
如何把小模型的 RL 训练成果传递给大模型？Direct-OPD
如何让 Agent 多轮交互蒸馏不再依赖昂贵的环境交互？ReOPD
如何不训练专门模型，就能评估和指导推理过程？LLM-as-a-Verifier

二、核心方法

Direct-OPD：传输"策略偏移"，而非"最终策略"

Direct-OPD 的核心洞察：不要教学生老师最终给出的答案，要教学生 RL 让老师改变的那部分。

具体来说，Direct-OPD 使用了两个 checkpoint 计算 log-ratio：

  • Teacher-post-RL：RL 训练后的弱模型
  • Teacher-pre-RL：同一弱模型 RL 训练前的 reference

这个 log-ratio 本质上是一个 密集隐式奖励信号（dense implicit reward），告诉学生哪些动作 RL 训练让老师更倾向于选择。

关键设计：信号是在 学生自己 on-policy 的状态 上计算的——让学生生成状态，再用老师的"策略偏移"来评估学生应该怎么做。这解决了两个痛点：不需要训练显式 reward model；不需要在学生上跑稀疏奖励的 RL。

ReOPD：「前缀陷阱」与优雅解法

微软团队在 ReOPD 中聚焦多轮 Agent 任务的 on-policy 蒸馏。完全在线的 OPD 成本极高——每次更新都需要学生在真实环境中 rollout。

ReOPD 提出：复用预先收集的老师轨迹作为"重放前缀"。但这里藏着一个被称为 "前缀陷阱"（prefix trap） 的问题：

让历史越接近学生自己的 on-policy 分布，对学生越相关，但此时在前缀上调用的老师的"目标"可能是不可靠的——因为老师在自己没见过的状态上也可能犯错。

ReOPD 的解法：把多轮 OPD 建模为可靠性感知的前缀分布设计问题。 具体实现是一个步数衰减采样策略——更早的前缀被赋予更高的采样权重。简单策略，但实验证明出奇有效。

LLM-as-a-Verifier：把"验证"变成一条 scaling 曲线

来自 Berkeley SkyLab（Chelsea Finn、Ion Stoica 等）的这篇论文提出了第三条 scaling 轴——验证（verification）。

传统方案是让 LLM 打离散分。LLM-as-a-Verifier 的方案是：计算评分 token 逻辑值分布上的期望，得到连续分数。

这让验证沿着三个维度分别 scaling：

  1. 评分粒度——更精细的评分范围意味着正负方案之间更好的分离度
  2. 重复评估——多次评估取期望，方差降低
  3. 准则分解——单一标准分解为多个子标准，复杂度降低

不需要额外训练，直接复用已有 LLM 的 scoring token logits。产生的连续分数还可作为任务进度代理估计，甚至为 GRPO 和 SAC 提供密集反馈。

四、技术启示与发展方向

趋势一：信号取代规模

这三篇论文共同指向一个趋势：后训练效率的下一个突破点不在更大的模型或更多的算力，而在更聪明的信号设计。

  • Direct-OPD 用一对 checkpoint 的 log-ratio 替代显式 reward model
  • ReOPD 用重放前缀 + 步数衰减替代完整在线交互
  • LLM-as-a-Verifier 用连续 logit 期望替代离散评分

趋势二：验证作为基础设施

LLM-as-a-Verifier 的作者为 Claude Code 写了 extension，让开发者实时监控 Agent 系统的任务执行进度。这意味着验证正在从"训练后评估"走向 "训练中反馈 + 部署中监控" 的全链路角色。

趋势三：离线成为新常态

ReOPD 提出"零工具调用"的 offline 蒸馏，Direct-OPD 则完全不需要在目标模型上跑 RL——两者都在推动：昂贵的环境交互只在训练做一次，后续的模型升级靠重放和信号传递。

局限与挑战

  • Direct-OPD：policy shift 是否总是可靠信号？当老师被 RL 搞出偏差时怎么办？
  • ReOPD：步数衰减策略实验有效，但最优采样分布依赖于未知联合分布，推广性待验证。
  • LLM-as-a-Verifier：依赖底层 LLM 的 logit 校准程度，校准不良时增益打折扣。

五、总结

今天 arXiv 上的这三篇论文，不是孤立的突破——它们是同一个更大故事的不同章节。这个故事是：LLM 推理训练的瓶颈，正在从算力转移到信号设计。

当你往 70B 模型上跑 GRPO 需要一个月时，有人告诉你可以用 1.7B 的小模型跑完 RL，然后 4 小时传功给大模型。当你纠结于 Agent 蒸馏的高环境成本时，有人告诉你重放老师轨迹 + 步数衰减就能零工具调用搞定。当你厌倦了用离散分数糊弄验证时，有人告诉你 logit 期望 + 三路 scaling 就能在四个基准上实现 SOTA。

这些工作让我们从"堆模型"的思路中稍微抽离出来，看到了另一条路的可能：不是更大，而是更聪明。
