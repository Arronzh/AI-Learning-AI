### 新组件提取（GPT-5.6 GA 产品发布页）

| 组件 | 结构 | 适用场景 |
|------|------|---------|
| **「Efficient by default, power on demand」** 标题式定位 | 开篇用一句话定义产品哲学（默认高效+按需极致） | 多档产品/分层服务体系报道 —— 先定义"默认值"再展"极限值" |
| **「Pareto chart + companion description」双模展示** | 图表+下方注解双行：图表展示数据分布，文字展示"少用 X% token 达到同水平" | 任何性能/成本对比——比纯表格更有叙事层次 |
| **「Cost-efficiency triplet」公式** | "少 X% token + 少 Y% 时间 + 省 Z% 成本" 三重效率指标并列 | 效率类报道 —— 三个维度永远一起出现，比单一指标更有冲击力 |
| **「Internal as proof + 100x growth」自用叙事** | 内部采用数据（2x 研究员产出）+ 增长倍数（100x 编码推理）作为产品价值的第一证据 | 产品/工具报道 —— "我们自己先用"是最高信服力 |
| **「Partner testimonial scroll」生态引语排列** | 页面中嵌入多段滚动引语（Cursor + Lovable），每段来自不同合作方，各展示不同维度的使用数据 | 产品发布/生态报道 —— 用合作方数据替代自夸 |
| **「Four-box design gallery」视觉展示法** | 四格并排展示设计输出（Sailing game / Tiny voids / Museum / Clockwork village）—— 用视觉作品证明设计能力，而非用数据 | 创意/设计能力报道 —— 视觉替代数据 |
| **「Dual-use framework」安全声明** | "同样的能力可用来防御也可用来攻击"→ "过度封锁本身就是安全风险"→ "上下文判断" | 任何涉及敏感能力的安全报道 —— 双面立场 + 平衡叙事 |
| **「Faster-than-retraining」安全架构** | "推理时安全更新不需要重新训练分类器"—— 用速度/灵活性指标说明安全体系的先进性 | AI 安全/治理报道 —— 速度本身是安全质量信号 |
| **「10x more blocking + friction acknowledgment」诚实约束** | 明确承认安全措施增加了摩擦，同时提供降级回退路径 | 涉及安全/限制/管控的产品报道 —— 诚实 + 解决路径 |

## 🔥 新增发现 2：ChatGPT Work —— 产品重新定义

### 核心定位变更
从 **"AI 助手"（assistant）** → **"工作伙伴"（partner）**
- 核心句："From answering questions to getting real work done"
- 对标用户行为变化：5M+ weekly Codex 用户，其中 1M+ 用于非软件开发工作
- 全新产品线：ChatGPT Work（agent）、Scheduled Tasks（定时任务）、Sites（发布网站）、Plugins 目录（统一） 

### 关键数据
- **Nearly 100% teams inside OpenAI**（含 finance, sales）使用 ChatGPT Work
- **Sales**：24小时从 Discovery 到 PoC（原数周）→ "high-value consultative partner"
- **Finance**：月结从 Days→Hours
- **Desktop app 合并**：Codex 并入 ChatGPT 桌面端，原 ChatGPT 重命名 Classic

### 新组件提取（ChatGPT Work 发布页）

| 组件 | 结构 | 适用场景 |
|------|------|---------|
| **「From A to B」产品定位升级** | "From answering questions to getting real work done"——用"从_到_"概括产品进化方向 | 产品升级/品牌重新定位报道 —— 一句话讲清"以前做什么，现在做什么" |
| **「1M non-developers」采用数据冲击** | "5M weekly users → 1M of them are non-developers"——用细分人群数据证明显著性转变 | 产品民主化/跨界采用报道 |
| **「24h = Weeks」工作流对比** | 具体案例（Sales 数周→24h）+ 角色转型描述（"freeing the lead to focus on the customer"） | 企业级 AI 采用/效率提升报道 |
| **「Days→Hours」财务流程对比** | "month-end close and forecasting from days to hours" + 节省时间后的工作内容描述 | 效率叙事 —— "省下的时间用来做什么"比"省了多少时间"更有价值感 |
| **「Plugin directory + @mentions」产品细节** | "输入 @+app 名即可引用"——具体交互细节让功能可视化 | 产品功能解读 —— 具体交互比功能名称更有画面感 |
| **「Scheduled Tasks」产品叙事** | "要求每早检查 + 发现有变化时更新 + 发送报告"——用使用场景列表代替功能描述 | 被动→主动转变类产品报道 |
| **「Auto-review」治理框架** | "重要操作由最先进模型在操作前复审"——用"前置审核"消除安全顾虑 | 企业/安全/合规类产品叙事 |
| **「Near 100% internal adoption」内部普及叙事** | "Nearly 100% of teams inside OpenAI now use it, including finance and sales"——用内部普及率作为质量信号 | 产品可信度建立 —— 内部采用 > 外部数据 |
| **「From goals to outcomes」案例分组** | 按团队/部门组织案例（Sales/Finance/...），每个附可用提示词模板 | 企业产品报道 —— "给模板"比"讲故事"更实用 |
