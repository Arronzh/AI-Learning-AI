### 文章一：How news organizations are using AI（新闻业 AI 案例）

**文章类型**：行业垂直案例编译（非产品发布，非思想领导力）
**关键特征**：这是 OpenAI 首次以"单一行业"（新闻/媒体）为轴心的案例合集，每个案例由其自己声音叙述

**叙事结构**：
```
行业总体框架 → 三支柱展开（Empowering journalism / Growing audiences / Strengthening business）
→ 每支柱下分散案例（AP → POLITICO → Axios → Inquirer → Axel Springer → Future → Le Monde...）
→ People-centered coda 收尾
```

**新写作组件（5 个）**：

1. **「Industry vertical case compilation」行业案例集**——首次聚焦单一行业（新闻业）的案例合集，而非跨行业案例散列
2. **「In their own words」编辑框架**——"in the words of the news organizations themselves"，让客户用自己的声音说话，避免"我们声称"的立场偏差
3. **「Three-pillar industry value」三支柱行业价值**——"Empowering journalism / Growing audiences / Strengthening business"，覆盖新闻业的三种价值维度（内容生产→读者体验→商业模式），适合任何 2B 行业案例编译
4. **「Vertical-specific workflow depth」垂直工作流深度**——每个案例展示了**具体工具名称+用途**（FOIA Refiner GPT / Scribe / Data Scouts），而非泛泛说"AI帮助他们"——具体工具名称让案例可记忆、可引用
5. **「National-to-local coverage breadth」全国到本地的覆盖广度**——"38 个州的出版物"展示规模和覆盖面，建立"不是孤例"的社会证明

**关键观测**：这是 OpenAI 7月一个新的内容类型——行业案例合集。7/21 的 Small Business Program + 7/22 的 News 案例，可能标志着 OpenAI 开始按行业维度组织客户叙事。预计接下来可能有 Health/Finance/Education 等行业案例。

### 文章二：Introducing OpenAI Presence（企业可信 Agent 部署平台）

**文章类型**：Enterprise Product Launch（重大企业产品发布）
**核心定位**：从"AI agent can work"到"make them reliable enough for production"——面向生产环境的企业级 Agent 平台

**叙事结构**：
```
挑战升级开场（proving→reliable）→ 产品定义（what it is）→ 部署哲学（one job at a time）
→ 功能组件（policies/guardrails/escalation/simulations）→ 内部证明（1-888-GPT-0090, 75%）
→ 企业案例（BBVA/SoftBank/IAG）→ 信任体系（before/during/after launch）→ 可用性
```

**新写作组件（8 个）**：

1. **「Challenge is no longer X, it's Y」转型开场**——"The challenge for enterprises is no longer proving that AI agents can work, it's making them reliable enough to do high-value work in production"——先否定旧问题再提出新问题，建立文章的必要性
2. **「One job at a time」最小化部署哲学**——"Each deployment starts with a specific job... The agent receives only the knowledge and system access required for that job"——以"一个具体工作"为单位，而非"全平台改造"，降低了读者认知负担
3. **「Policies/Guardrails/Escalation」三层治理**——"what the agent can do / when it needs approval / when a person should take over"——三句话覆盖从自主到人工的完整权限光谱
4. **「Codex-powered improvement loop」自适应闭环**——"Production sessions and escalations reveal gaps. Codex proposes updates that teams can test and approve"——发布后持续改进而非一次性交付，将运维升级为可测试、可管控的选择
5. **「Internal as proof 2.0：own phone support」自用验证**——"Presence powers OpenAI's own English-language phone support at 1-888-GPT-0090"——数字比之前的内部证明更具体（"打电话到这个号码试试"），然后附加数据："75% without human assistance" + "15pp handoff reduction in 10 days"
6. **「Before/During/After trust architecture」三时间信任体系**——发布前（simulations+graders）→ 发布中（monitoring+guardrails）→ 发布后（production signals+Codex updates）——覆盖全生命周期
7. **「Learn with you」持续进化声明**——"designed to learn with you—improving as your business, customers, and employees evolve while the business stays in control"——将产品从"工具"升级为"有成长性的伙伴"
8. **「Enterprise FDE-led model」高触达部署声明**——"Deployments are led by OpenAI Forward Deployed Engineers and select global systems integrators. Presence is not yet available as a self-serve product"——明确展示企业级产品的高门槛 + 人力投入 = 质量信号
