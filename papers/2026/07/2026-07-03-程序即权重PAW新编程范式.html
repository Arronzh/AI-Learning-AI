程序即权重：当 0.6B 模型通过「编译」匹敌 32B，一种新编程范式悄然诞生

📌 核心摘要：本文聚焦于 2026 年 7 月 arXiv 最新研究「Program-as-Weights (PAW)」，提出了一种革命性的「模糊函数编程」范式——将自然语言规格说明编译为紧凑的神经构件，让 0.6B 的轻量解释器执行 PAW 程序即可匹敌直接调用 32B 大模型，推理显存仅需 1/50，在 MacBook M3 上即可达到 30 tokens/s 的运行速度。同时，DecompRL 从另一维度探索了模块化解构重组的路径，将 GPU 推理成本降低约 50 倍。这些工作正在重新定义「大模型的使用方式」。

---

一、研究背景与动机

日常编程中，我们经常会遇到一类「模糊任务」：标记重要的日志行、修复格式异常的 JSON、按意图排序搜索结果……这些任务很难用确定性规则精确描述，却又不需要大模型全量推理能力。

当前主流方案是直接调用 LLM API：每次请求都让大模型从头推理一次。这种做法带来了三方面的痛点：

  • 高成本：每次调用都经过完整的前向传播
  • 高延迟：无法在本地快速响应
  • 不透明：重复调用之间的不确定性

来自哈佛大学和 MIT 的研究团队提出的 Program-as-Weights (PAW)，试图从根本上改变这种局面——他们给出的答案是：把大模型看作「工具构建者」，而非「逐次求解者」。

二、核心方法

2.1 模糊函数编程：一种新范式

PAW 的核心思想十分精妙：将自然语言描述的函数规格说明「编译」为一个紧凑的、可在本地执行的神经构件。

具体来说，PAW 使用一个 4B 参数的「编译器」模型，该模型在作者发布的 FuzzyBench（包含 1000 万个示例的数据集）上训练，能够为输入的 NL 规格说明生成参数高效的适配器（adapter），供一个冻结的轻量级解释器执行。

2.2 模型架构

PAW 的架构包含两个关键组件：

1. Compiler（编译器，4B 参数）：接受自然语言函数定义，输出参数高效的适配器权重

2. Interpreter（解释器，0.6B 参数）：基于 Qwen3 的轻量模型，冻结权重，执行编译后的适配器

这个过程借鉴了传统编译器的「一次编译、多次执行」的哲学，但编译的目标不是机器码，而是神经网络权重。

2.3 关键结果

  • 性能匹敌：0.6B 的 Qwen3 解释器执行 PAW 程序，在各种模糊函数任务上匹配甚至超越了直接提示 Qwen3-32B 的表现
  • 极致高效：推理显存仅需直接推理的 1/50
  • 本地可运行：在 MacBook M3 上即可达到 30 tokens/s
  • 可复用性：一次编译生成的构件可重复使用，后续调用无需再经过大模型 API

三、实验结果

3.1 PAW 的主要评估

研究团队在多个模糊函数任务上进行了系统评估：

维度PAW (0.6B 解释器)直接提示 Qwen3-32B
推理显存极低高（约 50×）
推理速度30 tokens/s (M3)需高端 GPU
函数精度相当或更优基准线
可复用性编译一次、无限次执行每次需重新推理
本地部署✓✗

研究团队强调，PAW 的关键价值在于重新定义了大模型的使用方式：从「每输入一个问题都调用大模型推理」转变为「每个函数定义调用一次大模型进行编译，后续应用该函数的调用变得廉价且离线可用」。

3.2 DecompRL：模块化解构的另一条路

与 PAW 的思路互补，DecompRL 探索了另一种路径——将困难问题分解为可独立求解的子函数，再通过组合产生大量候选解决方案。

DecompRL 的关键洞察是：当基础策略产生正确解的概率接近零时，无论多少采样或 RL 都无济于事——搜索空间太大。但如果将问题分解为 n 个模块，每个模块有 k 种实现，组合起来就能产生 kⁿ 个候选解，将瓶颈从 GPU 推理转移到廉价的 CPU 评估。

在 LiveCodeBench 和 CodeContests 上的实验表明：

  • DecompRL 将 GPU token 成本降低约 50 倍
  • 在单个问题推理预算超过 10⁵ tokens 时，DecompRL 显著超越标准 RL 和多样性优化 RL 基线
  • 能解决标准生成方法无法达到的困难问题

四、技术启示与发展方向

4.1 「大模型」不等于「每次都大」

PAW 最重要的启示是：我们可能对大模型的使用方式存在根本性的误解。传统观点认为，「更强的能力 = 更大的模型 = 每次都推理」。但 PAW 表明，大模型完全可以扮演「编译器」的角色——它智慧地产生一个小型的、高效的执行体，然后这个小执行体独立处理后续任务。

4.2 模块化思维正在回归

无论是 PAW 的「编译-执行」分离，还是 DecompRL 的「分解-组合」策略，都不约而同地指向一个方向：模块化思维正在 AI 领域回归。不是让大模型独立完成一切，而是让它构建更小的组件来协同工作。

4.3 对产业的影响

  • 边缘计算：PAW 这类技术使得在个人设备上运行高性能 AI 函数成为可能
  • 成本优化：企业可以将频繁调用的模糊逻辑从 API 调用迁移到本地执行，大幅降低成本
  • 可靠性提升：编译后的构件行为确定，避免了每次 API 调用的不确定性

五、总结

PAW 和 DecompRL 代表了一类正在兴起的研究方向——不是让模型变大，而是让模型的输出变小、变高效、变可复用。这种思路颠覆了「更强大的模型就是更大的模型」的直觉，揭示了一个更具工程美学的未来：大模型不再被当作每次都要亲力亲为的工匠，而是被当作能够创造工具的「工具创造者」。

这或许是 AI 工程化进程中一个被严重低估的范式转换。
