# 从「弱教强」到「验证即 scaling」：今天 arXiv 上 LLM 推理训练的三大新范式

📌 **核心摘要**：今天的 arXiv 上，三篇来自不同顶级团队的论文不约而同地指向同一个方向——LLM 推理训练的效率革命。ByteDance/Tsinghua 的 **Direct-OPD** 提出用弱模型的策略偏移信号教强模型，4 小时内让 Qwen3-1.7B 在 AIME 2024 上飙升 14 个百分点；Microsoft 的 **ReOPD** 解决了多轮 Agent 蒸馏中的"前缀陷阱"，实现零工具调用、4 倍加速；Berkeley/Stanford 的 **LLM-as-a-Verifier** 则彻底改写了验证的定义——用连续评分取代离散判断，将"验证"推向与预训练并肩的新 scaling axis。这三篇放在一起，正在描绘一幅清晰的图景：后训练效率的下一站，不在更大的模型，而在更聪明的信号传递。

---

## 一、研究背景与动机

### 当 RL 本身成为瓶颈

LLM 的推理能力在过去一年经历了飞跃，核心推手之一是 RLVR（Reinforcement Learning with Verifiable Rewards）。从 DeepSeek-R1 到今天的 OpenThoughts，GRPO 等无评论家策略优化几乎成为了推理模型的标配。然而有一个问题越来越尖锐：**RLVR 的训练成本随模型规模爆炸式增长。**

每轮 RL 更新都需要目标模型在环境中产生海量 rollout——对于 70B+ 的模型，这意味数十万美元的算力消耗。当模型家族从 1.7B 一路延伸到 235B，光是做一轮完整的 RL 后训练就可能掏空一个中小团队的预算。

**更致命的问题**：每次升级到更大的模型，RL 过程必须从头再来。这不仅浪费，而且不可持续。

### 弱到强：一个直觉上诱人但实操中翻车的想法

一个朴素的想法因此浮现：**既然小模型做 RL 成本低，能不能在小模型上跑完 RL，然后把"成果"蒸馏给大模型？**

听起来很美。但研究人员发现，直接蒸馏 RL 后的小模型（teacher）效果很差。原因是 teacher 的最终策略混杂了两种成分——真正的 RL 增益（学会了更好的推理路径）和小模型的固有局限（能力上限带来的妥协）。学生模型比老师强，反而不知道该信哪个。

ByteDance/Tsinghua 的团队在 Direct-OPD 中提出的洞察是：**你不需要把 RL 结果直接搬过去，你需要搬的是 RL 过程本身留下的"痕迹"。**

### 一组需要被串联的问题

如果把三篇论文放在一起看，它们回答的是推理训练效率革命的不同侧面：

| 问题 | 对应论文 |
|------|---------|
| 如何把小模型的 RL 训练成果传递给大模型？ | Direct-OPD |
| 如何让 Agent 在多轮交互中的蒸馏不再依赖昂贵的环境交互？ | ReOPD |
| 如何不训练一个专门模型，就能评估和指导推理过程？ | LLM-as-a-Verifier |

这三个问题在现实中往往是交织的——你要提升推理能力，先要知道当前方案好不好（Verifier），知道之后要传给更大的模型（Direct-OPD），具体到多轮 Agent 场景还要保证蒸馏效率（ReOPD）。

## 二、核心方法

### Direct-OPD：传输"策略偏移"，而非"最终策略"

Direct-OPD 的核心洞察可以用一句话概括：**不要教学生老师最终给出的答案，要教学生 RL 让老师改变的那部分。**

具体来说，Direct-OPD 使用了两个 checkpoint：
- **Teacher-post-RL**：RL 训练后的弱模型
- **Teacher-pre-RL**：同一弱模型在 RL 训练前（作为 reference）

然后计算两者的 log-ratio——这个比值本质上是一个**密集隐式奖励信号**（dense implicit reward），告诉学生：哪些动作 RL 训练让老师更倾向于选择，哪些则让老师不再考虑。

关键设计在于，这个信号是在**学生自己 on-policy 的状态**上计算的。也就是说，不是让老师给学生强塞它自己熟悉的状态下的答案，而是让学生生成状态，再用老师的"策略偏移"来评估学生应该怎么做。

这解决了两个痛点：
1. **不需要训练显式奖励模型**——一对 checkpoint 直接提供监督信号
2. **不需要在学生上跑稀疏奖励的 RL**——信号是密集的、连续的、每一步都有反馈的

### ReOPD：「前缀陷阱」与优雅解法

微软团队在 ReOPD 中聚焦的是一个更具体的场景：**多轮 Agent 任务的 on-policy 蒸馏。**

在多轮交互中，Agent 每说一句话，环境就返回一个结果，学生要模仿老师在这些交互历史中的决策。完全在线的 OPD 成本极高——每次更新都需要学生在真实环境中 rollout，还要在每个 visited history 上查询老师。

ReOPD 提出了一个"离线"替代方案：**复用预先收集的老师轨迹作为"重放前缀"（replayed prefixes）。**

但这里藏着一个被称为**"前缀陷阱"（prefix trap）**的微妙问题：

> 让历史越接近学生自己的 on-policy 分布，对学生越相关，但此时在历史前缀上调用的老师的"目标"可能是不可靠的——因为老师在自己没见过的状态上也可能犯错。

这是一个**双重分布偏移**：学生占据度（student occupancy）vs 老师可靠性（teacher reliability）。

ReOPD 的解法简洁有力：**把多轮 OPD 建模为一个可靠性感知的前缀分布设计问题。** 具体实现是一个**步数衰减采样策略**——更早的前缀（student occupancy 偏移较小）被赋予更高的采样权重，越往后的步骤权重越低。实验结果证明这个简单策略出奇有效。

### LLM-as-a-Verifier：把"验证"本身变成一条 scaling 曲线

这篇来自 Berkeley SkyLab（Chelsea Finn、Ion Stoica 等）的论文可能是三篇中最有野心的一个。

核心论点：**除了预训练 scaling、后训练 scaling、测试时计算 scaling，还有第四条 scaling 轴——验证（verification）。**

传统方案是让 LLM 作为"LM judge"对候选方案打一个离散分（好/坏，1-5 分）。LLM-as-a-Verifier 的方案是：**计算评分 token 逻辑值分布上的期望，得到连续分数。**

这个概率公式让验证可以沿着三个维度分别 scaling：
1. **评分粒度**（score granularity）——更精细的评分范围意味着正负方案之间的分离度更好
2. **重复评估**（repeated evaluation）——多次评估取期望，方差降低
3. **准则分解**（criteria decomposition）——把单一标准分解为多个子标准，复杂度降低

更妙的是，这套方法不需要额外训练——它直接复用已有 LLM 的 scoring token logits。而且它产生的连续分数不仅可以用来排名候选方案，还可以作为**任务进度的代理估计**（proxy for estimating task progress），甚至为 GRPO 和 SAC 提供密集反馈。

## 三、实验结果

### Direct-OPD

| 设置 | 成绩 | 对比 |
|------|------|------|
| Qwen3-1.7B on AIME 2024 | **48.3% → 62.4%** | 4 小时，8×A100 |
| 超越 step-matched 直接 RL | ✅ | 同等算力下胜出 |
| 顺序组合多个 policy shift | ✅ | 可叠加不同模型训练信号 |

团队特别强调，Direct-OPD 不仅优于直接蒸馏，而且**超越了在学生模型上直接跑 RL**——考虑到学生是老师数十倍的参数量，这个结果让人意外。

### ReOPD

| 设置 | 成绩 |
|------|------|
| 学生训练中工具调用 | **0 次**（完全离线） |
| 训练速度 | **至少 4× 比在线 OPD** |
| 准确性 | **保持或超越 OPD 级别** |
| 适用场景 | 数学推理（Python）、搜索环境、多种 teacher/student 规模组合 |

ReOPD 的意义不在于刷新 SOTA，而在于**把 Agent 蒸馏从昂贵的在线变成了可负担的离线**，这意味着一个预收集的老师轨迹可以像数据集一样被反复复用。

### LLM-as-a-Verifier

| 基准 | 分数 | 意义 |
|------|------|------|
| Terminal-Bench V2 | **86.5%** | SOTA，命令行工作流验证 |
| SWE-Bench Verified | **78.2%** | SOTA，软件工程任务 |
| RoboRewardBench | **87.4%** | SOTA，机器人奖励建模 |
| MedAgentBench | **73.3%** | SOTA，医疗 Agent |

除了这些基准测试，论文还展示了该方法作为 RL 密集反馈信号的实用性——为 SAC 和 GRPO 提供改进后的样本效率。

## 四、技术启示与发展方向

### 趋势一：信号取代规模

这三篇论文共同指向一个趋势：**后训练效率的下一个突破点不在更大的模型或更多的算力，而在更聪明的信号设计。**

- Direct-OPD 用**一对 checkpoint 的 log-ratio** 替代显式 reward model
- ReOPD 用**重放前缀 + 步数衰减**替代完整在线交互
- LLM-as-a-Verifier 用**连续 logit 期望**替代离散评分

这些都不是更大的模型，而是对已有信息更高效的利用。

### 趋势二：验证作为基础设施

LLM-as-a-Verifier 中特别有趣的一点是，作者为 Claude Code 写了一个 extension——让开发者可以在开发过程中实时监控 Agent 系统对任务的执行进度。这意味着验证正在从"训练后评估"走向**"训练中反馈 + 部署中监控"**的全链路角色。

如果验证真的成为第四条 scaling 轴，那么可以预见：**未来每个 Agent 系统都将内置一个不断打分、不断自我修正的 verifier 模块。**

### 趋势三：离线成为新常态

ReOPD 提出"零工具调用"的 offline 蒸馏，Direct-OPD 则完全不需要在目标模型上跑 RL——两者都在推动一个方向：**昂贵的环境交互只在训练做一次，后续的模型升级靠重放和信号传递，不再触达真实环境。**

这对于 Agent 系统的安全性和成本控制都有深远意义：一旦蒸馏过程不需要频繁调用外部工具或环境，潜在的 jailbreak 面和攻击面都大幅缩小。

### 局限与挑战

- **Direct-OPD** 的表面对齐假设：policy shift 是否总是可靠的信号？当老师被 RL 搞出偏差（reward hacking）时怎么办？
- **ReOPD** 的步数衰减策略虽然实验有效，但理论分析中说"最优采样分布依赖于未知的学生-老师联合分布"——推广性仍有待验证。
- **LLM-as-a-Verifier** 依赖底层 LLM 的 logit 校准程度。如果模型本身就校准不良，连续评分的增益可能会打折扣。

---

## 五、总结

今天 arXiv 上的这三篇论文，不是孤立的突破——它们是同一个更大故事的不同章节。这个故事是：**LLM 推理训练的瓶颈，正在从算力转移到信号设计。**

当你往 70B 模型上跑 GRPO 需要一个月时，有人告诉你可以用 1.7B 的小模型跑完 RL，然后 4 小时传功给大模型（Direct-OPD）。当你纠结于 Agent 蒸馏的高环境成本时，有人告诉你重放老师轨迹 + 步数衰减就能零工具调用搞定（ReOPD）。当你厌倦了用离散分数糊弄验证时，有人告诉你 logit 期望 + 三路 scaling 就能在四个基准上实现 SOTA（LLM-as-a-Verifier）。

这些工作让我们从"堆模型"的思路中稍微抽离出来，看到了另一条路的可能：**不是更大，而是更聪明。**
