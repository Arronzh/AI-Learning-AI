今日 arXiv 精选：匿名化预训练能让模型更诚实？端侧 Agent 框架 PalmClaw 亮相，评估指标也可以进化

📌 核心摘要：今天的 arXiv 新论文带来了三个引人注目的方向：Knowledgeless Language Models (KLLMs) 提出在预训练阶段匿名化实体名称，从根本上遏制模型的"死记硬背"倾向；PalmClaw 是一个真正"跑在手机上"的原生 Agent 框架，让 LLM Agent 直接调用设备能力而非模拟 GUI 点击，成功率和效率显著提升；Double Ratchet 则揭示了自进化 Agent 系统的"先有鸡还是先有蛋"问题——让评估指标与技能共同进化。

一、研究背景与动机

1.1 从"死记硬背"到"查证思考"

当前的大语言模型（LLM）在训练过程中会将大量事实知识编码到参数中。这导致了一个根本性的弊端：当模型面对过时的信息、不完整的上下文，或是与训练数据冲突的场景时，依然倾向于依赖参数记忆来回答，而不是"放下身段"去仔细阅读给定的参考资料。这种现象被称为 parametric recall，是幻觉（hallucination）的重要来源之一。

已有的缓解方案——如 RAG（检索增强生成）和工具调用——都是在推理阶段做干预。但来自特拉维夫大学、HPE 等机构的研究者们提出了一个更激进的问题：能不能在预训练阶段就动手脚，从根本上改变模型的知识依赖倾向？

1.2 端侧 Agent：终于不只在桌面上跑了

LLM Agent 已经从单一对话进化到能够调用工具、执行多步任务的阶段。但绝大多数 Agent 系统被部署在桌面或服务器上——这显然错过了最丰富的交互场景：移动端。

现有的手机端 Agent（如 AppAgent、MobileAgent）主要通过模拟 GUI 操作（点击、滑动、输入文本）来完成任务。这种方式有几大硬伤：动作序列冗长、接口耦合严重、无法直接调用设备原生能力（如传感器、通讯录）、执行边界模糊不清。换句话说，它们只是在模仿人类使用手机，而不是真正地"接管"手机。

1.3 没有评估指标，Agent 如何自我进化？

自进化 Agent 系统（self-evolving agent systems）的核心理念是让 Agent 自主创建、修订、淘汰自己的技能。但这个循环隐藏了一个致命的前提假设：我们已经有了可靠的评估指标。

然而在实际场景中，这面"照妖镜"往往并不存在。代码生成的自动测试可能覆盖不全，Text-to-SQL 的地面真值可能稀疏，报告生成更是缺乏客观评分标准。那么，当没有评估指标时，Agent 还能自我进化吗？

二、核心方法

2.1 KLLMs：匿名化预训练，让模型"忘记"知识

KLLMs（Knowledge-Less Language Models）的核心思路出奇地简单但深刻：在预训练语料中将命名实体（named entities）进行匿名化处理。

具体来说，训练语料中的人名、地名、机构名等被替换为占位符。技术细节上，研究者使用了实体识别（NER）和指代消解（coreference resolution）来保证匿名化的完整性。这样一来，模型在预训练阶段就几乎无法获取"谁是谁"的事实关联信号。

这一干预策略的效果是双重的：

  • 削弱了封闭式事实回召——模型不再知道"爱因斯坦提出相对论"这种具体实体关联；
  • 在上下文信息充足的场景中，表现反而更好——因为没有捷径可走，模型不得不认真阅读给出的证据。

2.2 PalmClaw：真正的原生移动端 Agent

PalmClaw 的名字取自"掌中之爪"，寓意是让 Agent 像一只灵活的爪子在设备上操作。与现有方案最大的不同在于：它不是在手机屏幕的 GUI 层面做事，而是直接在设备操作系统层面暴露原生能力接口（device tools）。

架构上，PalmClaw 将手机的能力（如发送短信、读取联系人、拍照、传感器数据）封装为带有显式参数和结构化返回结果的工具。Agent 的核心循环（session 管理、记忆、技能、工具调用）全部运行在设备本地。

关键创新点：

  • Device Tools：将手机原生能力抽象为明确的 API，每个工具有清晰的执行边界
  • 可定义执行边界：每个工具操作的 scope 和权限可以被显式控制
  • 本地闭环：Agent 决策和执行都发生在设备端，无需云端中转
  • 开源可用：代码已发布在 GitHub

2.3 Double Ratchet：当评估指标本身也需要进化

"谁来评判评判者？"——Double Ratchet 方法的核心是一个优雅的协同进化架构：

Metric Evolution（评估指标进化）：方法从一组小型的 drawback detectors（缺陷检测器）开始，通过进化算法搜索这些检测器的组合方式构建出一个复合评估指标。训练目标是与一个仅含 10 条样本的锚定参考集对齐，并通过无标签输出上的共识进行正则化，最后用一条从未见过的锚定样本进行审计。

Double Ratchet（双重棘轮）：将评估指标的进化与 Agent 技能的进化同步进行。技能循环包括技能的创建、修订和退役，而指标循环则持续评估和改进评估标准——两者形成一个相互约束、相互促进的闭环。

安全机制：锚定约束（anchor discipline）加上外部审计构成了安全防线。实验表明，移除锚定防护会导致评估指标退化成一个空洞的检测器。

四、技术启示与发展方向

4.1 预训练策略从"学知识"到"学能力"

KLLMs 这项研究表明了一个重要的范式转向：预训练的核心目标可能不应是"记住更多知识"，而是"培养更可靠的推理能力和证据使用习惯"。

这对 RAG 系统的设计有深刻启发——当前 RAG 往往高度依赖一个强大的基础模型，但如果基础模型本身就倾向于忽略上下文而依赖参数记忆，那么 RAG 的效果就会大打折扣。KLLM 提供了一个"天生更听话"的基础模型候选。未来的方向可能是在预训练阶段就做"知识遗忘"的设计，让模型更适应检索增强场景。

4.2 移动端 Agent 从 GUI 模拟到原生能力调用

PalmClaw 代表了一种架构转向：移动端 Agent 不应该模仿人类的操作方式（点击屏幕），而应该直接利用操作系统层面的原生接口。这类似于电脑端的 Agent 通过 API 而非鼠标点击来完成任务。

这一思路的延伸值得期待：随着 Android 和 iOS 系统对 AI Agent 的支持逐步原生化（如 Apple Intelligence 的 App Intents），PalmClaw 的 device tools 设计理念可能会成为端侧 Agent 的事实标准。

4.3 自进化系统必须面对"谁来验证"的问题

Double Ratchet 的核心贡献在于直面了自进化系统的"归因困境"：当系统自我改进时，如何知道改进是真的变好了，还是只是骗过了一个有缺陷的评估器？

这一工作在安全层面的启示尤为深刻：任何自进化系统都需要一个"外部锚定"——对于严肃的企业级或安全关键应用，不能仅依靠系统内部的指标来自我验证。锚定约束 + 外部审计的双重防护机制应该成为自进化 Agent 的默认架构。

五、总结

今天的三个工作虽然分属不同子领域，却共享一个共同的主题：让 AI 更可靠——通过更聪明的设计，而不是更大的模型或更多的数据。

  • KLLMs 选择在预训练阶段就纠正模型的"知识依赖症"——让模型学会查证而不是记忆
  • PalmClaw 将 Agent 从 GUI 模拟的泥潭中拉出来——让设备原生能力被直接操控，效率提升一个数量级
  • Double Ratchet 解决了自进化系统的元问题——当没有参照标准时，如何判断自己变好了
🧭 前瞻观察：这三个工作各有精彩之处，但放在一起看，它们共同指向一个方向——从"让 AI 变得更强大"到"让 AI 变得更可靠"。2026 年的 AI 研究正在经历一次深刻的价值观转向，可靠性正在取代规模成为新的北极星。
