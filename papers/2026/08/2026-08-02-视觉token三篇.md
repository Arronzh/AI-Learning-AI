# 视觉 token 太多，正在成为新瓶颈：一个检索 token、一群"潜在物体"、一枚"最后查询"——三篇新论文给出三种解法

📌 **核心摘要**：长视觉上下文（长图集、长视频、端云多模态推理）正在成为多模态大模型的新瓶颈——性能随干扰项增多而退化，全量 token 处理又超出显存与延迟预算。今天精选的三篇 arXiv 新论文，从三个不同视角给出了"少即是多"的解法：ReToken（UIUC × Microsoft Research × Google DeepMind）用**一个可学习 token** 在 value 空间做显式视觉检索，在 Visual Haystacks 上把 Qwen3VL-8B 提升 13.4 分；ObjectStream 把流式视频记忆组织成**跨帧的"潜在物体"锚点**，训练-free 即插即用，OVO-Bench 实时感知 +10.0 分且峰值显存与首 token 延迟减半；LAST 则面向端云协同推理，用边缘小模型**最后一个查询 token 的注意力**做传输前剪枝，仅保留 12.5% 的视觉 token 就能保住 95.4% 的精度。三篇论文殊途同归：视觉证据的"取舍"正在从压缩问题变成检索问题、组织问题和架构问题。

## 一、研究背景与动机

过去两年，多模态大模型（VLM）的上下文窗口飞速扩张，数小时视频、上百张图片"塞进"输入早已不是新闻。但**"装得下"不等于"用得好"**，三个现实问题正在浮现：

**第一，性能随干扰而退化。** 当只有一小部分图片或帧与问题相关时，VLM 的表现会随干扰项（distractor）增多而明显下滑。ReToken 团队指出，处理长视觉输入本质上是一个**检索问题**——要从海量视觉 token 中挑出与查询相关的那一小撮。

**第二，计算上"全量处理"不可行。** 一小时视频在 0.5 FPS 采样下仍有上百帧、数万 token，全量前向传播在单卡 H100 上直接 OOM。ObjectStream 面对的是更苛刻的**流式场景**：视频边来边看、问题随时可问，模型必须在不知道未来问题的情况下决定"留什么、丢什么"。

**第三，部署架构变了，剪枝问题也变了。** LAST 观察到，端云协同视觉智能正从"任务专用特征管道"走向"token 接口"——边缘设备把视觉编码成 token 传给云端通用 MLLM。此时剪枝发生在**传输之前**：边缘端必须在云端模型看到完整序列之前，就决定哪些视觉证据值得上传。这与传统"云端推理时剪枝"是本质不同的问题。

而一个共同的诊断结论让三篇论文显得尤为同频：**VLM 原生的注意力信号，并不可靠**。ReToken 的测量显示，基于 query-key 注意力的检索器在长视频 QA 上平均 recall@1 仅 5.1%；LAST 的消融同样证明"第一个查询 token"的注意力远不如"最后一个"。

## 二、核心方法

### 2.1 ReToken：一个 token 的显式检索目标

ReToken 的出发点是一个反直觉的发现：**在 VLM 里做视觉检索，value 空间比 query-key 空间可靠得多**。在两图受控实验中，用精确目标短语对"平均 value 投影"打分，recall@1 从 65.7 提升到 78.0（Qwen3VL）；而 query-key 打分只有 65.7。原因在于：value 承载的是真正通过注意力传播的内容，而 query-key 内积只决定内容如何被聚合——VLM 是为"下一 token 预测"训练的，从没学过"从干扰中检索"。

基于此，ReToken 只添加**两个参数**：一个可学习 embedding（追加在问题末尾，作为显式检索目标）+ 一个最终层投影矩阵。打分方式：用投影后的 token 与每帧平均 value 向量做余弦相似度，用类平衡的二元交叉熵损失监督（VLM 默认全程冻结）。推理采用两遍式：视频先一次性分块编码存入持久 KV 缓存（约 14.7 秒，可复用）；第一遍让检索 token 在最终层选出 top-K 相关帧，第二遍只基于选中帧生成答案——每问题仅多花约 0.4 秒。

### 2.2 ObjectStream：把记忆组织成"潜在物体"

ObjectStream 的洞见更偏认知：现有流式记忆按 token 重要性、时序冗余或片段相关性来管理上下文，却**很少围绕"持续存在、随时间演化的物体"来组织证据**——而这恰恰是回答"物体身份、交互、状态变化"类问题所必需的。

它是一个训练-free、即插即用的框架，四步构造"潜在物体锚点记忆"：
- **S1 显著性估计**：用帧内每个 token 与整帧上下文向量的余弦相异度打分，按分位数阈值选出活跃候选（无需任何检测器）；
- **S2 空间聚类**：在 patch 网格上用 4-连通分量把零散的显著 token 聚成"物体候选"；
- **S3 跨帧关联**：候选与已有物体轨迹做余弦匹配（EMA 更新特征），物体集有界——超出预算时按"最近出现 × 显著性 × 时序一致性"字典序淘汰；
- **S4 物体级证据保留**：在每个物体自己的历史 token 池内按显著性保留 top-K，避免全局 top-K 被少数高亮区域垄断。

在此基础上，ObjectStream 再补两个模块：**物体条件时序残差**（用物体自适应的阈值检测"突然变化"事件，在事件邻域窗口保留原始 token）和**近期视觉接地窗口**（保留最近数帧原始 token）。三者分别覆盖"持久物体历史、瞬态物体变化、近期视觉上下文"三类证据，底层 Video-LLM 完全不动。

### 2.3 LAST：边缘端"最后一个查询 token"做传输前剪枝

LAST 的灵感来自因果注意力的一个简单事实：**在 causal mask 下，序列中最后一个查询 token 能 attend 到全部视觉前缀和全部前置查询上下文**——所以它一个位置的注意力分布，就是现成的"查询条件化相关性信号"。

具体做法：边缘侧部署一个紧凑 VLM（InternViT-300M 编码器 + Qwen2-0.5B 代理 LLM，均来自 InternVL2-1B 权重），做**一次无解码的 prefill 前向**，跨层跨头聚合最后查询 token 对视觉 token 的注意力作为重要性分数。然后采用**重要性加权的 k-center 贪心选择**——目标函数是"查询相关性 × 覆盖增益"的乘积，既保留与问题相关的 token，又避免预算被相邻或语义相似的冗余区域耗尽。选中的 token 直接经共享编码器接口传给云端 InternLM2.5-7B 生成答案。全程无需云模型内部状态、无需自回归生成、无需多查询位置聚合，所有参数冻结。

## 三、实验结果

| 论文 | 核心结果 |
| --- | --- |
| **ReToken** | Visual Haystacks：Qwen3VL-8B **+13.4 分**、InternVL3.5 **+12.4 分**（>20% 相对提升）；仅用多图 QA 训练，**零样本迁移**到长视频：LVBench（平均 68 分钟/视频）**+8.0 分**；C=50 干扰下 K=1 检索 recall 64.7% vs ReKV 仅 1.8%；单张 H100 完成训练与长视频推理 |
| **ObjectStream** | OVO-Bench 实时视觉感知 Qwen2.5-VL-7B 63.3→**73.3（+10.0）**，Backward Tracing 44.6→49.5；StreamingBench 73.9→76.8；**峰值显存与 TTFT 均降约 50%**（19.89GB / 6.7s）；离线长视频丢弃 82.5% 视觉 token 仍超全 token 基线（VideoMME-Long 51.3→54.0，EgoSchema 58.5→60.8） |
| **LAST** | 11 个多模态基准：保留 62.5%/37.5%/12.5% token 时保持全 token 精度的 **99.3%/99.0%/95.4%**；12.5% 预算下比最强基线 SGP 高 2.4 相对点、ChartQA +8.6；重要性打分仅 **2.51ms**（比 FastV 少 36.8%）；跨模型验证（LLaVA-1.5 7B→13B）128/576 token 保持 99.2% |

几个值得玩味的细节：ReToken 的消融显示**冻结 VLM 反而比微调前几层更利于视频迁移**（微调带来图像域偏移）；ObjectStream 对比 SAM+DINOv2 说明**分割级精细 mask 并不等于可复用的时序记忆状态**；LAST 的消融则证明"最后查询 token"优于"首 token"、"全部均值"乃至"均值+生成答案"——**一个位置的信息量就够了**。

## 四、技术启示与发展方向

**1. 注意力分数 ≠ 相关性，价值空间是富矿。** ReToken 用数据说话：VLM 的注意力权重只是"聚合机制"，而 value 特征才携带真正传播的内容。这为多模态检索、长视频定位、甚至 RAG 的视觉化提供了新的特征空间选择依据——"检索该用哪一层、哪个空间"值得成为标准实验项。

**2. 压缩率之外，"组织方式"同样决定上限。** ObjectStream 在同等 token 预算下显著优于无结构的 patch top-K 选择，说明**记忆的组织单元（物体、事件、时间窗）比单纯的取舍阈值更关键**。物体中心记忆与事件级结构（如 OASIS）正在成为流式视频的两条主线。

**3. 部署架构决定剪枝范式。** LAST 把剪枝从"云端推理时"前置到"传输前"，让**小模型引导大模型**成为端云协同的标准范式。随着边缘设备逐步具备小型 VLM 能力，"边缘预筛 + 云端精答"的 token 接口可能会取代传统的特征管道。

**4. 三篇论文的共同信号：查询条件化、训练-free、固定预算。** 无论是检索、记忆还是剪枝，"和问题无关的丢弃"正在被淘汰；能不动主模型就不动主模型（ReToken 只训两个参数、ObjectStream 与 LAST 完全冻结）；token 预算被当作硬约束来优化。这暗示多模态推理的效率优化正在走向"系统化"而非"模型化"。

**未来方向**：跨模态检索与物体记忆的结合（用 ReToken 式检索去驱动 ObjectStream 式记忆）；端侧代理模型的蒸馏与适配（LAST 已证明 0.5B 模型足够提供可靠引导）；以及把这三条路径统一进长上下文推理引擎——先组织、再检索、后生成。

## 五、总结

三篇论文，三个场景，一个共识：**长视觉上下文的瓶颈已经从"容量"转移到"取舍"**。ReToken 告诉我们取舍可以交给一个经过显式检索监督的可学习 token；ObjectStream 告诉我们取舍应该围绕"物体"这一认知单元来组织；LAST 则告诉我们取舍发生的位置（边缘还是云端）会决定整个方案的设计。当"全量处理"在算力上不可行、"全量输入"在性能上有害时，如何优雅地丢弃视觉证据，正在成为多模态推理的下一个主战场——而这三篇工作，恰好勾勒出了战场上的三条进攻路线。
