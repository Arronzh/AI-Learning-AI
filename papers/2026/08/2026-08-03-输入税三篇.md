# 大模型推理的"输入税"该降了：分词吃掉 64% 延迟、视觉 token 浪费七成、检索还在"一刀切"——三篇 arXiv 新论文给出按需解法

📌 **核心摘要**：模型推理的成本，正在从"计算"悄悄转移到"输入"。今天精选的三篇 arXiv 新论文，恰好覆盖了输入链路上的三个环节：**TokTier** 发现 KV 缓存命中率高达 94.1% 时，分词仍可占用首 token 延迟（TTFT）的 **64%**——编码智能体每轮工具调用后都要把整段长对话重新分词，它用"状态化分词服务"把增量修复做到 0.5-1.1 毫秒，比 HuggingFace 分词快最多 **437 倍**；**CodeShrink** 面向"代码截图喂给多模态模型"的场景，指出换行缩进产生的空白区域与指令无关的代码区域是两笔"视觉 token 税"，用空白消除渲染 + RL 训练的压缩代理 + 指令感知剪枝三重手段，最多省下 **71.2%** 的视觉 token 且精度不降反升；**QASP** 则瞄准 RAG 底座向量检索的"固定参数方差"问题——平均召回率掩盖了查询间的巨大差异，它用一次回归预测整条召回曲线，达到 **99% 召回率时少访问 80% 的数据**。三篇论文殊途同归：**"一刀切"的固定策略正在被"按需自适应"取代，输入侧的每一分钱都值得被重新计算。**

## 一、研究背景与动机

过去两年，业界优化推理成本的注意力几乎全部集中在**模型本身**：量化、剪枝、投机解码、KV 缓存……但一个被忽视的事实是——**数据"进入"模型的路径上，还躺着三笔隐性开销**。

**第一笔：分词（Tokenization）——缓存命中了，前端却没命中。** LLM 服务系统普遍缓存 prompt 的 KV 状态，但绝大多数前端每次调用仍会对完整请求文本重新分词。这在编码智能体场景尤为致命：智能体每执行完一个工具调用，就要把累积的长对话记录重新提交一次。TokTier 团队统计了来自两个智能体生态的 **153,951 次调用**：中位调用仅追加约 **1.4K 字符**，只有 1.0%-3.6% 的调用会重建百万字符级的会话。更反直觉的是，在舰队级 prompt 缓存命中率高达 **94.1%** 的情况下，分词居然能占到首 token 延迟的 **64%**——KV 缓存把"计算"省了，分词却把"时间"重新花掉了。而复用之所以难，是因为哪怕只追加一小段文本，也可能改变前一段序列末尾的 token 边界，导致"从头重来"。

**第二笔：视觉 token——代码截图里的"空白税"和"无关税"。** 把源代码渲染成图片喂给多模态大模型（MLLM），是降低输入成本的一条热门路线。但单纯调整分辨率只解决了"清晰度 vs token 数"的取舍，却漏掉了两个更隐蔽的低效源：其一，换行、缩进产生的**空白区域**白白占用 token；其二，与当前指令无关的**代码区域**（比如你问"这个函数是干什么的"，截图里却躺着 200 行 import 和配置）同样被全量编码。更麻烦的是，最优压缩配置随输入、任务、模型而变，任何**固定压缩比**策略都注定顾此失彼。

**第三笔：向量检索——平均召回率掩盖的"方差黑洞"。** RAG 是当前大模型应用的事实标准底座，而向量检索（ANN）的搜索参数（如 probe 数量、候选集大小）通常全局固定。问题在于：**不同查询的"难度"天差地别**——简单查询轻轻松松就能召回，困难查询则需要深挖很久。固定参数要么让简单查询浪费算力，要么让困难查询召回不足；而业界惯用的"平均召回率"指标，恰恰把这种逐查询方差掩盖掉了。QASP 的作者直言：这种方差才是真实线上体验的痛点。

## 二、核心方法

### 2.1 TokTier：把分词做成"有状态的服务"

TokTier 的核心契约只有一条：**输出的 token ID 必须与对完整请求文本做参考分词的结果完全一致**——不做任何近似，不改变模型看到的任何内容。在这个契约下，它分两条路径处理：

- **会话续写（有可复用前缀）**：只对追加点附近的一个**小窗口**重新分词，通过"稳定边界检查"（stable-boundary check）确认拼接安全后再 splice 进旧序列；检查失败则扩大窗口重试，最坏情况回退到全量分词。这一设计的关键洞察是：虽然追加文本理论上可能影响任意靠前的 token 边界，但在 GPT 系正则预分词规则下，**边界变化只会发生在追加点附近**，可以高效验证。
- **无前缀的调用**：把 GPT 家族的正则预分词拆解为"run-local"规则，直接在 **GPU 上执行精确的预分词 + BPE**，绕开 CPU 上的串行瓶颈。

此外，TokTier 部署了一个**采样影子验证器**（shadow verifier）持续复检线上流量，确保"状态化"永远不会悄悄退化成"有状态但错了"。

### 2.2 CodeShrink：三重手段压缩"代码截图"

CodeShrink 由三个组件构成，分别对应三笔不同的浪费：

- **空白消除渲染（Blank-Free Rendering）**：不再依赖空白符布局，而是用紧凑布局 + 显式结构标记（如行号、缩进符号）重排代码图像，**从源头消灭布局诱导的 token**——这是对"渲染方式"动刀，而非对"渲染结果"动刀。
- **自适应压缩配置（Adaptive Compression Configuration）**：用一个**强化学习训练的轻量代理**，为每个输入预测"token 效率 vs 可读性"的最优平衡点。这一步承认了"最优配置因输入、任务、模型而异"的现实，把压缩从固定比策略升级为**逐输入决策**。
- **主导 token 选择（Dominant Token Selection）**：推理阶段**联合分析指令与代码图像**，剪掉与当前任务无关的视觉 token——相当于给"代码截图"做了一次查询条件化的注意力聚焦。

三者叠加的效果是：压缩不再是"无脑缩放"，而是"渲染层去布局税、决策层按需配置、推理层按指令剪枝"的三级过滤。

### 2.3 QASP：一次回归预测"整条召回曲线"

QASP 的出发点是一个优雅的抽象：与其为每个召回率目标训练一个预测器、或者在搜索过程中反复调用模型，不如**在搜索前用一次监督回归，预测该查询完整的"召回率-代价"曲线**——有了这条曲线，任何召回率目标都能直接推导出对应的搜索策略（如 probe 数量）。

为了保证泛化性，QASP 使用**尺度不变特征**（scale-invariant features）做预搜索推理，因此可以跨召回率目标、跨索引配置、跨数据集使用，无需重新训练。更妙的是，细粒度的进度预测还催生了一个**轻量反应式补丁**：搜索过程中把"预测进度"与"实际观察进度"对比，一旦偏离就动态调整搜索深度——而且不需要额外推理开销。理论上，作者证明了 QASP 只需要一个**与数据集规模和维度无关的有限训练样本**，其损失与任何固定策略的不可约下界只差一个可消失的余项，且相对固定 probe 策略的数据访问节省随**内在维度呈指数增长**。

## 三、实验结果

| 论文 | 核心结果 |
| --- | --- |
| **TokTier** | 17 种分词器族、1.5×10¹⁰ 次切分检查、12.4 TB 真实文本、93,000+ 重放智能体步骤的差分测试中**零分歧**；增量修复 100K-3M 字符仅 **0.5-1.1 ms**，比 HF 分词快最多 **437 倍**，1M 字符处比最强缓存基线 Gigatoken（完全预热）快 2.1 倍；GPU 全量分词 1M 字符请求仅 **0.87 ms**（比 HF 快 491 倍、比最快已发表 CPU 方法快 23.4 倍）；接入 vLLM 后中位 TTFT 降 **16-34%**、P99 降 **23%**；50ms P99 目标下，4 修复核 + 1 GPU 支撑 **1,821 req/s**，而 16 核无状态前端在 40 req/s 就饱和 |
| **CodeShrink** | 代码问答、克隆检测、代码补全三类任务上，视觉 token 最多减少 **71.2%**，精度**持平或超过**未压缩的纯文本输入；全面优于文本型与视觉型压缩基线 |
| **QASP** | 召回率方差与目标偏差显著更低、查询满意率更高；无需重训练即可扩展到大数据和层级索引；达到 **99% 召回率时数据访问减少 80%** |

几个值得玩味的细节：TokTier 的 437 倍加速不是靠"偷工减料"，而是靠**零分歧的差分验证**撑腰——加速与正确性可以兼得；CodeShrink 的 RL 代理证明了"压缩策略本身值得被学习"；QASP 的理论保证（训练样本与数据规模无关、节省随维度指数增长）则把经验结果钉在了数学地基上。

## 四、技术启示与发展方向

**1. 系统栈的"最后一公里"正在成为新的性能富矿。** TokTier 揭示了一个残酷的事实：当 KV 缓存把推理计算压到极致后，**前端的分词反而成了最大的延迟单项**。缓存优化是"存量红利"，而分词这类"被遗忘的环节"才是下一块洼地——类似的"最后一公里"（序列化、调度、前后处理）大概率还有不少。

**2. 输入表征的"布局税"值得被认真对待。** CodeShrink 提醒我们：多模态输入的 token 成本不只是"内容"决定的，**呈现方式（layout）同样决定 token 数**。换行缩进都能产生可观的空白 token——这意味着输入侧的优化不只是"压缩算法"问题，还是"渲染设计"问题，后者甚至更便宜、更有效。

**3. "平均指标"正在系统性误导系统设计。** QASP 的批评具有普适性：平均召回率掩盖逐查询方差，平均延迟掩盖长尾。**按需自适应（per-query / per-input 决策）正在取代全局固定策略**，这条规律在分词窗口、压缩配置、检索深度三个完全不同的环节同时出现，绝非偶然。

**4. 三篇论文的共同信号：精确性保证 + 轻量代理 + 自适应。** TokTier 以"零分歧"为生命线，CodeShrink 用 RL 训练轻量代理做逐输入决策，QASP 用一次回归换整条策略曲线——**"保证不破坏结果"的自适应优化**正在成为输入侧工程的黄金标准。

**未来方向**：把这三层优化叠进同一条链路——QASP 先按查询难度决定检索深度，TokTier 保证长对话追加的毫秒级重分词，CodeShrink 在视觉输入进入模型前完成指令感知剪枝。当"检索、分词、编码"都变成按需自适应，"输入税"才有可能被真正系统性减免。

## 五、总结

三篇论文，三个环节，一个共识：**当模型能力与推理计算都被优化到极致，输入侧的低效就成了最后的"隐形税"**。

<blockquote>
TokTier 告诉我们：缓存命中了，分词还在全量重来——状态化可以比"从头再来"快两个数量级；CodeShrink 告诉我们：视觉输入的浪费藏在布局与无关区域里——压缩应该是逐输入的决策而非固定比例；QASP 告诉我们：平均指标掩盖方差——一次回归预测整条曲线，检索就能按查询难度量入为出。
</blockquote>

这或许是大模型基础设施走向成熟的一个标志：**优化对象从"模型怎么算"延伸到"数据怎么进"**。当输入侧的每一毫秒、每一个 token、每一次数据访问都被重新计算价值，AI 服务的成本结构才真正完成了从"蛮力时代"到"精算时代"的转身。
