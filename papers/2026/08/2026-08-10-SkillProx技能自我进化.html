Agent 的技能也能"梯度下降"：SkillProx 前向闭环验证、后向按需瘦身，让技能库越用越强

📌 核心摘要：大模型 Agent 正在把经验"外置"成技能（skill）——一段可复用的文本制品，推理时加载进上下文，不需要动任何权重。但技能不是一次写好的：它会随着任务失败不断被打补丁。港科大团队发现，现有的技能进化方法有两个致命伤：补丁打上去从不验证效果，技能只涨不缩、越攒越乱。他们提出 SkillProx——一个受近端梯度下降（Proximal Gradient Descent）启发的"前向-后向"框架：前向阶段在同一个任务批次上反复"执行→诊断→打补丁→回滚"，用真实执行结果给每次修改把关；后向阶段把技能拆成可审计的知识单元，用"留一法"逐条估算贡献，对冗余、冲突、过拟合的内容做合并、降级或删除。在 SpreadsheetBench、WikiTableQuestions、HiTab 三个基准、三款 Qwen 模型上，SkillProx 平均比最强的基于梯度的基线高出 3.0 个百分点；在 Qwen3.6-27B 上把人工编写的基线技能从 36.7 分拉到 54.5 分（+17.8 个百分点），且方差全场最低。技能，第一次被当作一个"可优化的对象"来对待。

一、研究背景与动机

从"技能合成"到"技能进化"

Agent 要复用过往经验，最流行的做法不是微调权重，而是把"怎么做某类任务"写成技能——一段结构化的指令、脚本和参考资源，推理时加载进上下文。这就是 OpenClaw、Claude Skills 等框架背后的同一个思路：轻量、可编辑、不占权重。

但 SkillsBench 等基准给出过一个扎心的结论：一次性合成的技能，在不同任务上增益极不均匀，有时甚至是负的。一篇技能不可能预见到它未来遇到的所有情况。于是研究重心从"技能合成"转向"技能进化"——代表方法如 SkillGrad，把任务失败当作"文本梯度"，失败一次就打一个补丁，把静态技能调成动态的过程性记忆。

两个被忽视的漏洞

SkillProx 的作者（香港科技大学团队，含 Yike Guo、Sirui Han 等）指出了现有技能进化方法的两个关键缺陷：

  • **前向更新不被验证**。LLM 生成的诊断通常被直接当作有效更新方向，补丁打上就完事，既不重跑验证效果，也不把结果反馈给后续诊断。一个"看起来合理"的补丁，可能实际把任务表现拉低了。
  • **技能只增不减**。迭代打补丁让技能无限膨胀，重复指令、冲突启发式、把个案解法误当成通用规则的内容越积越多——它们不仅增加文本复杂度，还会干扰真正有用的知识。

作者做了一个开放性实验验证这两个猜想：同样是 Qwen3.6-27B 跑十轮，开环进化的平均准确率 50.30±2.50，而加了反馈控制的变体达到 51.40±1.51；另一个留一法实验里，删掉"负效用"内容后，准确率从 46% 升到 54%，技能体积还小了 3.12%。结论很直接：补丁好不好，得看执行结果，不能只看诊断文本；技能健康要靠选择性整合，而不是无限生长。

二、核心方法

把技能进化写成"复合优化"

SkillProx 的出发点是近端梯度下降（PGD）——一种经典优化方法：先对可微目标做一次前向梯度步，再对不可微的正则项做一次后向近端步。技能文本是离散的、不可微的，不能直接套数值梯度，但作者保留了 PGD 的分工哲学：

min J_λ(X) = L_T(X) + λ·G(X)

其中 L_T 是任务损失，G(X) 是技能文本复杂度（字符数）。前向负责降任务损失，后向负责控结构复杂度——正好对应技能进化的两个诉求。

前向阶段：闭环诊断进化

每一轮迭代，当前技能在训练批次上执行，诊断器根据失败轨迹、成功轨迹的对照、近期历史以及上一次的拒绝原因，提出修改方向；打补丁器产出候选技能后，在同一个批次上重新执行，只有同时满足硬准确率不降、单元格准确率不降的"前向门"才被接受。第一个带来严格硬准确率提升的候选会提前终止搜索；最多试三次，都不行就保持原样。被拒绝的修改方向和实测效果会进入"接受/拒绝记忆"，喂给下一轮诊断。

这套机制的关键词是闭环：诊断过程本身随着先前更新的实际后果进化，而不是只看语义上"像不像对的"。

后向阶段：近端收缩（Prox）

前向跑完，得到中间技能 X_f。后向阶段把它解析成可审计的知识单元（L2 章节 + L3 参考文件组），用冻结的留一法效用审计给每个单元打分：

u_i = H_V(X_f) − H_V(去掉 q_i 后的 X_f)

效用为负，说明"删掉它反而更好"。候选单元按效用排序，收缩器对每个候选提出合并、降级或删除三种处理，但要过三道闸：结构合法、复杂度严格下降、验证集上硬准确率不降（δh=0，单元格准确率最多容忍 0.02 的下降，累计压缩超过 10% 的软上限后停止尝试）。所有编辑先在副本上试，通过了才替换当前技能。

一句话概括前后分工：前向决定"新知识该不该进来"，后向决定"老知识该不该留下"。

三、实验结果

设置

  • **基准**：SpreadsheetBench Verified（同分布 IID）；WikiTableQuestions、HiTab（跨分布 OOD，考察泛化）
  • **底座模型**：Qwen3.5-4B、Qwen3.5-27B、Qwen3.6-27B
  • **基线**：无技能、人工技能、LLM 生成技能（EvoSkill、Trace2Skill）、自我进化技能（SkillGrad、SkillOpt）

主结果：全面优于生成式与进化式基线

  • 把人工基线技能变成稳定正收益：Qwen3.5-27B 上 **38.3→51.3（+13.0pp）**，Qwen3.6-27B 上 **36.7→54.5（+17.8pp）**，小模型 4B 上也保持正增益（20.3→21.0）
  • IID 三个底座全部最佳（21.0 / 51.3 / 54.5）；在 4B 上比 EvoSkill 高 14.3pp、比 Trace2Skill 高 11.0pp，并压过最强自我进化基线 SkillGrad（19.3→21.0）
  • **方差全场最低**（±0.5 vs SkillOpt 的 ±7.6）——增益稳定，不是靠运气初始化
  • OOD 泛化：WikiTQ 上 4B 与 27B 均最佳（78.5 / 86.8），HiTab 上 4B 与 Qwen3.6-27B 最佳（69.2 / 80.0）。反观 SkillOpt 严重过拟合 IID，在 OOD 上崩塌（4B：WikiTQ 26.0、HiTab 16.0）

消融：两个阶段互补

去掉闭环诊断：54.5→53.0（−1.5pp）；再去掉 Prox：→52.0（−2.5pp）。去掉 Prox 的损失更大——说明纯前向编辑会积累冗余内容，后向收缩是必需品；而闭环诊断也为后向提供了值得收缩的好技能。

阈值扫描：压缩-性能的帕累托前沿

不重训、只离线跑 Prox：τ=−0.001 时准确率最高 52.3%（压缩 25.7%）；τ=0.005 时压缩到 41.5% 仍保持 52.0%；τ=0.050 时删掉 74.9% 内容还能守住 51.0%。适度瘦身不但不掉点，反而提升——因为删掉了重复规则和上下文干扰。

四、技术启示与发展方向

1. "技能即参数"的范式正在成形。 SkillGrad 把技能当结构化参数、用文本梯度更新；SkillProx 更进一步，用"执行验证 + 效用审计"把技能当作可优化的对象。当技能库越来越大（企业 Agent 动辄几百个技能），"技能治理"会从选修课变成必修课。

2. 大模型更会"断舍离"。 一个有趣的发现：4B 模型练出的最终技能比 27B 长 45%，主技能文件长度却收敛到几乎相同（约 1.5 万字符），差异全在参考文件——小模型需要约两倍的补充材料。且 27B 内部，技能越长 IID 准确率反而越低。更强的模型天然产出更精炼的技能，而闭环验证+近端收缩给了小模型一个外挂的"拒绝机制"。

3. 验证成本是现实约束。 同批次重执行、留一法审计都是真金白银的推理开销。作者在论文中给出了评估复杂度分析，但"用多少验证换多少技能质量"仍是一个待解的工程权衡——这也直接关系到该方法能否在真实 Agent 平台上规模化。

4. 开放问题。 效用审计目前是"冻结"的（一次性打分），能否让审计本身也进化？技能单元之间的依赖关系（比如参考文件被多处引用）如何建模？这些问题都留给后续工作。

五、总结

SkillProx 用近端梯度下降的框架，把 Agent 技能进化拆成了"前向验证 + 后向收缩"两个互补阶段，在三个基准、三款模型上稳定跑赢生成式与进化式基线，平均比最强梯度基线高 3.0 个百分点。它最大的贡献或许不在分数，而在于一个观念转变：技能不是写出来的，是"训练"出来的——只是这一次，优化的不是权重，而是文本本身。
