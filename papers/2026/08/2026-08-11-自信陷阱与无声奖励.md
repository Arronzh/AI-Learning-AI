# "自信的陷阱"与"无声的奖励"：Consilience 用信心轨迹重做无验证器测试时扩展，SKALD 把技能蒸馏进权重

📌 **核心摘要**：推理模型越用越强，靠的是两条路——训练时用强化学习（RLVR）喂奖励，推理时用测试时扩展（TTS）多采样再挑选。但今天精选的两篇 arXiv 新论文，分别戳破了这两条路上最"理所当然"的假设：Consilience（arXiv:2608.09898）发现，**置信度最大化在难题上会灾难性失效**——错误答案的平均置信度反而更高，模型会系统性地选出"自信地犯错"的轨迹；正确推理的置信度不是一条平线，而是"先低后高"的探索-收敛曲线，据此提出的 consilience 指标在 LiveCodeBench 上把 GPT-OSS-120B 从 65.7% 提到 69.7%。SKALD（arXiv:2608.09826）则发现，RLVR 的组内相对奖励在"全对或全错"的 rollout 组里**完全沉默**——这类组占了训练数据的 63%–68%；解法是把"技能卡"作为特权信号只给老师分支看，通过退火倾斜交叉熵把技能效果蒸馏进共享权重，在 4B 模型上比同等算力的 GRPO 高 11.19 分。一个信号会骗人，一个信号会沉默——两篇论文殊途同归：**当最直接的信号失效时，真正的智能藏在"轨迹"和"权重"里。**

## 一、研究背景与动机

**先看测试时扩展这一侧。** 并行 TTS 的思路很简单：一次采样 n 条推理轨迹，选一条最好的。可"选"这个动作依赖验证器——代码有编译器跑测试用例，机器人有学出来的价值函数。但现实世界里大量场景（开放式代码生成、Agent 的中间步骤、自由文本）根本没有外部验证器，于是社区转向"无验证器测试时扩展"（VF-TTS）：用模型自己的 token 级 log 概率当置信度，挑置信度最高的一条。它零训练、近零开销、还能用在只暴露 top-K log 概率的闭源 API 上——看起来是通用解。

**但 Consilience 的作者发现了一个危险的盲区。** 在 LiveCodeBench-V6 上，把 GPT-OSS-120B 的完成轨迹按平均置信度画直方图：全局看，正确答案置信度确实更高——这正是所有置信度方法的立论基础。可一旦只看难题（正确率 <20% 的子集），分布**反转**了：错误答案的平均置信度（9.03）反而高于正确答案（8.79），而且在最高置信度区间拖出一条长长的尾巴。用 argmax 挑置信度最高的轨迹，等于**专门去捡"自信地幻觉"的那一条**。论文里甚至给出更扎心的数据：在 HMMT 上对 OSS-20B 用 Self-Certainty 挑选，准确率从 Pass@1 的 76.5% 掉到 68.0%——比随机挑还差。

**再看训练这一侧。** RLVR 用"可验证奖励"做组内相对策略优化（GRPO）：一个 rollout 组里，谁的答案对、谁获得正优势。但 SKALD 的作者指出一个代数上的盲点：**当一组 rollout 全对或全错时，组内归一化优势恒为零，这一组对整个训练贡献的梯度信号就是零**。在他们的实验里，这类"零方差组"占了全部训练组的 63.0%–68.0%——包括大量难题上"全军覆没"的组。奖励函数对这些题完全是聋子。

## 二、核心方法

### 2.1 Consilience：惩罚"过早收敛"，奖励"最终确定"

Consilience 的核心洞察借用了科学哲学里的"一致性原则"（consilience）：**一个结论只有当多条独立路径汇聚到它时才是可靠的**。而置信度最大化恰恰反着来——它奖励从第一个 token 起就"一条道走到黑"的轨迹，压制那些"意识到存在多条可行路径"的轨迹。问题在于：自回归模型里，token 的置信度衡量的是"过去的推理有多严格地蕴含当前 token"。推理早期高置信度，说明一个很短的 prefix 就把概率空间坍缩成了一条路——模型没意识到题的难度，跳过了必要的探索，直接过拟合进一个局部解。

因此，真正扎实的推理应该呈现**时间不对称**：开头低置信度（概率质量在多条候选路径间分流，即探索），结尾高置信度（逻辑约束收紧，即收敛）。Consilience 把这个结构签名变成了一个可计算的指标：

- 取序列首尾两个窗口（W 个 token，跳过前 5% 的模板 token），分别算初始置信度 C_initial 和最终置信度 C_final；
- 得分 = C_final − α·C_initial，**主动惩罚高初始置信度，同时严格要求最终确定**；
- 关键工程细节：**推理阶段隔离**（-think 变体）。把序列按 `</think>`、`<|channel|>final` 等分隔符切开，只在推理段上算置信度，避免"总结腔"token 用虚高置信度稀释信号；
- 全程训练-free、只用 logits（K=5 个 top 概率即可，兼容闭源 API），Best-of-n 挑选零额外成本。

### 2.2 SKALD：技能只给老师看，效果写进权重

SKALD 的思路是把"特权信息"蒸馏进参数。它用同一个 Qwen3-Base checkpoint 实例化两个"上下文视图"：**学生分支只看题目**（与部署条件完全一致），**老师分支额外看一张技能卡**——{标题、原理、用法、常见错误} 的结构化卡片，明确过滤掉参考答案。技能卡由更大的 Qwen3-14B 离线从训练解中挖掘筛选（17,384 个候选 → 11,382 张卡 → 合并为 1,926 个可复用技能，93.1% 的训练题都有归属）。两个分支共享全部参数，老师只负责打分、不参与更新。

训练目标有两个关键设计：

- **退火倾斜交叉熵**。直接做老师交叉熵在"老师偏好但学生觉得极不可能"的 token 上会不稳定。SKALD 用 ℒ = −(1/τ)·log E_{v∼q}[p(v)^τ]：τ>0 时，有效目标变成 r_τ ∝ q·p^τ，自动压低"学生当前概率极低"的老师 token，平稳解是锐化后的 escort 分布 p* ∝ q^{1/(1−τ)}；随后 τ 从 0.8 线性退火到 0，退火结束后恢复标准老师交叉熵（等价于 forward-KL 的学生梯度）。这相当于先用"mode-seeking"稳住训练，再逐步放开到完整老师分布。
- **经验门控**。训练前用 K=8 次采样估计"老师分支是否真的比学生分支准"，只有估计为正的题（约 61.2%）才开启蒸馏——把"技能可能帮倒忙"的样本挡在门外。

推理时，模型只看到题目，技能卡和老师分支都不存在——**技能的效果被完全内化进了权重**。

## 三、实验结果

### Consilience：开放式代码生成是最大赢家

| 场景 | 基线 | Consilience | 提升 |
| --- | --- | --- | --- |
| LiveCodeBench（GPT-OSS-120B） | Pass@1 65.7% | Cns-think **69.7%** | +4.0 |
| LiveCodeBench（Qwen3-80B-Next） | Pass@1 55.3% | **60.4%** | +5.1 |
| HMMT（DS-R1-7B） | Pass@1 47.8% | Cns-2K-think **57.1%** | +9.3 |
| GPQA（Qwen3-80B-Next） | Pass@1 60.5% | Cns-full **65.2%** | +4.7 |
| SWE-bench（mini-SWE-agent + GPT-OSS-120B） | 23.0% | **26.9%** | +3.9 |
| SWE-bench（mini-SWE-agent + Qwen3-Coder-Next） | 65.3% | **67.3%** | +2.0 |

最值得注意的是 LiveCodeBench——这是投票类方法（Self-Consistency）完全不适用的自由格式生成场景，而 Consilience 恰恰在这里收益最大。消融显示：推理段隔离（-think）优于全序列（-full），且两档窗口（动态 20% / 绝对 2K token）都稳健。

### SKALD：奖励沉默处，蒸馏补位

在 MATH500 + AMC23 + AIME24/25 + Minerva 共 872 题的 avg@8 上，SKALD 相对 GRPO 的增益随规模单调上升：**0.6B +2.46、1.7B +4.85、4B +12.01**。几个关键对照：

- **等算力对照**：1.7B 下把 SKALD 的全部预算（含额外打分与门控开销）折算给 GRPO，GRPO 提到 46.31，SKALD 仍领先 **+4.06**；4B 下调优后的等算力 GRPO 为 52.19，SKALD 达 63.38，领先 **+11.19**。
- **机制验证**：只对零方差组做蒸馏，就恢复了全量增益的 **84.7%**（49.63 vs 45.52）；只对混合组蒸馏只贡献 +0.79——证明增益确实来自"奖励沉默"的地方。
- **"写进权重" vs "放进上下文"**：同样的"测试时不给技能"协议下，把技能卡放进 RL 上下文再在测试时撤掉，得 46.60；SKALD 的权重级迁移得 50.37，**高出 +3.77**——技能内化比临时脚手架更可靠。
- **防泄漏审计**：条件恢复实验显示，仅题目能恢复 2.4% 的答案，匹配技能卡也只有 5.1%（完整参考答案是 94.2%）；清洗掉题目里的具体数字、实体后分数几乎不变（50.24 vs 50.37）。直接答案泄漏不构成 +4.85 的解释。
- **稳定性**：无倾斜（τ=0）的训练在 1.7B 上 2/3 种子发散、4B 上 3/3 发散；倾斜退火版本全部收敛，梯度范数从 ~4.5 降到 ~0.3。

## 四、技术启示与发展方向

**1. "高置信度"是一个难度相关的信号。** 两篇论文合起来给出一条清晰的警示：模型内部信号（置信度、组内优势）只在"模型已经会做"的题上可靠。Consilience 用难度分层揭示了置信度分布的反转，这提醒所有基于 log 概率的挑选器——先判断"这题对你难不难"，再决定信不信它的自信。用"轨迹形状"替代"平均高度"，是比单纯换阈值更深的一步。

**2. 训练与推理正在共享同一套"信号稀缺"问题。** RLVR 的奖励在零方差组沉默，置信度在难题上撒谎——两者本质是同一件事：**终点信号（对错、置信）在难题上信息量趋近于零**。Consilience 转向过程信号（置信度的时间轨迹），SKALD 转向特权信号（技能卡提供的密集 token 级监督）。"从终点信号转向过程/特权信号"，可能是下一阶段推理能力提升的主轴。

**3. 技能叙事的两条路线正在合流。** 昨天的 SkillProx 把技能当作可进化的文本制品（技能在上下文里）；今天的 SKALD 给出互补答案——技能作为特权信号蒸馏进权重（技能不在上下文里）。一条线是"技能治理"，一条线是"技能内化"，两者都指向同一个判断：**技能正在成为与权重、提示词并列的第三类一等公民**。SKALD 的"老师分支有条件、测试时无痕迹"范式，也天然适合隐私敏感场景（特权信息不进部署模型）。

**4. 成本账要算清楚。** Consilience 几乎零成本（一次前向的 logits），SKALD 则要付出老师打分前向、门控采样和离线技能挖掘的算力——论文用等 FLOP 对照证明了净收益，但"门控何时刷新、技能卡如何随训练演化"仍是开放问题。另外 SKALD 目前只验证了数学推理，技能卡能否泛化到代码、Agent 任务，值得跟进。

## 五、总结

Consilience 告诉我们：**自信是会骗人的**——尤其在难题上，越是"一条道走到黑"的轨迹越危险，可靠的推理应该先探索、再收敛，而"先低后高"的信心轨迹正是可以免费提取的可靠信号。SKALD 告诉我们：**奖励是会沉默的**——当组内相对优势归零，技能卡作为特权信号可以补上密集监督，并把效果永久写进权重。一个在推理侧重建了"选择"，一个在训练侧重建了"信号"。两篇论文指向同一个未来：**当最明显的信号失效时，下一步的智能增量，藏在过程、结构与权重里，而不是藏在更多的采样和更大的奖励里。**
