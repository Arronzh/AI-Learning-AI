# 自改进 Agent 真的在变强吗？Salesforce 三项重测揭开"记忆增强"的脆弱真相

📌 核心摘要

"让 Agent 自己记住经验、越用越强"——这是过去一年最性感的 Agent 叙事之一：系统维护一个文本记忆库，每做完一个任务就把"经验"写进去，下次遇到相似任务时调用，形成自我改进的闭环。今天精读的这篇论文（arXiv:2608.18066，Salesforce AI Research，8 月 18 日上架）却给这盆冷水浇得透心凉：作者对两个代表性方法（Agent Workflow Memory 与 ReasoningBank）在 WebArena、VisualWebArena、SCUBA 三大网页基准上做了"加严重测"——每个实验跑 3 次量化方差、把任务顺序随机打乱两次——结果发现：**① 自改进循环会把本就存在的评估噪声放大，71% 的情况下方差不降反升，同一次实验最好与最差运行可差 10 个百分点；② 所谓"进步"高度依赖任务顺序，前人默认的"从易到难"排序其实是一种隐式课程，一旦打乱顺序，RBank 从默认顺序下的 +1.5% 进步变成 -4.5% 的退步；③ 在 GPT-5-mini 这样更强的基座上，两个方法的增益要么消失（AWM -0.7%），要么统计上不显著（RBank +1.5%，p=0.23）。** 作者进一步手工检查 Agent 写的记忆，定位到"规范缺失"（underspecification）：Agent 会在只支持浏览器操作的环境里记下"调用 API"的建议，会把"请求用户确认"写进记忆然后卡死等待，甚至会因为地图加载失败而"发明"Haversine 公式硬算距离——这些看似合理实则不可执行的记忆，会像病毒一样在任务流里传染放大。加入评分细则、环境反馈等额外信息后，退化缺口只补回 31%，其余 69% 仍原因不明。**一句话：记忆不是经验，未经校验的记忆只是"未经验证的假设"——而单次运行的分数，可能只是运气。**

## 一、研究背景与动机

**"越用越聪明"的 Agent，正在成为主流叙事。** 自改进智能体（self-improving agents）是当前 Agent 研究里最受追捧的方向之一：系统在线上任务流中持续学习，通过维护文本记忆库在推理时不断优化自己的表现。理论上，它能自动化日常工作流、带来可观的经济效益，甚至支撑开放式科研探索。近两年涌现了大量相关工作——从技能记忆、工作流记忆到推理记忆——"记忆增强"几乎成了 Agent 系统的标配。

**但可靠性问题被系统性忽视了。** 这篇论文开篇就点出要害：现有文献大多只报告"单次运行"的平均通过率，很少对系统做压力测试。而在真实部署场景（尤其是企业环境）里，容错空间极小：第一次失败就可能失去用户信任，更危险的是，**初始错误会在长期运行中无声级联**，在高风险领域造成不可逆的后果。作者引用同行的呼吁（Rabanser 等 2026，"Towards a science of AI agent reliability"）：可靠性应当与能力并列，成为 Agent 评估的基本轴。

**前人的评估协议里藏着三个"隐藏前提"。** 第一，只跑一次——而 Agent 行为天然有随机性；第二，任务按默认顺序排列——作者发现这种顺序暗含"从易到难"的隐式课程；第三，基座模型较弱——AWM 用 Claude-3.5-Sonnet 时基线只有 32.7%，RBank 用 Gemini-2.5-Pro 时基线 46.7%，模型能力本身就有巨大提升空间，"记忆"的贡献被混在了模型进步的贡献里。**当基线换成更强的 GPT-5-mini，记忆方法还能兑现承诺吗？** 这就是本文要回答的问题。

## 二、核心方法

**2.1 问题设定：在线任务流 + 文本记忆库。** 智能体需要完成一串 N 个任务，并维护一个文本记忆库 ℳ。每个任务结束后，一个"记忆构建模块"根据任务轨迹（以及奖励信号）更新记忆库；后续任务开始时，相关记忆被检索出来注入上下文。这是一个纯推理期（inference-only）的自我改进范式——不微调权重，只读写记忆。

**2.2 两个代表性方法。** 作者选择了两条最主流的技术路线：

- **Agent Workflow Memory（AWM）**：只从**成功**轨迹中总结可复用的工作流（step-by-step），写入前做去重检查，之后所有工作流都塞进上下文；
- **ReasoningBank（RBank）**：更近期的做法，记忆不限于结构化工作流，而是更通用的推理痕迹与洞见，从**成功和失败**轨迹中都能生成，并用检索器挑选最相关的记忆注入。

**2.3 加严重测协议：两条新评估轴。** 这是本文方法上的核心贡献，不是提出新模型，而是重新定义"怎么测"：

- **多运行量化方差**：每个实验设置跑 3 次完全相同运行，报告平均通过率、标准差和"最好-最差差距"（best-worst gap）；
- **随机打乱任务顺序**：在默认顺序之外构造两个随机乱序（Shuffle-1、Shuffle-2），检验"进步"是否依赖排序；
- **更强的基线**：基座换成 GPT-5-mini（同时充当 Agent 与记忆构建模型），并用更强的 Agent harness；记忆构建时直接喂**真实奖励**（ground-truth reward），而不是前人用的、作者认为噪声很大的 LLM-Judge 代理奖励。

**2.4 追因：手工检查记忆，定位"规范缺失"。** 方差为什么爆炸、乱序为什么崩盘？作者手工翻阅 RBank 写出的记忆，发现三类典型失败模式：

- **环境规范缺失**：Agent 频繁在记忆里推荐"调用 API"方案，但实验环境是纯浏览器操作、根本不支持代码执行；它还喜欢写"请求用户确认"（3 次运行里 WebArena 出现 26 次、VisualWebArena 22 次），而评测环境里没有人类可确认——结果 Agent 反复发出"等待"动作直到超时；
- **任务规范缺失**：任务本身有歧义。比如 WebArena 任务 118 让 Agent"展示能缓解磨牙症的东西"，意图是找到护齿套商品，Agent 却字面理解成"建议咨询牙医"，还把"先收集患者背景信息再给医疗建议"这种无关经验写进记忆；
- **记忆的"传染性"**：在 Map 域，地图网站偶尔加载失败，Agent 就自创"用 Haversine 公式估算距离"的兜底策略，偶尔蒙对答案后居然被写进记忆、反复检索使用——越早入库，传染越广，这直接解释了跨运行的方差放大。

**2.5 干预实验：给记忆构建"补规范"。** 作者设计三类补充信息：**+Rub**（把评分细则、must_include 等评测函数细节喂给记忆模块）、**+Env**（把环境反馈如"点击后文本框消失、动作报错"等信息纳入）、**+PMod**（修改提示词，明确禁止 API 方案、外站访问、请求人工确认，鼓励过程性知识与站点导航结构），以及三者全上的 **+All**。

## 三、实验结果

**发现一：评估本来就有噪声，自改进把它放大了。** 仅看无记忆基线：WebArena GitLab 子集（180 个任务）上，3 次运行的最好-最差差距高达 **4.4%**，标准差 1.98%；SCUBA 上差距最大达 6.7%——单次运行的结果在不少场景下足以被误读成"有效改进"。叠上自改进循环后更糟：**24 个实验组合中有 17 个（约 71%）方差上升，其中 11 个相对增幅超过 50%**；RBank 在 Map 域把最好-最差差距从 2.75% 拉到 **8.2%**，在 Multisite 域拉到 **10.4%**。原因很直接：记忆构建依赖前序任务结果，加上 LLM 采样的随机性，**早期的一点点随机性会随时间复利式放大**，不同运行最终走向完全不同的"记忆人格"。

**发现二：基线一强，增益就消失。** 前作里 RBank 用 Gemini-2.5-Pro 在 684 个 WebArena 任务上做到 53.9%；而本文的 GPT-5-mini 无记忆基线直接达到 55.3%——**"裸奔"已经超过对方"带记忆"的成绩**。在此基座上，AWM 反而 -0.7%，RBank 仅 +1.5%，且 p=0.23（3 次运行的未配对 t 检验），统计上不显著。VWA 上基线 54.9%，甚至超过该基准 2026 年 5 月的榜首都 54.0%。

**发现三：任务顺序决定成败——默认顺序藏着"隐式课程"。** 把基线在默认顺序下的成功率画成滑动平均曲线：前 150 个任务通过率约 75%，之后跌破 40%——**任务 ID 越小越简单，默认排序天然是"从易到难"**（很可能是标注者先写简单任务导致的工件效应）。一旦打乱：WebArena 上 AWM 从 54.8% 跌到 49.1%，RBank 跌到 49.8%；8 个实验组合中 6 个显著退化。RBank 在默认顺序下 +1.5%，乱序下 **-4.5%**——同样的方法，换个顺序就从"进步"变"退步"。

**发现四：补规范只能救回三成。** +All 组合在 Shuffle-1 下把 RBank 从 49.8% 拉回 52.7%（+2.9%），Shuffle-2 下 +1.1%，默认顺序下不破坏原有表现。三类信息单独使用也都有小幅增益、且互不冲突。但即便如此，乱序下仍跑不赢无记忆基线——**退化缺口只闭合了 31%，剩下 69% 的脆弱性来源依然未知**。

## 四、技术启示与发展方向

**启示一：单次运行的成绩单，正在系统性高估 Agent 的进步。** 这篇论文最有价值的产出不是某个新模型，而是一套"加严评估协议"：多运行 + 随机乱序 + 强基线。对研究者，报告多次运行的平均值与方差、压力测试乱序表现，应该成为自改进 Agent 论文的标配；对工程师，论文建议先在"规范良好"的任务上试跑新方法，再在"规范缺失"的任务上做最坏情况测试，再谈部署。**这与此前精读过的"自信陷阱"（8/11）一脉相承：模型对自己的能力过度自信，而我们对模型的评估同样过度自信。**

**启示二：记忆不是经验，是"未经验证的假设"。** 作者这句总结值得全文背诵：没有校验机制的 Agent 记忆，只是把"猜测"当"教训"。API 建议、用户确认、Haversine 公式——这些"看似合理"的记忆不仅没用，还会在后续任务中反复污染决策。**未来方向之一是记忆验证机制**：过滤问题记忆、对记忆条目做可执行性检查、追踪记忆的"信用历史"。这与 8/12 精读的 SkillZip（技能压缩）形成有趣对照——压缩技能的前提是技能本身可靠，而本文恰恰证明：Agent 自产技能的第一道坎是"可信"而非"压缩"。

**启示三：规范缺失是系统问题，不是提示词问题。** 环境有哪些动作可用、任务到底要什么结果、评测怎么打分——这些信息在记忆构建时往往没被交代清楚。论文给出的 +Rub/+Env/+PMod 是"事后补丁"，只救回 31%。真正的解法可能是**系统与界面层面的设计**：让人能及时看到 Agent 写了什么记忆、干预错误经验、迭代式补充规范。现实世界的部署只有一次、不可重来，人类监督界面不是可选项，而是安全底线。

**启示四：警惕"记忆增强"叙事的时代红利。** AWM/RBank 在 2025 年的模型上有效，不等于在 2026 年的模型上有效——模型变强本身吃掉了一部分"记忆的功劳"。这提醒我们：评估任何"能力增强"组件，都必须先锚定一个足够强的基线，否则很容易把模型进步的功劳错记到方法头上。**自改进的下一站，大概率不在"更会记"，而在"会甄别、会遗忘、会求助"。**

## 五、总结

一句话：**Salesforce 用"跑 3 次 + 打乱顺序 + 换强基线"的重测协议，戳破了记忆型自改进 Agent 的泡沫——方差放大 71%、乱序即崩盘（+1.5% 变 -4.5%）、强基线下增益消失，根因是规范缺失导致 Agent 写下"看似合理实则致命"的错误记忆，且补规范只能救回 31% 的退化。** 这篇论文的价值不在于否定自改进方向，而在于给整个领域立了一面镜子：**当 Agent 开始"越用越强"之前，我们得先能证明它"真的在变强"，而不是"恰好碰到了顺手的任务顺序"。** 下一次看到"记忆增强带来 X% 提升"的结论时，不妨先问三个问题：跑了几次？顺序打乱了吗？基线够强吗？
