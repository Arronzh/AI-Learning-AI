# 算力堆不出好决策：测试时计算的"选择瓶颈"与 AI 训练 AI 的"策略锁死"

📌 核心摘要

"给模型更多推理算力，它就会变得更聪明"——这是过去两年最主流的 scaling 信仰。今天精读的两篇同日上架论文（arXiv:2608.18931 与 2608.19072，分别来自 Thomson Reuters 与清华/人大团队）却从两个完全不同的方向，同时撞上了同一堵墙：**算力可以堆出更好的"候选"，却堆不出更好的"决策"。** 第一篇论文首次对测试时计算（Test-Time Scaling）做"野外"实测：在医学、法律、金融、通用对话、创意写作五个开放生成基准上，用统一框架把每种方法的 token 预算拆成"探索"（生成候选）与"利用"（打分、选择、合成最终答案）两半，结果发现——**探索端一切正常，候选池质量随算力稳步上升；崩掉的是利用端：最强奖励模型与真实质量的相关性只有 ρ≈0.12，近乎随机选择，Best-of-N 把预算拉高 8 倍几乎零收益，树搜索被 PRM 引导出"多样性崩溃"（16 个粒子实际约等于 1 条轨迹），只有跨候选合成（Fusion）一致有效，却也只恢复了约 40% 的可用空间。** 第二篇论文则把镜头对准"AI 训练 AI"：分析 1,338 条公开的 LLM 后训练轨迹后发现，前沿 Agent 是称职的"执行者"，但**训练策略在开局前就被锁死**——Claude Code 有 80.7% 的轨迹锚定全参数 SFT，Codex CLI 有 89.6% 锚定 PEFT，相邻训练之间只有 3.6% 尝试过更换策略。给 Agent 补经验（+12.6 GSM8K、+40.8 HumanEval）、补人类指导、补推理算力（AIME 上多烧 7.9 倍 token、约 6,700 万 token 才多解对一道题），都只能改善"执行"，无法撬动"策略"。**一句话：当模型越来越会"生成"和"执行"，卡住它们继续变强的，是"选不出答案"与"改不动策略"这两个决策环节。**

## 一、研究背景与动机

**测试时计算的"温室"与"野外"。** 测试时计算（TTS）是当前提升模型能力最热的手段：不更新权重，靠推理时多花算力——多采样几个候选再打分（Best-of-N）、在部分序列上做树搜索、对草稿反复精炼（Self-Refine）、或者干脆让模型多想一会儿（extended thinking）。这些方法在数学竞赛题、代码生成、选择题上收获巨大，但它们几乎全部是在"验证很便宜"的任务上发育起来的：答案对不对，一眼可知。可一旦进入开放生成任务——医疗咨询、法律分析、金融研判、创意写作——"对错"变成多维度评分细则，二元验证不复存在。**第一篇文章（Thomson Reuters 团队）指出：TTS 方法的成功高度依赖验证器（奖励模型）本身可靠；验证器一垮，整个方法家族跟着垮。**

**"AI 训练 AI"的叙事漏洞。** 与此同时，Agent 已经能端到端地"后训练"一个 LLM：写代码、启动训练、评估 checkpoint、提升下游性能，AI-for-AI 似乎近在眼前。第二篇文章（清华孙茂松/林衍凯团队等）却指出，这个图景混淆了两种能力：**执行级能力**（在选定策略内迭代——修 bug、调超参、改数据格式）与**策略级能力**（随着实验证据积累，修订高层判断——换训练范式、增删阶段、重分配预算）。作者分析了一个大胆的假设：也许 Agent 缺的不是执行力，而是"证据都摆在面前，却从不改弦更张"的策略能力。

**两篇论文共享一个追问：资源（算力、经验、指导）真的能买到更好的决策吗？** 一个从推理侧问，一个从训练侧问；一个在西方工业界实验室，一个在中国高校。答案却惊人地一致：**不能。**

## 二、核心方法

**论文一：把 TTS 拆成"探索-利用"两本账。** 作者构建了一个统一框架：固定 token 预算下，每种 TTS 方法都在"探索"（生成候选池）与"利用"（把候选池变成最终输出）之间分配资源。实验覆盖五个开放生成基准——医学（HealthBench）、法律（LEXam）、金融+法律（PRBench）、通用对话（WildBench）、创意写作（WritingBench），横评六种代表方法：Best-of-N+ORM（并行采样+外部奖励模型打分）、Beam Search（确定性树搜索）、Particle Filter（随机重采样树搜索）、顺序精炼 SR（自批判迭代改写）、Budget Forcing（单轨迹长思考）、Fusion（跨候选合成）。生成器用 Qwen3.5（9B/35B-A3B）与 OLMo3 两大家族，奖励模型用 Skywork-Reward-V2 与 Llama-3.1-70B-RM，全部做**计算量归一**（四个算力档位），总计评估 270 亿生成 token、耗费 23,800 B200 GPU 小时。方法上的关键创新有两个：一是**去偏的 oracle 估计器**——直接取候选池最高分会系统性高估池子质量（取最大值等于连噪声一起选），作者推导出逐条目闭式修正；二是**一条可验证的理论预测**：Best-of-N 的"空间恢复率"（headroom capture，即方法实际拿到手的好答案比例）约等于验证器与真实质量的相关性 ρ——奖励模型越不准，加多少算力都是白搭。

**论文二：先解剖轨迹，再递进干预。** 作者首先分析 PostTrainBench 公开的 1,338 条 Agent 后训练轨迹（7 个基准、4 个基座模型 1.7B-4B、20 种 Agent 配置、每条 10 小时 H100 预算），把"策略变化"严格定义为改变训练范式、数据源类型或阶段结构——调学习率、改数据配比、换对话模板都只算"执行变化"。然后设计三组递进干预，逐一检验三个候选解释：**缺经验？** 给 Agent 装上实验日志（跨迭代持久化观察）、技能库（从 verl/TRL 等开源框架蒸馏）、评估者 Agent（返回具体诊断与可执行建议）；**缺指导？** 训练开始前由人类评审者对策略做"绑定式"修订（不是建议，是批准/驳回）；**缺推理算力？** 对比干预前后消耗的推理 token，检验"多想一会儿"是否等于"想得更对"。

## 三、实验结果

**论文一：探索有效，利用崩盘。**

- **验证器相关性崩塌。** 在 152 个（生成器×奖励模型×基准）组合上，两个最强 ORM 与真实质量的 Spearman 相关性平均只有 ρ≈0.12——比随机略好一点。理论预测"空间恢复率≈验证器相关性"，实测回归斜率≈1、截距≈0，完美命中。
- **Best-of-N 的 8 倍预算白烧。** 预算从低档拉到高档（8 倍 token），BoN 整体得分只从 0.574 爬到 0.584；两个奖励模型（8B 与 70B）成绩几乎完全相同——这是结构性失败，不是模型个体问题。
- **树搜索死于"多样性崩溃"。** PRM 引导的重采样让候选池自己塌掉：Particle Filter 最终输出的平均余弦距离只有 0.036-0.069，而 BoN 是 0.123-0.124——写作任务上 16 个名义粒子从头到尾几乎一模一样，实际约等于 1 条轨迹。校准不良的 PRM 每一步都在剪掉好分支，最优候选存活的概率随深度指数衰减。
- **顺序精炼只在 1/5 基准上真有效。** SR 在金融法律 PRBench 上确实持续改进；但 HealthBench 上每多迭代一轮反而退化（-2.3pp），写作基准上的 +7.3pp 增益被证明是"冗长偏置"（长度与分数相关 0.xx，裁判偏爱长答案）——去掉这个混淆后增益消失。
- **唯一赢家是 Fusion，但只赢一半。** 跨候选合成是唯一在每个基准上都超过单样本基线的方法（高档算力下 0.610 vs BoN 的 0.584 vs 基线 0.574），但它只恢复了约 40% 的可用空间（BoN 只有约 15%）。更扎心的是跨家族对比：OLMo3.1-32B 生成的候选池与 Qwen3.5 一样好，Fusion 却在其 2/3 的基准上"合成出比随机候选更差的答案"——**生成能力不等于利用能力，这是两种独立的能力。**

**论文二：执行满分，策略零分。**

- **Agent 是称职的执行者。** 1,338 条轨迹共启动 5,111 次训练，平均每个基准把基座模型提升 10.41 个百分点（最好 23.0%）；Agent 会修 EOS 错误、重构数据、逐步缩小学习率，把失败的训练救回来——执行级能力不是瓶颈。
- **策略在开局前锁死。** Claude Code 80.7% 的轨迹锚定全参数 SFT，Codex CLI 89.6% 锚定 PEFT——**策略跟随 Agent 而非任务**：同一个任务上，不同 Agent 各抱各的默认值。所有相邻训练对中，只有 74/2,075（3.6%）尝试过换策略；OpenCode 的切换率 0.4%，Qwen3Max 干脆是 0.0%。换资源预算复测依然如此（GLM-5.2 全程全参 SFT，GPT-5.2 几乎全程 PEFT）。
- **补经验：执行大涨，策略纹丝不动。** 经验驱动框架把 GSM8K 从 64.7% 拉到 77.3%（+12.6）、HumanEval 从 22.0% 拉到 62.8%（+40.8，几乎追平官方 instruct 模型）；但评估者 Agent 反复建议"从 SFT 切到 RL""加 SFT warm-up 阶段"，主 Agent **采纳了全部执行级建议，策略级建议一条都没采纳**——甚至在写好 GRPO 训练脚本之后，仍然没有启动 RL 训练。
- **补指导：起点被改写，然后慢慢塌缩。** 人类评审把 AIME 2025 的策略从"SFT 为主"改为"RL 为主、SFT 只做格式热身"，Agent 不仅照做，还自主判断格式无需 SFT 直接跳过——策略级能力其实是有的。但 pass@8 只到 13.33%（仍在评估方差内），且最优结果出现得很早，之后就是来回调超参的局部循环。
- **补算力：容易任务划算，最难任务撞墙。** 经验框架整体多烧 2-4 倍推理 token（AIME 上高达 7.9 倍，约 6,700 万 token 才换来多解对一道题）。GSM8K/HumanEval 上算力换性能很划算；AIME 上，额外算力全部花在了锁死策略内部的更密集局部搜索上。**作者总结：一个 Agent 完全可以在错误的策略里高效迭代十个小时。**

## 四、技术启示与发展方向

**启示一：决策层，是新的 scaling 边界。** 两篇论文合起来讲了一个故事：生成（exploration）可以 scaling，执行（execution）可以 scaling，但"选择"与"策略修订"这两个决策环节对算力、经验、指导统统不敏感。这与此前精读的 7/31"反思不如重试"、8/13"测试时计算"一脉相承，但更进了一步——**不是"算力花在哪更值"的问题，而是"算力根本买不到决策质量"的问题。**

**启示二：验证器是测试时计算的阿喀琉斯之踵，但缺口可以测量。** ρ̂_v（验证器与真实质量的相关性）是一个便宜的诊断指标：部署前在小样本上测一下，就能预判 Best-of-N 值不值得烧钱。当生成器强于奖励模型（generator outpacing RM），TTS 不仅无效甚至有害——在高 stakes 领域（医疗、法律、金融）这直接意味着"未经人类复核的 TTS 部署不可取"。训练面向开放任务的校准验证器，是明确的下一步。

**启示三：评估协议要跟上——"取最大值"本身就有偏。** 论文一的去偏 oracle 估计器提醒我们：用裁判分数取 max 会连噪声一起选中，池子越大偏差越大。这与昨天（8/19）精读的 Salesforce 重测文章形成呼应：单次运行、朴素估计、默认顺序，都在系统性高估系统的真实进步。**评估方法论本身正在成为一门显学。**

**启示四：AI-for-AI 的下一站，是把"改策略"变成显式动作。** 论文二最锋利的结论是：缺的不是能力，是"自发性"（spontaneity）——Agent 能理解、实现、甚至超越一个不是自己提出的策略，但永远不会主动开启策略重估。作者的药方不是更大模型，而是**训练信号与交互协议**：让"重新打开一个已承诺的选择"成为显式、有奖励的决策点，而不是长上下文里一个隐式选项；在训练开始后保持人类参与，因为策略只在开局前的短窗口内可塑。这与 8/12 SkillZip（技能压缩的前提是技能可信）是同一逻辑的另一面：**自我改进系统的第一瓶颈，从来不是"做得不够多"，而是"不会质疑自己正在做的事"。**

## 五、总结

一句话：**Thomson Reuters 在五个开放生成基准上证明"测试时计算的瓶颈不是生成候选，而是选择答案"（奖励模型相关性 ρ≈0.12，8 倍算力近乎零收益，只有 Fusion 恢复约 40% 空间）；清华与人大团队在 1,338 条后训练轨迹上证明"AI 训练 AI 的瓶颈不是执行，而是策略"（开局锁死、切换率 3.6%、经验/指导/算力三重干预全部只改善执行）。** 两篇论文，一个从推理侧、一个从训练侧，殊途同归地指向同一判断：**当"做"变得廉价，"选"和"改"就成了新的稀缺品。** 对从业者，这既是警告也是机会——谁先解决"决策层的 scaling"，谁就握住了下一代 AI 系统的钥匙；而对每一个迷信"堆算力就能变强"的人，这两篇论文是一剂及时的清醒药：**多想想，不如选得对、改得动。**
