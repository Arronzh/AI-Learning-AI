# 安全对齐的开关与盲区：66 万参数门控把越狱率打到 0.5%，360 条假记忆让四道筛查形同虚设

📌 **核心摘要**：大模型安全对齐正在经历一场"精细化"革命——但攻防两侧同时在进行。**CLEAR**（2608.21278，斯坦福 Sanmi Koyejo 团队联合 UIUC）把安全干预从"全局一把梭"改成"按输入条件路由"：冻结主干模型，挂一个安全 LoRA 适配器，用一个只有 **66 万参数**的隐状态门控连续控制适配器激活强度。良性提示几乎不激活、恶意提示才加强干预——在 Llama-3-8B-Instruct 上把 HarmBench 越狱成功率从 **32.25% 打到 0.50%**，同时 GSM8K 数学能力保留 **73.46%**，比全局 SFT/LoRA 高约 **7 个百分点**，门控成本仅为 Llama Guard 3 的八千分之一。另一边，**Agent 记忆投毒**（2608.21230，开源记忆层 Aegis 的自审报告）揭示了一个更冷峻的盲区：持久记忆让"一次被接受的假话"变成"每次都被检索到的持久错误"。攻击者用最弱的攻击——一句措辞普通的假话，无指令、无触发词、无任何优化——污染语料库 **1.2%**（360 条），就让 LongMemEval 准确率从 **0.850 暴跌到 0.300**；而 recall 高达 0.832 的四阶段写入筛查管线，对这 360 条毒记忆**零拦截**。溯源加权检索的出厂权重与无防御统计上毫无差异（p=0.80），调大后却只能靠"排除"而非"偏好"生效——答案证据本身不可信时，检索直接归零（准确率 0.0417）。安全既要有"开关"，也要直面"盲区"。

## 一、研究背景与动机

先看一个行业共识里的隐痛：**对齐税（alignment tax）**。

为了让模型拒绝有害请求，主流的做法是全局安全微调——SFT、RLHF、DPO，或者挂一个 LoRA 适配器，所有输入一视同仁地经过同一套"安全参数"。问题是，这套参数不仅会改变模型对恶意提示的回应，也会悄悄改变它对良性提示的回应：过度拒绝（over-refusal）频发，数学推理、代码能力下滑。你越强调安全，模型越"草木皆兵"——这是安全-能力权衡里最经典的困局。

过去的研究大多在"数据"和"策略"层面缓解这个矛盾，但一个更根本的问题被忽略了：**安全干预为什么必须是全局的？** 能不能让模型自己判断"这个输入危不危险"，危险时加强干预、安全时保持原样？这正是 CLEAR 的出发点。

与此同时，另一场攻防正在 Agent 记忆的战场上展开。无状态的 LLM 应用里，攻击者的破坏被限制在单次请求内——上下文窗口一丢，一切归零。但**持久记忆改变了游戏规则**：内容写入一次，就会被检索进未来的每一次会话。这意味着攻击者的载荷不再需要在到达时生效，只需要被存储、被检索。更棘手的是，现有防御体系——提示注入检测、指令层级、输出约束——全都是为"指令型载荷"设计的，而记忆投毒攻击**根本没有载荷**：它只是一句普通的假话，唯一的缺陷是"内容是错的"。

两篇论文，一问一答，恰好构成安全对齐的一体两面：**一个在问"安全干预该管多少"（开关），一个在问"防线到底能看见什么"（盲区）**。

## 二、核心方法

### CLEAR：把安全适配器装上一个"连续开关"

CLEAR 的思路非常直接：主干模型完全冻结，安全能力全部装进一个 LoRA 适配器，而适配器的激活强度由一个从隐状态学出来的门控连续控制。

具体来说，给定输入 prompt，模型先用主干的前向计算提取中间层与后期层的隐状态，交给一个两层 MLP 门控，输出一个连续分数 g(x) ∈ [0,1]。这个分数直接调制适配器：h′ = (W + g·ΔW)h。良性提示分数趋近 0，模型行为接近冻结主干；恶意提示分数升高，安全适配器被激活，生成向拒答对齐。推理时，先跑一次仅含 prompt 的门控前向拿到 g，再开始解码——同一个 g 作用于整条序列的所有适配层。

门控的训练有三个关键设计。第一，**子类型感知的加权**：用 WildJailbreak 的四类标签（vanilla/adversarial × benign/harmful）训二分类，但对"对抗性良性"和"对抗性有害"样本加大权重——它们最容易骗过门控。第二，**硬成对间隔损失**：显式要求恶意提示的门控分数比良性提示高出一个间隔 m，并且对"高分良性、低分恶意"的混淆对加权惩罚，把两类样本在门控分数空间里硬性分开。第三，**仅用不安全数据对齐适配器**：LoRA 只学"恶意提示 → 安全回应"的映射，良性输入根本不参与适配器训练——安全行为只在被激活时存在。

一个容易被误解的点：这个门控**不是**外部过滤器，也**不是**后置审核模块。它和适配器联合优化，直接调制前向计算——安全干预从"全局参数更新"变成了"条件化的潜在路由"。

### 记忆投毒：最弱的攻击，捅破最强的防线

攻击者的手法朴素到令人不安。给定一个问题及其真实答案，生成模型产出一个"看似合理但错误"的假答案，再写成三轮普通对话——复用问题里的关键词，让假记忆在检索时能和真证据竞争。例如用户实际有 20 个 Spotify 歌单，毒记忆就写"你有 15 个歌单"。120 个问题 × 3 轮 = **360 条毒记忆，约占语料 1.2%**。没有指令、没有角色操纵、没有编码技巧、没有针对检索器的任何优化——这是作者能构造的最弱攻击。

防御侧，被攻击的系统 Aegis 有两条防线。**写入路径**是四阶段筛查：输入校验 → 敏感数据检测 → 规则式注入检测 → 条件触发的 LLM 分类器（置信度 ≥0.8 直接拒绝）。这套管线在间接提示注入上 recall 高达 0.832，对含触发词的良性文本误报率仅 1.5%——比 DeBERTa 系检测器低一个数量级。**读取路径**是溯源加权排序：score = w_s·sim(q,m) + w_t·τ(m) + …，其中信任先验 τ 按通道分级：untrusted 0.0、unknown 0.5、internal 0.7、privileged 0.85、system 1.0。

## 三、实验结果

### CLEAR：安全不掉，能力少掉

在 Llama-3-8B-Instruct 上，CLEAR 把 HarmBench 越狱成功率从 32.25% 压到 **0.50%**，XSTest 不安全拒绝率从 88.50% 升到 92.50%；而良性输入的过度拒绝率只有 4.80%——全局 SFT 是 10.80%。能力侧，GSM8K 保留 **73.46%**，比 SFT（66.34%）和标准 LoRA（66.72%）高出约 7 个百分点，TruthfulQA MC2 也全面领先。在 Gemma-2-2B-it 上同样成立：ASR 9.50% → 0.00%，不安全拒绝率 48.50% → 96.00%，GSM8K 41.62% vs SFT/LoRA 的约 38%。

| 模型 / 方法 | HarmBench ASR ↓ | 不安全拒绝率 ↑ | 过度拒绝率 ↓ | GSM8K ↑ | TruthfulQA MC2 ↑ |
|---|---|---|---|---|---|
| Llama-3-8B（基线） | 32.25% | 88.50% | 2.80% | 75.06% | 52.47% |
| Llama-3-8B + SFT | 2.00% | 94.00% | 10.80% | 66.34% | 48.28% |
| Llama-3-8B + LoRA | 0.00% | 82.50% | 6.40% | 66.72% | 50.46% |
| **Llama-3-8B + CLEAR** | **0.50%** | **92.50%** | **4.80%** | **73.46%** | **52.63%** |
| Gemma-2-2B + SFT | 0.00% | 90.00% | 5.20% | 38.06% | 47.99% |
| **Gemma-2-2B + CLEAR** | **0.00%** | **96.00%** | 9.60% | **41.62%** | **53.19%** |

表格里最有信息量的一行是 Llama-3-8B：全局 SFT 把越狱率压到 2.00% 的同时，过度拒绝率飙到 10.80%、GSM8K 掉了近 9 个点；CLEAR 用几乎相同的安全水平（0.50%），把过度拒绝控制在 4.80%、GSM8K 只掉 1.6 个点。这就是"开关"的价值——干预按需发生，而不是无差别覆盖。

与既有对齐模型家族对比更直观：Llama-3-8B-RR 的 ASR 是 15.50%，CLEAR 是 0.50%；P-SACPO 从 22.50% 加装 CLEAR 后降到 0.50%。门控的代价呢？**664,129 个参数**——对比 PromptGuard 的 2.79 亿和 Llama Guard 3 的 80.3 亿，差了三个数量级。

缩放实验里，Qwen2.5 从 0.5B 到 7B，CLEAR 的 ASR 全部压到 2.00% 以下，7B 时 GSM8K 分毫未损；门控的可分性也随规模提升（ROC-AUC 从 0.78 升到 0.96）。更硬核的是潜在空间自适应攻击测试：攻击者直接扰动隐状态，CLEAR 在嵌入层/中间层/末层的 ASR 只有 0.0%/7.1%/18.4%，而标准 LoRA 是 54.0%/48.0%/31.0%、全局 SFT 是 47.0%/35.0%/22.0%——条件路由把安全干预限制在"风险激活区"，反而更难被潜在扰动攻破。

### 记忆投毒：0 / 360 的荒诞

结果冷峻得近乎黑色幽默。**1.2% 的毒记忆，让 LongMemEval 准确率从 0.850 掉到 0.300**——三分之二的记忆价值蒸发，而且只有一部分损失来自"模型采信了假答案"，更多是毒记忆挤占了真证据的检索位。

| 防线 | 配置 | 效果 |
|---|---|---|
| 写入筛查（四阶段管线） | 间接注入 recall 0.832、良性误报 1.5% | 对 360 条毒记忆拦截 **0 条** |
| 溯源加权（出厂权重） | 溯源最多压倒 0.175 相似度差距 | 与无防御无差异（p=0.80）；毒记忆靠措辞拿到 0.32 相似度优势 |
| 溯源加权（调大权重） | 不可信内容绝对惩罚 0.245（>相似度上限 0.45 的一半） | 靠"排除"生效：不可信内容大多良性时 0.3167 → 0.7000 |
| 溯源加权（证据不可信） | 答案证据来自不可信通道 | 120 个问题检索全部归零，准确率 **0.0417** |

写入筛查的表现更是触目惊心：对间接注入 recall 0.832 的强管线，对 360 条毒记忆**拦截数为 0**。作者强调这不是调参失败，而是**方法类别的结构性边界**：区分"假话"和"真话"需要文本之外的外部 grounding——筛查器要能识别假话，就得先知道答案，那它还需要记忆干什么？

读取侧同样没有好消息。出厂溯源权重的表现与"无防御"统计上不可区分（p=0.80），三行推导就能解释：该权重下溯源最多只能压倒 0.175 的相似度差距，而毒记忆靠"说得像问题"就拿到了 0.32 的相似度优势。把权重调大后确实有效了，但方式令人不安——它对不可信内容的绝对惩罚是 0.245，超过语义相似度最大贡献 0.45 的一半：不可信内容不是"被降低优先级"，而是**被直接排除**。两个混合溯源语料验证了这个判断：当不可信内容大多是良性时，防御依然有效（0.3167 → 0.7000）；但当答案证据本身来自不可信通道时，120 个问题的检索无一幸存，准确率跌到 **0.0417**。作者的结论斩钉截铁：在可测量的相似度 regime 下，**加性溯源惩罚没有可用设置**——任何能扛住"会塑造内容的攻击者"的权重，都足以把不可信内容整体排除。他们给出的替代方案是"有界占用约束"：给不可信内容保留空间，而不是罚分。

## 四、技术启示与发展方向

- **安全干预正在从"全局参数"走向"条件路由"。** CLEAR 与 MoE、routed adapter 一脉相承：输入条件化的干预，比全局微调更精细、更省成本。对齐税的本质是"干预错配"——干预了不该干预的输入。门控机制把税基从"所有输入"缩小到"高风险输入"。
- **门控本身是新的攻击面。** CLEAR 论文坦承：良性提示仍可能误触发、低分恶意提示可能绕过适配器；门控的校准和分布漂移鲁棒性都是开放问题。当防御变成"一个开关"，攻击者就会研究"怎么拨动这个开关"。
- **内容筛查存在结构性盲区：假话与真话在文本特征上不可分。** 360 条毒记忆零拦截不是检测器不行，而是这类攻击根本没有载荷。写入时无法判定真假，防御重心就必须向读取侧转移——这是"信任分配"问题，不是"内容检测"问题。
- **溯源是通道属性，不是真值属性。** 不可信内容可能完全正确，内部内容也可能出错。加性溯源惩罚在"攻击者能塑造内容"的 regime 下无可用设置，有界占用约束、非可变溯源绑定（non-malleable origin binding）是更值得探索的方向。
- **评估口径需要革命。** 攻击成功率（ASR）无法区分"抵抗了攻击"和"被攻击废掉"，也看不见无攻击时防御的代价。utility retained（保留效用）+ 误报率与召回率并列报告，才是一个系统在被攻陷后"还值多少"的真实答案。

## 五、总结

两篇论文，一场关于安全对齐的攻防两面。CLEAR 证明：**安全干预可以是连续的、按需的、几乎免费的**——66 万参数的门控，把越狱率打到 0.5% 的同时保住数学能力，安全不再必然以能力为代价。记忆投毒则证明：**当攻击不携带任何可检测特征时，写时防线结构性失效**——最弱的攻击击穿了最强的筛查，防御只能退守到"该信谁"的分配问题。

一个在问"该管多少"，一个在问"该信多少"。它们共享同一个底层洞察：**安全不是一个全局开关，而是一套需要精细分配的连续资源**——管得太多会伤能力，信得太多会中毒。在 Agent 时代，这个分配的精度，就是安全的边界。
