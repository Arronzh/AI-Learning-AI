# 执行前的最后一道闸门：StepGuard 用 4B 参数把 Agent 攻击成功率砍掉 77.3%

📌 **核心摘要**：LLM Agent 一旦会调用工具，就拥有了"改文件、发消息、泄露敏感信息、执行交易"的真实世界后果——但现有守卫大多只做"事后审计"，等危险动作已经执行完才追责。上海 AI Lab 等机构团队（2608.24777，EMNLP 2026）提出 **StepGuard**，一个只有 4B 参数的"步骤级"守卫模型：既能**在执行前**拦截候选工具调用，也能**事后**审计完整轨迹。为了让这个 4B 小模型学会"拦得准"，他们做了两件事：一是 **StepGen** 数据引擎——围绕"风险锚点"自动生成**前缀对齐**的安全/不安全轨迹对（同一段执行历史，只在危险那一步分叉出 Refuse 拒绝、Aware 察觉后绕行两种安全结局），再配上复用同类工具的良性轨迹，防止守卫把"工具身份"当安全信号；二是 **Balance-GRPO**——在 GRPO 之上按"安全类与不安全类的实时准确率差"动态重加权，把过防御与漏防御一起压下去。结果：静态评测上 StepGuard 拿下开源守卫最高平均准确率，追平闭源的 GPT-5.4；部署到 AgentDojo / AgentDyn 后平均攻击成功率（ASR）相对无守卫降低 **77.3%**，任务效用只掉 **2.8 个百分点**；消融显示 Balance-GRPO 把安全/不安全准确率差从 13.0 压到 8.0，效用最高 +6.7，ASR 仅 +0.3。一句话：**给 Agent 装一道"扣扳机前"的闸门，比事后追责便宜得多。**

## 一、研究背景与动机

LLM Agent 正在从"聊天"走向"动手"。工具调用让模型能改文件、发消息、查数据库、执行交易——也把安全问题的性质从"说了什么"变成"**做了什么**"。现实中的 Agent 攻击已经不再是理论：间接提示注入可以藏在网页、邮件、文档里，等着 Agent 去读；一条恶意指令可能让 Agent 把机密文件发到外部服务器，或者删掉不该删的东西。

现有的防御思路大致分两类。一类是模型级对齐（alignment），在训练时就给模型注入"安全意识"；另一类是**守卫（guardrail）**——在部署时加一道独立监控，不改动、不重训 Agent 本体。但论文指出，现有守卫普遍存在两个问题：

1. **粒度太粗**：多数守卫评估的是"完整的轨迹"——动作已经执行完了，守卫才给出一个事后判断。而真正值钱的拦截点是在**执行之前**：候选工具调用刚被 Agent 提出来、还没落地的那一刻。步骤级（step-level）的预执行监控几乎没人做。
2. **防御偏差（defense bias）失控**：有的守卫"宁可错杀一千"——过度防御，把大量良性动作拦下来，任务效用大损；有的守卫"绝不放过一个"——漏防御，危险动作悄悄溜过去。安全与效用之间的天平，训练时没人管。

更扎心的是数据困境：真实世界里的"危险执行"极其稀有，人工构造步骤级标注又贵又难扩展到各种工具、场景和风险类型。就算有了数据，如何让训练过程显式地根据"安全类/不安全类的准确率差"来校准行为，也仍是空白。

StepGuard 的目标很直接：**把守卫从"事后诸葛亮"变成"事前哨兵"，并且用一套可扩展的数据管线 + 动态平衡训练，让 4B 小模型也能在安全与效用之间站住脚。**

## 二、核心方法

### 守卫模型：结构化诊断，而不是一个"安全/不安全"标签

StepGuard 基于 Qwen3-4B-Instruct 微调，输入可以是"完整轨迹"（事后诊断）或"当前前缀 + 候选动作"（执行前拦截），输出一个结构化的安全诊断：

- **Ŷ**：安全/不安全判定
- **B̂**：是否存在风险来源
- **R̂**：风险来源类型
- **Ŝ**：不安全步骤定位（可选）

一个关键设计理念：**检测到风险来源 ≠ 判定不安全**。上下文里可能有风险源，但如果 Agent 正确识别并妥善处理了，这条轨迹依然是安全的。这让守卫学会"看上下文做判断"，而不是"看见敏感工具就报警"。

### StepGen：前缀对齐的数据引擎

真实危险执行太稀有，那就合成。StepGen 按 ATBench 的风险分类法采样（风险来源、失败模式、危害类型），让规划器构造一个任务场景和结构化执行计划，并指定其中一个动作作为**不安全锚点（risk anchor）**——即风险首次出现的那个动作。然后用环境模拟器 rollout 出一条不安全的基础轨迹。

接下来是精髓——**前缀对齐的对比分支**：固定锚点之前的执行前缀不动，只重放锚点之后的剩余计划，生成两条安全分支：

- **Refuse 分支**：拒绝那个危险动作；
- **Aware 分支**：识别出风险，但通过安全替代方案继续完成任务。

这样得到的三条轨迹（1 条不安全 + 2 条安全）**共享同一段历史、只在关键决策点分叉**——守卫必须学会区分"同一语境下的不同选择"，而不是靠上下文表面的线索蒙答案。

此外，StepGen 还独立构造一条**良性工具复用轨迹**：在非对抗场景里用同一组工具正常干活。这防止守卫偷懒——把"用了敏感工具"当成"不安全"的信号，逼它真正理解动作意图。

最后是质量控制：规则验证器 φ_mech 检查轨迹结构、工具调用格式和参数来源链；LLM 审计器 φ_qual 评估语义一致性、锚点正确性和场景真实性，双重过滤后才进入训练集。

### Balance-GRPO：动态校准安全—效用天平

冷启动 SFT 只学了"格式和基本风险推理"，但 SFT 检查点明显**过度防御**（安全类准确率 69.3 vs 不安全类 91.1，差 21.8）。为此论文提出 Balance-GRPO，在标准 GRPO 上加了两个重加权因子：

- **c_i**：修正类别数量不平衡（少数类获得更多权重）；
- **ω_i**：根据 rollout 批次里实时计算的类间准确率差 Δ_cls = Acc_safe − Acc_unsafe，**给当前准确率更低的那个类更大的训练权重**——安全类落后就多学安全，不安全类落后就多学不安全，并带死区滤波防止震荡。

最终优势 A′ = c_i · ω_i · A，奖励函数采用结构化设计：只有判定正确才给风险类别分（0.5·判定 + 0.5·判定且类别正确）。不改变提示采样和原始奖励，只动权重——训练动态地"扶弱"，而不是静态地"端水"。

## 三、实验结果

### 静态评测：4B 追平 GPT-5.4，内容守卫全线溃败

在 3 个轨迹级基准（ATBench、R-Judge、ASSE Security）和 2 个步骤级基准（TS-Bench-Dojo、TS-Bench-Harm）上，StepGuard 平均 Acc/F1 达到轨迹级 **83.0/83.3**、步骤级 **84.8/84.1**——开源守卫中最高，与闭源 GPT-5.4（步骤级平均 81.3/83.3）同一水平线。

对比组里最有信息量的是"内容安全守卫"的崩盘：LlamaGuard3-8B 在 ATBench 上 F1 只有 16.4，Qwen3-Guard-8B 更是只有 7.3——它们擅长判断"一句话危不危险"，却完全看不懂"多步工具调用 + 执行上下文"里的风险。专用 Agent 守卫（AgentDoG、ShieldAgent-THU、Safiron、TS-Guard）在轨迹级有进步，但**增益没能迁移到步骤级**；StepGuard 是唯一在两级评测都保持高水准的模型。

### 运行时部署：ASR 砍掉 77.3%，效用只掉 2.8 个点

用同一个 Qwen3.6-35B-A3B 作为底层 Agent、只换守卫，在真实 Agent 环境里测：

| 环境 | ASR（越低越好） | 效用（越高越好） |
|---|---|---|
| AgentDojo | **1.2** | 90.7 |
| AgentDyn | **9.3** | 66.7 |
| 相对无守卫 | **−77.3%** | −2.8 点 |

两个环境平均：攻击成功率相对无守卫下降 **77.3%**，而良性任务效用只损失 **2.8 个百分点**——这正是"安全—效用平衡"想要的形态：拦得住攻击，又不耽误干活。

但 AgentHarm 依然是个硬骨头：恶意分数从 22.8 降到 3.4，可任务完成率也从 70.9 掉到 52.8。论文坦诚：在高度对抗的"恶意 Agent"设定下，没有任何守卫拿到清晰占优的权衡——**开放问题**。

### 消融：每个组件都站得住

- **StepGen 前缀监督**：轨迹级平均 Acc/F1 从 80.4/82.0 提到 83.8/83.4——"在哪一步出问题"的标注确实有用。
- **良性工具复用**：TS-Bench-Harm F1 从 69.2 提到 75.2——防止"看工具下菜碟"的捷径。
- **泛化性**：只用 2 种风险来源（恶意指令/越狱 + 间接提示注入）训练，在**没见过的 6 种风险来源**上拿到 74.9/78.1，碾压骨干模型（49.6/35.6），逼近全量训练（76.8/80.7）。
- **Balance-GRPO**：相比 vanilla GRPO，安全/不安全准确率差从 13.0 压到 **8.0**，Acc/F1 提升到 82.2/82.1；部署后 AgentDojo 效用 85.3→90.7、AgentDyn 60.0→66.7，ASR 只涨 0.3。对比"固定权重 1.5/0.5"这种静态方案：虽然也能压差距（7.9），但**不安全类准确率被牺牲到 77.5**，而 Balance-GRPO 保持 86.4——动态扶弱，而不是把一边按下去。

## 四、技术启示与发展方向

- **守卫应该长在"执行前"而不是"执行后"。** 事后审计是追责，执行前检查才是止损。对 Agent 平台而言，一个与 Agent 本体解耦、可插拔的步骤级守卫，比反复重训模型更便宜、更可迭代——这也正是 guardrail 路线的核心卖点。
- **"有风险源 ≠ 不安全"是 Agent 安全判断的分水岭。** 内容安全模型在 Agent 场景集体失灵，根因是它们只认"表面危险信号"；而 Agent 安全需要"风险 + 上下文 + 处置"的三元推理。数据构造上，**前缀对齐的对比分支**是教科书级做法：让正负例只差一个关键决策，模型才学得会"关键决策"本身。
- **小心"工具身份"捷径。** 良性工具复用轨迹的设计点醒了所有做 Agent 安全数据的人：如果训练数据里危险样例总用敏感工具，模型学到的就是"工具名 → 危险"的肤浅映射，换一个场景就失效。
- **平衡要用动态反馈，不要用静态权重。** Balance-GRPO 的价值不在于"给弱类加权"这个想法本身，而在于权重来自**训练过程中的实时准确率差**——自适应地扶弱，同时保住强类的绝对水平。这对所有"类别不平衡 + 双目标权衡"的对齐问题（安全、事实性、格式遵循）都有借鉴意义。
- **未解决的问题同样醒目：** AgentHarm 式的恶意 Agent 场景仍无解；合成数据会继承教师模型和风险分类法的偏见；步骤级评测还没覆盖开放工具生态、长程任务、多智能体协作与自适应攻击者；而且守卫不是形式化保证——误拦/漏拦仍会发生，上线还需要"被拦动作如何修订"的策略与人工兜底。

## 五、总结

StepGuard 讲了一个"闸门前置"的故事：与其等 Agent 闯了祸再复盘，不如在每一次工具调用落地之前，让一个 4B 小模型先过一遍"安全体检"。支撑它的不是更大的模型，而是更聪明的数据（前缀对齐的对比轨迹）和更聪明的训练（按实时准确率差动态扶弱的 Balance-GRPO）。

结果很有说服力：静态评测追平 GPT-5.4，运行时把攻击成功率砍掉 77.3% 而效用几乎无损。它同时划出了边界：对付"工具调用"这类具体风险，小守卫已经够用；对付"恶意 Agent"这类全面对抗，还没有银弹。对正在把 Agent 推向生产环境的团队来说，这篇论文提供了一个即插即用的起点，也留下一个值得记住的原则——**安全，最好在动作发生之前就位。**
