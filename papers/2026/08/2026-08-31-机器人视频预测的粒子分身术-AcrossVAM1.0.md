# 机器人视频预测的"粒子分身术"：AcrossVAM1.0 用 0.28M 参数动力学核，把轨迹误差砍掉 21%

📌 **核心摘要**：机器人视频预测有一个"作弊捷径"——画面里大部分像素是静止的，模型只要复制最后一帧就能拿到漂亮的全图指标，却根本没学会机械臂该往哪动。Across Physical AI 与中科院自动化所团队（arXiv:2608.28491）提出的 AcrossVAM1.0 选择把这个问题"拆开治"：用冻结的 SAM3-DLP 编码器把机器人、手臂、夹爪分解成**语义粒子**（位置、尺度、深度、存在性、外观），用一个仅 **0.28M 参数**的时空 Transformer 预测粒子的未来轨迹，再由"因果双流解码器"把粒子渲染的运动与只来自最后一帧的外观合成起来，通过一个**可学习的交付掩码**决定哪里该生成、哪里该保留原图。在自建的 VRS 基准（2,746 段真实机器人轨迹、10 种机器人平台）上，粒子动力学把轨迹误差相对 persistence 基线降低 **21.0%**，未来帧 PSNR/SSIM 从 19.97/0.796 提升到 20.573/0.8004，运动区域 PSNR 提升 1.34 dB。更难能可贵的是论文的"诚实"：它明确报告语言指令的 grounding 依然很弱（打乱文本只改变 2.8–3.1% 的轨迹误差）、LPIPS 尚未超过 persistence、跨机器人泛化不稳定——把"什么有效、什么还没解决"摊开来讲。

## 一、研究背景与动机

预测场景如何演化，对机器人规划、表征学习和数据生成都至关重要。视频预测之所以成为通用接口，是因为它保留了下游视觉策略需要的几何与外观信息。但真实机器人视频有一个"不友好的组合"：**大多数像素是静止的，决定动作的只是少数关节部件**，而同一个自然语言指令又可以对应多条视觉上完全不同的轨迹。

这带来一个隐蔽的评估陷阱：模型完全可以靠"复制最后一帧"拿到有竞争力的全局图像指标——静态区域全对，真正重要的运动却全错。传统的世界模型把整帧压缩进稠密潜变量再学习时间演化，表征能力强，但对应关系（correspondence）、动力学与纹理合成被耦合在一起；物体中心模型把场景表示为槽（slot）或粒子，状态显式、运动可检查，但紧凑的物体瓶颈又不足以重建精细纹理。此外，给视频模型加上语言条件，**并不保证轨迹真的依赖指令**。

AcrossVAM1.0 的思路是"各司其职"：语义粒子负责整个机器人、手臂、夹爪的几何；紧凑 Transformer 预测粒子未来状态；独立的因果外观流负责恢复细节；语言只通过特征级调制（FiLM）注入动力学，让它的影响可以在轨迹层面被测量。稠密分支只观察最后一帧上下文、永远看不到未来帧，未来运动无法从外观路径泄漏——从架构上堵死了"抄答案"。

## 二、核心方法

### 冻结的语义粒子编解码器

对每一帧，冻结的 SAM3-DLP 编码器接收 RGB 与 VRS 部件掩码，提取 **K=3 个语义粒子**（整机、手臂、夹爪）加一个空间背景潜变量。每个粒子的状态是 `[位置 p, 尺度 s, 深度 d, 存在性 q, 外观 a]`——显式几何构成预测目标，外观与背景只服务渲染。冻结编解码器是为了防止表征漂移成"方便的像素复制解"。

粒子是无序提议，需要时序对应：相邻帧之间用"尺度归一化位置距离 + 外观余弦距离"构造代价矩阵，再做 **Hungarian 匹配**对齐身份；离线缓存里固定语义部件 ID 已确定排列，直接跳过匹配。

### 文本辅助的粒子动力学

动力学输入拼接几何、一阶速度（Δp、Δs）、深度、存在性以及可学习的槽/时间嵌入。一个**因果时空 Transformer**（宽度 64、两层、四头，仅 0.28M 参数）在槽内做时序推理、在机器人部件间做交互，自回归地预测残差更新：

```
ŷ(t+1) = ŷ(t) + f_θ(ŷ(1:t), e_c)
```

冻结的 OpenCLIP ConvNeXt-L/320 文本塔产出指令嵌入 e_c，在每个 Transformer 块经 **FiLM 调制**注入（`h̃ = (1+γ(e_c))⊙LN(h) + β(e_c)`），且 FiLM 投影**零初始化**——优化从不带条件的动力学起步，而不是从一个随机扰动模型开始。训练损失同时监督一步转移与自回归 rollout。

### 因果运动–外观解码

冻结的粒子渲染器把预测粒子 + 上下文背景映射为结构化的 RGB 提议与 alpha 图——部件动对了，但缺高频细节。并行地，稠密编码器只从**最后一帧上下文**提取外观特征，条件残差先验根据上下文外观 + 粒子运动预测未来细节。残差精修器合成候选帧后，一个**学习到的置信掩码** m_t ∈ [0,1] 逐像素地在"生成"与"persistence（复制末帧）"之间混合：

```
x̂_t = m_t ⊙ g_t + (1 − m_t) ⊙ x_C
```

掩码只使用推理期可得量（预测 alpha 运动、候选分歧等）。训练时外观损失为 L1 + SSIM + LPIPS，并对运动区域加权；未来 RGB、掩码、残差码都只是目标，绝不进入推理输入。

### VRS 基准

团队自建 Video Robot Segmentation（VRS）基准：从 DROID 风格真实机器人轨迹构建 **2,746 段标注片段**（2,526/106/105 划分训练/验证/测试），补齐整机/手臂/夹爪掩码与自然语言指令，128×128 分辨率、观察 4 帧预测 5 帧，覆盖 Franka、WidowX、Mobile ALOHA、Google Robot、Fanuc、Sawyer、Stretch、UR5、Kuka IIWA、xArm 十种平台。

## 三、实验结果

**运动学上：粒子动力学可靠地赢过 persistence。** 轨迹误差相对 persistence 降低 **21.0%**；诊断实验显示，残差化的 box 坐标与原始外观特征会引入捷径，去掉它们并把步长拉到 stride-3 后，误差降幅才从低个位数升到 21.0%。

**图像质量上：残差交付是关键一环。** 原始粒子生成把运动区域 PSNR 提升 1.34 dB，但会扰动静态像素、拉低全局 SSIM；残差交付恢复静态保真度，全局 PSNR 再 +0.61 dB、SSIM +0.0044，同时保留大部分运动优势。三个交付掩码种子的离散度很小（PSNR 0.009 dB、SSIM 0.0002），说明交付模块本身稳健。最终未来帧 PSNR/SSIM 从 persistence 的 19.97/0.796 提到 **20.573±0.009 / 0.8004±0.0002**。

**诚实的失败清单：**
- **LPIPS 仍未超过 persistence**（0.1304 vs 0.122）——感知质量上，复制末帧依然是强劲对手；
- **语言 grounding 很弱**：正确 vs 打乱文本只带来 2.8–3.1% 的轨迹误差变化，远低于 10% 的目标，因此论文自称 text-assisted 而非 instruction-controlled；
- **跨机器人泛化不一致**：Franka +21.1%、WidowX +19.0%、UR5 +18.4%，但 Mobile ALOHA −16.1%、Google Robot −5.2%；非 Franka 聚合 +10.0%，严格的留一机器人实验仍打不过 persistence；
- **oracle 差距 1.55 dB**：候选质量不是唯一瓶颈，"在哪里合成"的校准依然不完美；
- 对 FitVid、SlotFormer、DDLP、TextOCVP、LPWM 等公开基线，论文坚持"没有在同一 VRS 划分上重训就不移植数字"，把它们列入复现队列——这种不混用不可比数字的纪律本身就很罕见。

**消融要点：** 32×32×4 的稠密残差码把重建 PSNR 提高 7.01 dB（印证双流必要性）；codec box 残差有 34.4% 的速度符号翻转率（几何状态优于 box 残差）；固定粒子 alpha +0.23 dB，学习因果掩码再 +0.41 dB 并把 SSIM 拉回 persistence 之上，代价是 0.36 dB 运动 PSNR。

## 四、技术启示与发展方向

第一，**"复制最后一帧"基线是一面照妖镜**。任何在静态占比高的场景里做预测的任务，都必须同时报告全局指标与运动区域指标，否则进步可能只是幻觉。AcrossVAM1.0 把 motion-region PSNR 单独拎出来，正是为了不让模型躲在静态像素后面。

第二，**物体中心 + 冻结感知的组合值得借鉴**。用冻结的 SAM/CLIP 提供语义结构、只训练一个极小动力学核，既获得可解释的部件级运动接口（哪里动错了可以直接检查粒子），又把可训练成本压到 9.5M 参数（动力学核仅 0.28M）。"轻量"指的是学习核心，而非总部署内存——论文如实指出了冻结 OpenCLIP 塔依然很大的事实。

第三，**语言条件 ≠ 语言控制**。FiLM 调制确实捕获了真实语义信号（打乱文本有正向差距，kinematic 伪文本与随机标签几乎为零差距），但效应太小。论文给出一个务实解释：自动生成字幕的动词召回率低，更大的语言编码器并不会自动带来更大的因果效应。未来需要**反事实指令对**（同一场景、不同指令）来真正训练 grounded 动力学。

第四，**不确定性感知的混合是下一步主战场**。像素级 oracle 显示交付校准还留有 1.55 dB 的空间——学会"哪里该生成、哪里该保守"比生成本身更值钱。发展方向包括不确定性感知混合、用提议时分割取代掩码监督、以及从视频指标走向闭环控制评估。

## 五、总结

AcrossVAM1.0 把一个看似"图像生成"的问题重新定义成了"语义粒子动力学 + 因果外观合成"：0.28M 参数的动力学核让运动可诊断，冻结渲染器与上下文外观流负责保真，学习掩码管理生成与保守的边界。轨迹误差 −21%、运动区域 PSNR +1.34 dB 是实打实的收益；而 LPIPS 落后、语言 grounding 薄弱、跨机器人不稳，则是同样实打实的边界。**"低维粒子接口 + 分模块职责 + 诚实的失败报告"**——这种不把失败藏在聚合指标后面的做法，或许比单点提升更值得行业学习。
