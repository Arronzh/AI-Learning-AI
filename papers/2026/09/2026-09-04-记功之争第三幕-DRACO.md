# 记功之争第三幕：DRACO 让细则动态生长、让优势按步落账——没有验证器，照样反超"看得见真值"的训练

📌 **核心摘要**：给多轮工具型 Agent 做强化学习，最省事的奖励是"终点验证器"——单元测试过了给 1 分。但绝大多数真实 Agent 场景（客服、开放式研究）根本没有程序化验证器，构造一个往往和完成任务一样难。IBM Research 与 CMU 的研究者（arXiv:2609.04094）在**完全看不到任务真值**（outcome-blind）的训练 regime 里提出 DRACO：让裁判（judge）为每条轨迹**动态生成评分细则**（rubric），再把这些细则的判定结果**按"被引用的步骤"重新分配 GRPO 的组内优势**——闭式重排、零训练模块、总推力严格守恒。结果：在 AppWorld 上把 Qwen3.6-27B 从 69.4 抬到 85.3 TGC（+15.9），**反超用真值单元测试训练的 vanilla GRPO 5.3 分**；零样本迁移到 τ-bench 也赢过真值奖励训练；换成策略自己当裁判，成本砍掉 5.1 倍，τ-bench 成绩反而全场最高。结合前两天的 CANOPY 与 Coverage-Not-Targeting，这场关于"功劳记给谁"的连续剧迎来第三幕：**定位不是没救，前提是信号要细到能指名道姓——而"细则"必须动态生长，否则记功组件在训练后半程九成时间处于关机状态**。

## 一、研究背景与动机

RLVR（基于可验证奖励的强化学习）过去两年的成功叙事建立在同一个前提上：任务有一个程序化验证器——数学题有标准答案、代码有单元测试、Agent 有任务通过检查。验证器给出难以欺骗的终端奖励，于是可以绕开学出来的奖励模型。

但这个前提在真实世界里大面积失效。客服、开放式研究、办公自动化这类长程 Agent 域，**没有程序化 oracle**；硬造一个，难度常常等于重做任务本身。于是研究者转向"过程准则"：用多准则细则（rubric）打分。可细则通常**每条轨迹只打一次分**，一个标量要跨过几十步工具调用去指导策略——信号太稀。

这引出两个耦合问题：**没有真值，该奖励什么？**以及**奖励到了，功劳该记在哪几步头上？**后者正是本周 arXiv 的连续剧主线：

- **第一幕（9/2，CANOPY，2609.01245）**：在 AppWorld 上论证结果奖励 RL 在小模型上"见顶"是训练方式的假象，不必加过程信息；
- **第二幕（9/3，Coverage-Not-Targeting，2609.02417）**：定义"验证器信息密度" V_d=k/C，测出终端验证器统治的世界 V_d≈0.15，远低于定位开始奏效的相变点 0.8——结论是**均匀摊平 > 定点投放 ≈ 随机投放**，"定位是二阶的"；
- **今天这篇 DRACO**：干脆把验证器整个拿掉，在 outcome-blind 的世界里问——如果信号只能来自"裁判的细则判定"，功劳怎么记？它的回答是：**细则要动态生成（贴着每条轨迹长），优势要按步落账（裁判引用了哪几步，功劳就倾向哪几步）**，并且全程守恒、保号、可退化。这等于给"定位派"递了一份答辩状，也给昨天的相变图补上了缺失的一格：V_d 不是环境的宿命，**信号细度是可以花钱（裁判引用）买来的**。

DRACO 的作者还点出一个方法论站位：此前几乎所有逐步信用分配方法（SALT、RUDDER 谱系、进度估计器）都把信号锚在真值结果上；而"验证视界"（verification horizon）框架认为，当验证比生成更难时，**任务自适应覆盖**与**忠实的逐步归因**必须 jointly 成立——DRACO 的两个组件正好一一对应。

## 二、核心方法

### GRPO 的"均匀病"

GRPO 对每个任务采样 G 条轨迹，把奖励在组内标准化成优势 A_i=(R_i−mean)/std，然后**同一个 A_i 乘到这条轨迹的每一个 token 上**。于是"查订单"和"下换货单"拿到一模一样的梯度推力——这就是要治的病。DRACO 的改动有两处：换掉 R_i 的来源（细则裁判，而非验证器），换掉 A_i 的用法（按步优势 a_j，而非均匀 A_i）。

### 组件一：动态逐轨迹细则

不用一套写死的细则覆盖整个任务分布，而是**每个任务、每条轨迹现场长细则**，分三阶段：

1. **生成**：裁判先只凭任务指令提出一组准则；每条 rollout 完成后，再根据这条轨迹暴露的子目标与失败方式**追加准则**；
2. **合并去重**：组内 G 条轨迹的提议合并成一套共享准则集 ℛ={c₁,…,c_K}，并要求准则满足 MECE（互斥且完备）——因为奖励是比率，两条重叠准则会把一次错误算两遍；
3. **判别式丢弃（discriminative dropout）**：**只有组内至少一人没通过的准则才保留**。全组都过的准则在组归一化后对优势毫无贡献，留着只会稀释信号。

随后冻结裁判对每条轨迹逐准则打分：pass / fail / not applicable（故意粗粒度），并附上理由和**责任步骤引用**。奖励是 R_i=(p_i−f_i)/(p_i+f_i)，按实际投出的票归一——没被触发的准则不计入分母，不同轨迹之间依然可比。全程没有任何任务成功项或标准答案项，**outcome-blind 是构造性保证**。

### 组件二：细则条件的按步记功（核心）

裁判打分时**引用哪些步骤为该准则的判定负责**，这正是 DRACO 的记功依据。设 p_j、f_j 为引用步骤 j 的通过/失败准则数，步骤质量 Q_j=p_j/(p_j+f_j)（未被任何准则引用的步骤继承被引用步骤的均值 Q̄）。然后做**保号加权**：

- 轨迹是"赢家"（A_i≥0）：权重 w_j=Q_j——强化好的步骤；
- 轨迹是"输家"（A_i<0）：权重 w_j=1−Q_j——抑制坏的步骤。

按步优势为 a_j = A_i·N·w_j/(n_j·Σw_k)，其中 n_j 是该步 token 数，N 是步内 token 总数（步骤间隙的胶水 token 记 0 分、不进 N）。这个闭式重排有七条可证明的不变量，最要紧的是三条：

- **总推力守恒（精确）**：Σ n_j·a_j = A_i·N，与 baseline GRPO 施加在同一批 token 上的总推力**分毫不差**——重排只移动功劳，不放大不缩小；
- **长度无关（精确）**：一步的总影响力只由裁判评级决定，**注水写长不能买到更多强化**（1/n_j 只负责把固定份额摊到自己 token 上）；
- **符号保持（精确）**：任何 a_j 都不会与 A_i 异号，裁判再错也不会把"该强化"扭成"该抑制"。

还有一个优雅的退化设计：当裁判的判定**全体一致**（全过或全挂）或无人被引用时，所有权重相等，公式自动坍缩回 baseline GRPO——记功组件"惰性关机"而非添乱。论文给了一个真实 rollout 的 traced 例子：7 步轨迹、5 条准则命中、R_i=−0.2 却是"赢家"（因为组内其他人更差——**赢家/输家由组内相对位置决定，与任务成败无关**，奖励根本看不到成败）；被引用的好步骤（第 1、2 步，Q=1.0）拿到的总推力是最差步骤（第 4、6 步，Q=0.333）的 **3 倍**。

## 三、实验结果

主实验在 AppWorld（90 个训练任务）上做，Qwen3.6-27B + LoRA + GRPO，组大小 G=6，8×H100 训 100 步；τ-bench Banking 是**零样本迁移**（训练从未见过）。裁判用冻结的 GPT-5.4，全部报告 3 次独立运行的一致性指标。

**对基座与对真值训练的双重胜利**：AppWorld TN 上 TGC 69.4→85.3（+15.9）、SGC 41.1→70.6（**+29.5**）；挑战集 TC 的 TGC 49.7→61.5。对照臂"outcome reward"（同一基座、同一超参，用 AppWorld 单元测试真值做 vanilla GRPO）只有 80.0/59.3——**DRACO 全程没碰真值，却反超它 +5.3 TGC / +11.3 SGC**，且优势随一致性要求放大：p³ 时拉到 +9.5/+13.7。随机奖励的 sanity check 只到 74.0/50.0，排除了"随便给信号都能涨"的读法。弱基座 Qwen2.5-32B 增益更大（TN TGC 35.7→62.9，+27.2），逼近用了真值的逐步记功基线 SALT（66.2/47.9）。零样本 τ-bench：SR 15.8→20.4（+4.6），高于真值奖励训练的 17.6。

**关键消融：记功需要"会生长的细则"**。四臂对比（静态细则±按步记功 × 动态细则±按步记功）显示：在动态细则上加按步记功值 +3.2 TGC/+5.7 SGC，两个组件合起来比静态细则独走多 +4.2/+10.7（p³ 时扩大到 +8.1/+14.3），而任一组件单独上几乎不动（+0.8/+1.0）。TC 集上甚至出现**符号反转**：静态细则 + 按步记功在 p³ 时**倒亏 3.7**，同一记功组件换到动态细则上就变成 +1.4——机制预测得很准：**记功需要细则具体到能指名道姓某几步**，为整个任务分布写的大而化之的准则，让归因器无功可归。量化证据在附录：静态细则上记功组件"惰性"（unanimous → 退化为 GRPO）的比例随训练从 23.6% 一路爬到 **91.9%**，全程均值 76.4%；DRACO 只从 29.7% 爬到 56.5%（均值 48.1%）。静态细则的通过率 25 步内就饱和到 90 多分然后躺平（均值 94.8%/95.8%），动态细则一直停在 66.9%/74.2% 继续产生判别力——**因为它每步都在长出新准则**。6,245 条去重准则里 84.4% 只为一个任务写过（如 Spotify 任务："只关注自己播放列表里的 indie 歌曲作者"、"关注前去重"），跨任务的只有 18 条，且全被静态集覆盖——动态细则 = 静态准则 + 任务特有的"误读方式清单"。

**自判省钱且更准**：用策略模型自己当裁判（thinking 全开 + 每条准则投 3 票、全票才算过），100 步训练裁判成本从 $1,607 降到 $316（**5.1×**）；AppWorld TN 81.1/62.7 仍压过真值训练，τ-bench SR 21.1 是**全场最高**（比基座 +5.3，比 frontier 裁判的 DRACO 还高）。回放对照显示自判与 frontier 裁判在 60,689 条准则判定上 89.4% 一致，分歧是**宽松**而非噪声：frontier 判挂的准则它放过了 30.4%，frontier 判过的它只挂 1.3%——三票全票制正是冲着这个主导错误去的。

**效率与规模故事**：DRACO 在 TN 上平均回合数 18.7→14.7（TC 22.9→20.7），是"更少步数解更多题"而非买长度；评测成本 $10.77→$8.27 且分数更高。把训练后的 27B 放进 frontier 全家福：距 claude-sonnet-4-6（89.9）只差 4.6 TGC、距 claude-opus-4-7（93.5）差 8.2，成本分别是它们的 44% 和 25%；**反超 DeepSeek-V4-Flash（284B）14.5 分、gpt-oss-120b 41.3 分**——只有 1T 的 Kimi-K2.7-Code 比它又便宜又强。全程只用 outcome-blind 奖励、100 步训练。

## 四、技术启示与发展方向

第一，**这周的三幕剧可以收束成一个坐标系**。CANOPY 说"结果奖励够用"，Coverage-Not-Targeting 说"终端验证器下均匀摊平最优、定位是二阶"，DRACO 说"没有验证器时，把信号做成动态细则 + 按步引用，定位又能打赢均匀摊平（+3.2/+5.7）"。三者并不矛盾：昨天论文自己的预言是"学到式/神谕式过程奖励，本质是在为填补可观测性缺口付费"——DRACO 就是这份账单的实证：**裁判的逐步引用把可见性从'写操作尖峰'铺到了全部步骤（包括读与探索），等效把 V_d 从 0.15 抬过了相变点**；而静态细则 + 记功在 TC 上的 −3.7，恰好复现了昨天"在尖峰里做文章"的亏损。给 Agent 记功的问题，从"功劳落在哪"变成了"**谁能看见功劳、看得多细**"。

第二，**DRACO 给了记功方法两条可复用的工程纪律**：(a) 重排必须守恒、保号、可退化——总推力不变意味着任何收益都来自"放对位置"而非"偷偷加量"，unanimous 退化保证信号不足时自动回到 baseline；(b) **"惰性份额"（inert share）是一个该被广泛报告的诚实度指标**——76.4% vs 48.1% 直接说明静态细则下记功组件后半程九成时间在睡觉，任何逐步方法都该自报这个数。同日 arXiv 的 Spurious Advantage Hidden in GRPO（2609.04063）是这场解剖的另一个切面：它拆的是 GRPO 优势的**幅度组成**——有界答案集、搜索预算类任务里，靠猜命中答案的 rollout 同样拿到高幅度（spurious advantage），于是用 stop-gradient 按类重缩放恢复零均值。一个拆空间分布、一个拆幅度组成，**GRPO 的组内统计量正在被全面外科手术**。

第三，**对 RLVR 叙事的一记提醒**：DRACO 证明"无验证器也能练出验证器级策略"，但代价是**目标由裁判定义**。裁判系统性偏差会无验证器兜底地遗传给策略（作者在伦理声明里承认这是双刃剑：目标可审计是安全属性，偏差无兜底是风险）；细则的"有效性"没有独立信号可校验，需要人类评分者（留给未来工作）；归因质量只经端任务性能间接验证——**记对了步骤与记错了步骤都可能涨分，论文无法区分**。自判的宽松偏差（30.4% 放水率）也提醒：省钱的自判需要机制性的防宽松设计（三票全票制），而不是指望模型自律。

第四，**边界同样要划清**：判别式丢弃使存活的准则集随采样组变动，训练期方差未被刻画；单冻结裁判、无与人类评分者的机会校正一致性；100 步/20 epochs 的小规模训练，scaling 行为未知；τ-bench 上回合数不降反升（27.7→27.9），说明域外收益来自"更少放弃"而非"更快完成"。

## 五、总结

"没有验证器，功劳怎么记？"DRACO 的答案是两步：**让细则贴着轨迹长**（动态逐轨迹生成 + 判别式丢弃，保证准则永远有人会挂、永远有判别力），**让优势按引用落账**（裁判引用了哪几步，功劳就倾向哪几步，闭式重排、守恒保号、全员一致时自动退化为 GRPO）。它在 AppWorld 上反超了看得见真值的训练，把 27B 模型推到距 claude-sonnet-4-6 一步之遥的位置，还附赠一个 5.1 倍省钱、成绩更高的自判方案。放到本周的连续剧里，它的真正贡献是补全了 Coverage-Not-Targeting 那张相变图的横轴注释：**V_d 不是环境的宿命，而是信号细度的函数——细则的动态性，决定了记功组件是"指名道姓"还是"无从下手"**。给 Agent 记功之前，除了问"验证器照亮了因果链的几分之几"，现在还要多问一句：**这份照亮，是买来的，还是长出来的？**
