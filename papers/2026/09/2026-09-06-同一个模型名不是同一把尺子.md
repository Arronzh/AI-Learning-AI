# 「同一个模型名，不是同一把尺子」：5.3 万次预注册审计两连败——LLM 评委工程满分，测量不及格

📌 **核心摘要**：LLM-as-a-Judge 早已不只是"打榜玩具"——它给训练数据把关、给生成结果打分、驱动整个榜单与 RL 训练信号。这背后藏着一个极少被说破的假设：**同一请求发给同一个模型名，明天读出来应该一样**。两位英国研究者（arXiv:2609.04198）本要研究"能否从推理轨迹前缀读出解题进度"，按计量学规矩先给观测器做仪器校验——结果两轮预注册战役全部**死在仪器层**：5.3 万次审计请求里，同窗口重复排序一致性 Spearman 中位数 **0.400**（冻结门槛 0.90），次日字节级重放精确一致率 **78/100 = 0.78**（门槛 0.99）；而工程层完美无瑕——3,312/3,312 次请求全部送达、零重试、请求体 SHA-256 100% 一致、可见元数据全恒定。更狠的是三条"逃生路线"全部被堵死：换指标（同一批漂移能读出 0.78 / 0.95 / 0.986 三个故事）、加采样（模拟到 74.8 万次调用，通过率仍钉在 0/500）、换平台（四家供应商共享 0.74–0.88 的稳定性"地板"，连 fingerprint 都救不了）。作者把失败转化为一份审计：三个失效机制、一座 L0–L2 快照身份阶梯、八条设计规则和一张报告清单。**核心就一句：在共享端点上，模型名不是冻结的仪器；预注册评测必须先测量自己的仪器，再冻结任何门槛。**

## 一、研究背景与动机

**模型已经坐在自己领域的测量回路里。** 从 MT-Bench 与 Chatbot Arena 开始，LLM 当评委（judge）就成了惯例：给候选回复排序、给推理轨迹打分、为训练数据把关、驱动排行榜。作者指出，把模型当仪器使用，隐含着一个基本到几乎没人明说的假设——**稳定性**：同一个请求、同一个模型名，今天与明天应该读出同样的结果；一条冻结的评测标准，测的应该是被研究对象，而不是测量装置自身忽明忽暗的状态。

**共享端点让这个假设不再无辜。** 服务端把并发请求打包成批；常见推理内核并非"批大小不变"（batch-invariant）——同一份权重，批大小不同、相邻请求不同，greedy decoding 也会分叉；部署还会在固定模型名背后悄悄更换。而这一切在响应元数据里都看不见。黑盒研究能观测到不稳定，却无法归因。

**作者不是选了这个题，是撞上的。** 他们的预注册研究计划（测量"可见推理前缀上的正确性概率路径"）立了规矩：任何科学结论之前，观测器必须先通过一组仪器校验门槛。结果两轮战役都没走到科学结论——全部终结在仪器层。他们没有把失败藏起来，而是把失败本身做成了一份审计，并把它上升到方法论：分析化学与工业质检早有的"仪器优先"纪律（先测噪声底与间隔分布、再跑操作特性曲线、最后才冻结阈值），在 LLM 评测里从未被执行过——他们自己就坐在这个缺口的正中央。

## 二、核心方法

### 2.1 测量对象：一个"干净得过分"的实验台

被测系统是**确定性算术任务上的双模型流水线**：生成器为每个任务写 4 个候选解（4–8 步显式推理轨迹，以精确有理数答案结尾）；每个任务有唯一标准答案，全研究唯一的监督标签是"最终答案是否正确"，由有理数精确比较判定——**绝不由模型判定**。外部观测器看到任务 + 截断到 25%/50%/75%/100% 的轨迹前缀，输出伯努利判断或一个完整排序。观测器跑在 temperature 0.0、关闭思考、top_logprobs 5 的配置上，计划 3,312 次调用、硬上限 3,632。

### 2.2 两代仪器、三种读数协议

- **D1（第一代）**：单映射双标签 logprob——只能输出 A/B 两个精确标签，在答案 token 位读 logprob 比值；
- **D1-S v2.3a（第一代升级）**：双映射邻近对——每个测量点问两遍，标签与含义的映射在两次之间反转，对称化取平均，并附带映射偏差诊断 b_map；
- **I0-R judge（第二代）**：结构化全排序输出——一个 JSON，把 10 个候选别名排成一个精确排列。

每一代都修复了上一代被诊断出的毛病，然后各自死在**另一个**预注册门槛上。

### 2.3 预注册纪律与审计链

所有设计常数在执行前封进哈希固定的配置快照；预算由"先预留、再联网"的计数器硬顶；每次请求前后向 append-only JSONL 写入请求体与原始响应的 SHA-256、UTC 时间戳、逐字元数据；跑完目录不可变、manifest 锁定全部哈希，中断恢复只允许"严格前缀"续跑。两道决定叙事的门：

- **Gate I-3S（仪器稳定性）**：同窗口内重复排序，任务内 Spearman 中位数 **≥ 0.90**；
- **Gate I-5R（次日重放）**：强制 24 小时后，100 个请求以**字节相同**的请求体重放，全排列精确一致率 **≥ 0.99**。

另有三个前瞻性补充实验（全部预注册、独立归档、绝不与历史数据混合）：A-S1 同日/跨日方差分解、A-S2 跨平台电池、A-S3 构造误差电池，外加一个自托管对照臂。

## 三、实验结果

### 3.1 两张并排的"表里不一"

| 检查项 | I0-S（同窗口重复） | I0-R F2（次日重放） |
|---|---|---|
| 计划调用 / 实际送达 | 3,312 / 3,312 | 100 / 100 |
| 重试 / 传输错误 / 拒答 | 0 / 0 / 0 | 0 / 0 / 0 |
| 请求体与冻结计划一致 | 构造保证 | SHA-256 100/100 |
| 响应 model 字段 / fingerprint / finish reason | 全程恒定 | 100/100 相同（fingerprint 均为 null）|
| 标量读数重复稳定性 | 中位 \|Δr_sym\| = 0.00671（阈值 ≤0.03，4.5× 裕量通过）| — |
| **预注册主裁决** | 排序 Spearman 中位数 **0.400 < 0.90 → 失败** | 全排列一致 **78/100 = 0.78 < 0.99 → 失败** |

每一列从上往下读：凡是执行审计能查的（送达率、schema 合法率、字节一致性、元数据恒定）全部满分；预注册的科学门槛随后失败，而且不是擦边失败——同一个仪器，标量读数重复性好到 0.0067，排序却塌缩到 0.400。"标量稳定、排序塌缩"不是悖论，是算术。失败也很"广谱"：31 个有效任务组里 29 个低于门槛，每个前缀进度层的读数中位数都低于 0.90；22 个漂移的重放记录横跨 16/25 个任务，一个也没被删、没被重跑、没被多数投票抹掉。

### 3.2 三个失效模式，同一根根因结构

- **M1 标签—语义映射偏差（第一代）**：把"哪个标签代表正确"翻转，排序**倾向于整体反转**——反演映射重复的任务内 Spearman 中位数是 **−0.632**（阈值 0.90）。偏差诊断 b_map 中位数 0.25 logits、95 分位 1.39 logits，幅度与信号动态范围同级；更糟的是它与被测量交互：正确候选 +0.531、错误候选 −0.250，正反两臂的排序只一致到 Spearman 0.211。单映射协议把"标签方向偏好"与"正确性"混进了同一个 measurand。
- **M2 近简并 measurand（核心机制）**：噪声底约 10⁻³–10⁻²（重复增量中位数 0.0067、p95 0.080），而任务内候选读数跨度中位数仅 0.0114，**相邻候选最小间隔中位数 3.04×10⁻¹⁰**——间隔比噪声底低约 7 个数量级；32 组里 12 组原始读数完全平局。原因在上游：候选准确率 0.781，只有 16.25% 的任务含"正确/错误混合"候选——**约 84% 的组根本没有可排序的东西**。按前缀进度分层更漂亮：Spearman 中位数 0.000（25% 可见）/ 0.769（50%）/ 0.500（75%）/ 0.000（100%）——排序信息只存在于轨迹中段：前段尚未分化，末段正确答案对观测器可见后读数饱和。
- **M3 字节相同，输出漂移（第二代）**：100 个字节级相同的请求，24 小时后只有 78 个精确复现原排序。漂移是**局部的**：Kendall 距离谱里 78 个精确、11 个距离 1、11 个散布在 2–11——大多是相邻对换，正是"近简并子集 + 小数值扰动"在全排列读数下的产物。A-S1 补充实验把"隔夜漂移"的直觉**证伪**了：同日重放中位数 0.805 vs 跨日 0.800（差 0.005，落在等价带内），历史值 0.78 就躺在同日分布（0.73–0.83）内部——**24 小时什么也没加，这是瞬时非确定性**。再复刻五天（2,500 次调用）：同日 0.815 vs 跨日 0.810，结论不变；倒是某一天的"地板"自己低了下去（0.78），且事前没有任何可记录信号能预告它。

### 3.3 三条逃生路线，全部堵死

- **换指标？** 同一批 22 个漂移，三种计分读出三个故事：全排列一致 0.78（决定性失败）、top-1 95/100（"几乎稳定"）、两两序 4436/4500 ≈ 0.986（"几乎完美稳定"）。全排列读数是指数放大器（45 个候选对，一个相邻对换就废掉整条记录）。**门槛若在数据之后选，三种读数里两种都会支持"几乎稳定"的叙事**——他们的协议事先禁止了这种替换，论文也只把宽松读数当敏感性说明、从不当作通过裁决。
- **加采样？** 模拟把每个测量点换成 M 次独立采样（Jeffreys 平滑），M 从 8 爬到 500——最高 74.8 万次调用，标准误改善约 7 倍，Spearman 中位数从 0.33 爬到 0.57，**门槛通过率纹丝不动地钉在 0/500**（q95 最高 0.80 < 0.90）。算术原因：平均只能缩小分母（噪声），分子（近零的间隔）是样本的属性；对完全平局的那 1/3 组，任何有限采样都只是掷硬币。而且 M=8 那一行（11,968 次调用）就已经是整场 I0-S 战役调用量的 3.6 倍。
- **换平台 / 等一等？** 四家供应商（deepseek-v4-flash、mistral-small-2603、gpt-4.1、qwen3.7-plus）4,000 次调用共享同一"地板"：同日一致率中位数 0.74–0.88，平台类检验（max < 0.95）触发；所有供应商的跨日行为都等于同日行为。fingerprint 字段以三种形态失效：缺失（mistral/qwen）、抖动（openai 一天 19 个值；同 fingerprint 对 0.854，并不比不同 fingerprint 对的 0.884 好）、**稳定但不够**（deepseek 恒定 fingerprint 下仍是 0.879）。自托管（vLLM 0.11.0 batch-invariant 模式 + 4090 级显卡 + 开源权重）只在服务器安静时有效：串行 0.9872；8 路并发背景流一来，逐对分歧率从 1.28% 涨到 10.75%（**8.4 倍**），直接回到共享端点量级——批处理压力本身就足以复现共享端点级的不稳定。

**A-S3 还回答了"这把尺子能不能按大小量"**：构造 5 类人为错误、误差 ε 事先已知的候选（340 次调用、3,060 个判断），正确候选在每一档都能胜出（Wilson 下界 > 0.5）——但按错误类型对比，5 类里 4 类的分离度**不随 ε 上升**，某类最大误差单元（off-by-one，ε≥1）只有 0.333、低于随机。**它分辨的是错误类型与表面形式，不是错误大小**——一把能分辨对错、却不能按误差大小排序的尺子，自然无法为近简并的候选排序背书。

## 四、技术启示与发展方向

三条根因清晰可辨：measurand 近零间隔 × 平台不承诺确定性 × 流程（门槛冻结在从未试测过的量上）。论文由此给出八条设计规则，最值得带走的几条：

1. **先锁快照，再信稳定性门**。报告任何 LLM 评测都应附一个"快照身份级别"元数据：L0 只有模型名（能声明的只有"该窗口内可见行为"）；L1 锁定供应商快照/部署 ID（权重固定了，可观察行为仍不字节稳定——供应商文档自己都承认固定 ID 不固定行为）；L2 自托管权重哈希 + batch-invariant 内核 + 锁定硬件（安静时远超共享端点地板，但**精确性靠验证、不靠旗帜**）。多数谨慎从业者的舒适区在 L1——而它恰恰不够。
2. **门槛永不冻结在没测过的量上**：pilot（测噪声底与间隔分布）→ simulate（跑操作特性曲线）→ freeze 三步流水线。教训的价格标签很讽刺：最终暴露 I-5R 门槛不可达的那次 pilot **只花了 3 元人民币**；而约 2% 调用量（约一千次请求）的事前 pilot，本可提前宣判两道门都不可达——省下的是 52,988 次审计请求与两轮战役。
3. **排序门只统计"原则上可分辨"的对**（间隔大于由噪声底决定的分辨界限 δ），平局与近简并对按预注册规则事先排除；"大部分样本低于检测限"要作为样本属性报告，而不是仪器故障。
4. **用连续读数 + 等价带代替精确匹配门**。若下游确实消费全排序，就把聚合（Borda 或中位秩）而不是单次调用作为测量对象：按他们实测谱模拟，k=3 时两组独立聚合电池精确一致率 0.94，k=5 达 0.98（容一换位一致率 0.999），k=9 达 0.999——"单次调用不可达的全排列门"，在 5–9 次调用的聚合下变得可达成，且成本事前可知。
5. **让 measurand 存在**：构造候选集时注入可控误差、把难度调到准确率 0.5 附近、混合正确率设下限——他们自己跑过的 0.781/0.163 本应在设计期就被判不合格。
6. **报告按固定清单**（附录 D，20+ 项；"测不了就写 unmeasured"）；解析不了的 guard **必须 fail closed**——他们的工具链自己就 fail-open 过两次（一个 SDK 参数从未进入请求体、两个执行进程并发写同一目录），都被抓住、披露、重新冻结，而不是静默修补。

把审计本身再往外推一层，还会撞上更多"边界的形状"：文档不是审计源（实测与文档矛盾四次——号称被静默忽略的 seed 参数实际被 HTTP 400/422 拒绝、文档标注的补全上限被 reasoning 模式默认值超出 39 倍、号称会填充的字段返回 null）；有平台在协议层面禁止确定性（temperature=0 直接被拒，只接受 0.6）；限流可见性是双峰的（一半平台不返回任何限流头）；无日期的滚动别名会在审计脚下移动。**这意味着：一次复现失败，若无快照级别与响应侧元数据记录，连"仪器漂了还是平台漂了"都无法归类。**

**给整个领域的提醒**：当 judge 走进 RLVR 奖励、训练数据把关与榜单，它就不再是"参考意见"，而是**测量仪器**。这篇负结果之所以有分量，不是因为它发现了新现象（评委不一致、内核非确定性都是已知工程常识），而是因为它把"一致性数字"从描述性报告升级为**有权力终止整条研究线的预注册门槛**，并用字节级审计链证明：工程层满分不蕴含测量层可靠——"所有测试通过、所有哈希一致"只是必要条件。对读者最实用的拷问是：下次看到一张评测表，先问两句——**它的快照身份是 L0/L1/L2 哪一级？冻结门槛之前，仪器本身被测量过吗？**

## 五、总结

这篇论文贡献的不是新评测方法、不是新基准，而是一场罕见的、证据卫生极高的预注册负结果：两代 LLM 评委仪器、5.3 万次审计请求，全部在"仪器校验"层阵亡，工程记录却完美无瑕。三个机制（标签映射偏差、近简并 measurand、共享端点的瞬时非确定性）被逐一拆开、归因（同日 vs 跨日、四平台、自托管对照、构造误差电池），再被写成可执行的纪律（L0–L2 阶梯、八条规则、报告清单）。作者把边界划得很清楚：一切结论都是共享服务基础设施上的**外部测量**，不涉及模型内部，也不构成对任何供应商的质量评估；真正可迁移的危险不是简并本身，而是**不知道自己正处在哪个 regime**。一句话收束全文：**在共享端点上，模型名不是冻结的仪器；预注册评测必须先把仪器量过一遍，再谈冻结门槛、再谈结论。**
