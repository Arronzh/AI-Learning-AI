# 「格式一个错都没有，答案却反了」：把 no/yes 背后的定义对调一下，1200 道工作流选择题当场翻掉 76.92%——AUROC 从 .94 跌到 .23（低于随机＝排序被倒置），而厂商引以为豪的"类型错误率 0%"纹丝不动

📌 **核心摘要**：有一类模型，卖的不是文本，而是**决定**：你给它一道有固定选项的选择题（每个选项＝一个**名字** ＋ 一段定义它的**评分标准/rubric**），它返回一个概率分布，并**保证结果一定落在你给的选项集合里**。厂商因此都爱标一句"**类型错误率 0%**"，并把它当成可靠性卖点。这篇论文（arXiv:2609.26758v1，作者 **Yu Sun（新加坡国立大学）、Junhao Xu（复旦大学）**）做了一件极其"坏"、又极其干净的事：**只交换"哪个名字绑哪段定义"，题目、状态、定义原文、选项名集合一个字节都不改**。结果是——把 `0/1` 换成 `no/yes` 之后，**1200 道工作流决策里 76.92% 的答案翻面**，AUROC 从 **.9376 直接掉到 .2315**（**低于随机，是排序被倒置，不是变糊涂**）；而同样的操作放在 `0/1`、`A/B` 这类**没有语义极性的名字**上，只动 **6.50% / 6.00%**。最扎心的一句总结：**这个模型读的是"选项的名字"，把绑在名字上的"定义"当成了装饰。** 而那条"类型错误率 0%"——从头到尾，**一个格式错都没出**。

## 一、研究背景与动机

**一类模型开始"卖决定"，而不是"卖文本"。** 现在很多生产系统里，模型的输出会被软件**直接消费**：不是写一段话让人去读，而是要**在一个预先定义好的选项集合里选一个**。接口收进一道带类型的题（一个问题、一个状态、一组选项），吐出一个概率分布，**且这个分布的概率质量严格落在给定选项上**——不合法的候选会在归一化之前被 mask 掉。厂商把这个性质说得很对：这是**结构性事实，不是测量出来的数字**。它甚至在文档里写"**schema 匹配是保证的，所以我们可以放心地在图里写上 0%**"，并把 self-consistent 与 type-safe 并列为同一件产物的属性。

**问题就藏在这句话里：这个 0% 是"推导"出来的，不是"观察"出来的。** 论文把它拆成一条引理（Lemma 1）：**返回的决定，对任意输入、任意权重、任意扰动，都一定是选项集合里的元素。** 证明就是一句话——`argmax` 只在选项集合里取，集合外根本不存在概率质量。而这条保证，**只约束了输出分布的"支撑集"，对"质量落在支撑集的哪一个元素上"一言不发。** 于是那个被当作可靠性数字展示的 0% 类型错误率，**其实只是读数层（read-out）的性质，关于模型本身的信息量为零。**

**于是论文提出了一个能把两件事干净分开的实验问题：** 概率质量到底落在"**定义与当前状态相符**"的那个选项上，还是落在"**名字读起来顺眼**"的那个选项上？答案是——**可以干净地分开，因为界面把每个选项渲染成"一个短名字 ＋ 定义它的评分标准"，而这两者都在输入里。** 只要把问题、状态、定义原文、选项集合**保持逐字节相同**，只交换"哪段定义坐在哪个名字后面"，就能分辨：**读定义的模型，两臂答案相同；读名字的模型，两臂答案相反。** 而这次重映射是**声明式、完整地写在同一个输入里的**——不是靠示例去暗示，也没有任何隐藏。

**"模型对 prompt 格式、选项标识符、标签词敏感"，学界早就知道。** 但作者明确划清了界限：他们**不主张**这个。**这篇的贡献是"在同一条选项通道里做一次受控解离"**：名字与定义各自独立变化、其余逐字节相同、且用无极性名字作**对照臂**，而实验对象是**那些承诺了类型安全保证的 checkpoint**——**结果不是"性能下降"，而是一次"反转"，一次任何阈值调整都救不回来的"低于随机"的排序。**

## 二、核心方法

### 2.1 先把"类型安全"覆盖了什么、没覆盖什么说清楚

一次带类型的提问（一个问题 q、一个状态 s、一组选项 O=(o₁,…,o_k)）被渲染成**一个编码器输入**；决策头给每个选项打一个分 z_i，再对所有选项做 `softmax(z/τ)`（可有学习到的温度 τ）。**非法候选在归一化前被移除**——在作者检查过的实现里，是把非法 logit 用 `masked_fill` 填成 −10⁴ 再 softmax。**Lemma 1** 因此成立，并有三个对评测要紧的推论：

- **（i）** 测出来的 0% 类型错误率**不携带任何关于模型的信息**——它是读数层的属性，厂商"解析地算出来"是对的；
- **（ii）** 这条保证对论文后面做的所有操作**完全不敏感**：**即使在模型四题错三题的条件下，它照样成立**；
- **（iii）** mask 会丢掉编码器本会放在"合法选项的同义词"上的概率质量——这本身就是已知的失真来源；而论文的干预**完全发生在幸存的那部分质量内部**。

### 2.2 三种读数几何（read-out）

论文审计了**两种编码器几何各一个公开 checkpoint，外加一个托管模型**：

- **Marker 读数**：ModernBERT-large ＋ 两层 transformer 头，每个选项贡献一个 `[MASK]` 标记 token，用它的上下文化嵌入打分，配一个"问题类型嵌入"和一个按（类型, k）的温度；
- **Span-mean 读数**：DeBERTa-v3-large，一个选项的分数 ＝ **它整段渲染文本（名字 ＋ 定义）所有 token 的均值**，单一标量温度；
- **Hosted 读数**：厂商自己的产品，通过 HTTP 调用，权重不可见；它的带类型提问把"名字"绑到"定义"上，返回一个支撑集恰好等于声明选项集的分布——**同一个"重归一化 softmax"接口，Lemma 1 照样适用，而且它正是那个被宣传"0% 类型错误率"的产物。**

**几何决定了"名字"能有多大分量**——这一点在第 4.6 节揭晓。

### 2.3 那件"坏"事：标签–定义对调（label–rubric swap）

**渲染**：界面把一个选项渲染成"名字: <定义>"，比如 `no: <rubric>` / `yes: <rubric>`。**定义**是任务自带的、用来界定这个谓词的文本；**名字**只是个标识符。两者对编码器**都可见**。

**工具（instrument）**：固定一个题目和一对选项名 (ℓ₀, ℓ₁)。**对齐臂**把每个名字绑到它"出厂"的定义；**对调臂**把两段定义在名字之间交换。**金标（gold）始终以"定义"为准**——于是**读定义的模型不受对调影响，读名字的模型则反转**。**除此之外，什么都不变**：同一问题、同一状态、同一段定义字符串、同一选项集合、**选项个数也相同**。

**对照臂**：把**完全相同的结构操作**重复一遍，但选项名换成**不带极性**的 `0/1` 和 `A/B`。它们把"词"从"通道"里孤立出来——**它们身上出现的任何变化，就是"当名字没有任何含义时，重新绑定所付出的代价"**。**下文所有效应都相对它们报成差值。**

**数据**：**1200 道二值工作流决策**，覆盖 **4 个谓词、每个 300 条**，每条都带数据集自带的**任务专属定义文本**，一段记录一道题，**金标正例率 .5750**。四个谓词是：**发票核对、代理轨迹分诊、安全告警分类、客服升级**。

**能力筛查（competence screen）**：一道**模型本来就判不了的题**上的翻转，不算证据。所以**对齐臂同时充当能力测量**：四个谓词的**平衡准确率 .7857–.9310、AUROC .9141–.9867**。**论文报告的每一个效应，都只在"这个头显然能判对"的决策上测量。**

**指标**：p≥.5 处的**平衡准确率**；**AUROC**（无阈值，因此能把"丢掉的排序信息"与"移动的操作点"分开）；**翻转率**（两臂间返回选项发生改变的比例，**根本不需要标签**）；以及**相对中性对照的差中差（DiD）**，95% 区间来自按记录聚类的 2000 次 bootstrap 重采样。**托管模型不是确定性的，所以对它还测了一个 test-retest floor**：把对齐臂逐字节地问两遍，用与翻转率完全一致的口径打分——**这就是"什么都不变时，它自己会变多少"的下限**。**另报类型错误率，而它在所有条件下都是 0%。**

## 三、实验结果

**七条发现共用同一把工具、同一批题目，而类型错误率在每一条里都是 0%。**

| false/true ✓ | .9012 | .4861 | .9623 | .5773 | 49.67% | +43.17 [40.25, 46.08] |

（Table 1：对调只交换"哪段定义绑到哪个名字"，金标以定义为准。✓ 表示这对名字是该头在训练中发布过的。）

### 结果一：选项"名字"压过了绑定给它的"定义"

**Table 1 就是全部结果。** 定义原文不动、金标随之不动，把 `no` 和 `yes` 背后的两段定义一交换：**76.92% 的答案翻了面**；而**完全相同的交换**放在 `0/1` 后只动 **6.50%**、放在 `A/B` 后只动 **6.00%**。**受控对比是 70.42 个百分点（95% CI [67.58, 73.08]）**（对 `0/1`），对 `A/B` 是 **70.92 pts（[68.16, 73.50]）**。**五对极性名字全部至少动了 39.25 pts；两对中性名字都停在个位数。** **这个头读的是名字，把绑在名字上的定义当成了装饰。**

**换成从业者更在意的单位，平衡准确率讲的是同一个故事**：`no/yes` 从 **.8719 掉到 .2839**——**从远高于随机，掉到远低于随机**；而 `0/1` 对照只从 **.8368 挪到 .8322**。

### 结果二：是"反转"，不是"犯糊涂"

**这个区分决定了部署层还能做点什么。** 一个**变糊涂**的模型会丢掉排序信息，AUROC 会朝 .5 塌；此时重校准或换阈值还能救回一部分决策。**但这里，AUROC 是从 .9376 掉到 .2315——远远低于随机。排序是完整的，只是指反了**：把对调臂的分数**倒过来读，AUROC 能恢复到 .77**。**这个头不是对谓词感到困惑，它是在"自信地回答另一道问题"——它的选项名所暗示的那道。**

**这也解释了为什么论文把 AUROC 和翻转率并列报、而不是只报翻转率。** `negative/positive` 翻了 **48.25%** 的答案，但 AUROC 仍留在 **.7579**（从 .8258 来）：**对这一对，交换只移动了操作点、排序仍可用，翻转率把伤害说大了**。**只有那些 AUROC 穿过 .5 的名字对，才是真正"丢掉了决策本身"。**

### 结果三：逐个谓词都成立

**跨重命名的单一平均值是个"混合参数"**，因为不同重命名对语义的保留程度不同（"positive"是把"发票已核对"报告出来的地道说法，却不命名"这条轨迹需要人工复核"的任何属性）。所以论文**逐个谓词报告**：`no/yes` 单独就能扛住——它在四个独立谓词上的**最小值是 56.7%**，而**中性对照从未超过 11.3%**；**逐谓词看，它至少是对照的 7.4 倍**。其余极性名字对则从 **12.3% 到 92.0%** 不等，论文只把它们报成**区间、绝不报点估计**，**头条结论只压在那个"最小值"上**。

### 结果四：极性驱动它，训练词表熟悉度放大它

**五对极性名字在第二个轴上又分开了**：`no/yes` 与 `false/true` 是**这个头在训练里发布过、界面也在用**的词；而 `absent/present`、`negative/positive`、`rejected/accepted` 是**它从未发布过的极性词**。拆开两个贡献：**从中性名字走到"不熟悉的极性名字"要付出 41.00 pts；从不熟悉的极性名字再走到"两对熟悉的"要再付 16.04 pts。** **极性是更大的那一项，而且它作用在"这个头从来没被训练去发布"的词上**——所以这个效应**不能归约为"背下来的输出词表"**。

**作者诚实地说明：这两个效应无法用这些臂干净分开，他们不主张分开。但混淆的方向才是不舒服的地方——`no/yes` 和 `false/true` 正是被部署的名字，而能扛过对调的中性标识符，却是任何工程师都不会为一份"可读 schema"去选的。**

| 选项名类别 | 翻转率 | 逐谓词范围 |
|---|---|---|
| 中性（0/1、A/B） | 6.25% | 2.7–11.3% |
| 极性、词表外（3 对） | 47.25% | 12.3–92.0% |
| 极性、词表内（2 对） | 63.29% | 29.0–92.7% |
| 极性相对中性的增量 | **+41.00 pts** | — |
| 训练词表熟悉度的额外增量 | **+16.04 pts** | — |

### 结果五：超过二值时，名字几乎承载了全部信号

在 **683 道真正的多值题**上（选项渲染为"名字: 描述"，金标以描述为准），**把成员名换成中性字母——一个描述都不动——就改变了 52.42% 的答案，准确率从 .5637 掉到 .2782**。**把名字相对描述整体转一格**（每个名字开始"宣传"邻居的内容）：**改变 79.65%，准确率掉到 .1552**。**仅仅"有误导性"的名字，就比"仅仅无信息"的名字多付出 27.2 pts**；而**转位后，模型的答案在 k=4 的题上有 .240 与"名字原本的内容"一致**。**二值情形低估了问题：基数越高，描述越接近被忽略。** k=16 时中性重命名落到 **.141**——**恰好是这些题里"金标成员正好排第一"的占比（.1406），也就是位置性的、而非语义性的**。（论文注明：这一臂的出厂准确率只有 .5637 且随基数波动，所以只当作对二值结果的"方向性支持"，不当作第二个头条。）

### 结果六：读数几何决定效应大小

**对同一批 1800 道题、同一个对调**，换成 **span-mean 头**：`no/yes` 只改变 **19.50%** 的答案，而 **marker 头是 80.50%——4.1 倍之差**。**机制在架构里看得到**：当选项分数是"整段渲染文本的均值"时，一个单 token 的名字被一段长一个数量级的定义**稀释**了；当分数来自一个在整段上做注意力的 marker token 时，**没有这种稀释**。**与此一致的是**：span-mean 头在"没有定义可稀释名字"的域内题上，正是强名字驱动——它的 AUROC 从 `no/yes` 的 **.7860** 掉到 `A/B` 的 **.3597**。**所以"名字敏感性"是读数的一个设计参数，而不是某个 checkpoint 的怪癖——这也意味着，它可以被设计掉。**

**第三个家族是厂商自己的托管模型**，在 Table 1 的 1200 题上通过 HTTP 调用（金标正例率 .5750），对调"只是把该题的名字–定义映射做了一个置换"。交换 `no`/`yes` 背后的定义：**改变它 32.50% 的答案**，两对中性对照只动 **2.08%** 和 **1.67%**，**对比 30.42 pts（95% CI [27.58, 33.33]）**，平衡准确率 **.7127 → .5163**。因为它的概率**最多只有 36.33% 能在两次请求间逐位复现**，论文把对齐臂在 300 题、2 对名字上问了**两遍**：**什么都不变时，它的答案最多只有 1.33% 会变**。**对调是这条下限的 24 倍，而两对中性对照正好压在这条下限上。**

**同一个对调，三个家族都复现，类别的排序也复现**：每个家族里，**中性名字动得最少**，"marker 头词表外的三对极性词"动得更多，"词表内的两对"动得最多。**但量级不复现**：marker 头在 `no/yes` 上的翻转是托管模型的 **2.4 倍**。**失败形态也不一样**：**marker 头"反转"、span-mean 头"稀释"，而托管模型两者都不是——它的 AUROC 从 .8146 掉到 .5806，朝着随机去、却不越过它**；论文看不到它的读数层，因此不给机制，而**它的类型错误率同样是 0%，by Lemma 1**。**反转可修正、稀释可容忍、塌陷两头都不是——为一个头选的几何，决定了部署层对"名字效应"还能做什么。**

| 选项名类别 | marker | span-mean | hosted |
|---|---|---|---|
| 中性（0/1、A/B） | 6.25% | 14.80% | 1.88% |
| 极性、词表外（3 对） | 47.25% | 18.56% | 11.06% |
| 极性、词表内（2 对） | 63.29% | 33.66% | 32.21% |

### 结果七：完全没有语义的名字

**前面每一类名字都带含义。第四类把含义也拿走**：每个选项用**随机的 5 字符字符串**命名（字母数字混合，抽的时候保证两个名字都不是词、也不互为前缀、且无任何序数或字母序关系，如 `xg6a6` / `e97ce`）。**这些名字像 `0/1`、`A/B` 一样不带极性，且不同于它们的是——也不带任何内容**，于是**定义成了选项里唯一可读的东西**。论文独立抽了 **15 对**，全部过两个本地读数、前 5 对过托管模型，**其余什么都不变**。

**不透明的名字，在三个家族里都落在"中性类"上**：它们分别改变 **6.86% / 11.67% / 2.02%** 的答案，而 `0/1`＋`A/B` 是 **7.94% / 14.83% / 1.88%**——**任何家族里差距至多 3.16 pts，在两个本地读数上还略低于中性对照，在托管模型上与它无从区分**。**对齐平衡准确率全程保持**（三个家族里与中性类的差距至多 .03），**所以低翻转率是"决策仍在被做"，而不是"通道被关掉了"**。**而同样题目、同样读数上的极性名字，改变 32.21%–70.72%。** **所以对调利用的是选项名字的"极性"：极性一旦缺席，名字的语义内容最多值 3.16 pts；一个"什么都不表示"的名字，相对一个"不表示特定东西"的标识符，买不到任何东西。**

## 四、技术启示与发展方向

**第一，"类型错误率"这句可靠性承诺，需要一条"名字不变性"的数字陪着。** 0% 类型错误率是**解码器的属性**，把它当作可靠性数字展示，**会诱导出一个它根本支撑不起的推论**。论文的建议很具体：**在旁边加一个"名字不变性数字"**，而**相对中性选项名的翻转率**就是现成候选——**它不需要标签、每条多走两次前向，却能在这些 checkpoint 上把一个 76.92% 的不稳定性暴露出来**，而这个不稳定性，**靠"出厂 schema 上的准确率"永远看不到**。

**第二，有两条能直接落地的缓解。** ① **用中性的选项标识符，把含义放进定义里**——在论文的数据上，这把不稳定性成本从 **76.92% 压到 6.50%**；② **在训练时就把决策绑到定义上**——对**随机化的选项名做绑定**，对这么小的一个头来说**很便宜**。论文也点到**基于课程的定义遵循、选项 ID 去偏、词偏置校正**是可行的缓解，只是**这篇没有评估**。

**第三，"它读名字"不是某一家模型的毛病，而是读数层的设计参数。** **同样的对调、同样的题，marker 几何动 80.50%、span-mean 几何只动 19.50%**；而**托管模型走出一条既非反转、也非稀释的"塌向随机"曲线**。**这既是警告、也是出路**——**既然名字敏感性由几何决定，它就能被几何设计掉。**

**边界也要说清。** 论文**只审计了两个编码器 checkpoint（每种读数几何各一）、且是英语**，稀释的解释能否定量迁移到别的架构**尚未检验**；**第三个家族是"某一时刻通过网络够到的黑箱"**（只看得到返回分布、不确定、且同名模型可能被替换，所以有了那个测出来的 test-retest floor）；**不同重命名对语义的保留程度不同**（所以只报逐谓词最小值、不报均值）；**极性与训练词表熟悉度这对混淆，没有被这些臂分开**；**多值那一臂建立在一个出厂准确率只有 .5637 的池子上**，只当方向性支持；**论文报告了漏洞和两条缓解，但一条都没评估**。

## 五、总结

这一篇，把本系列一路追问的母题又拧到了最新、也最贴身的一个角度。9/13 是"探针读到 0 分，真相未必被藏起"，9/14 是"秘密从基准里漏出来"，9/15 是"分数干净不等于证据在场"，9/16 是"榜单再也排不出名次"，9/17 是"动手前会不会去取证据"，9/18 是"共识是这样被吹大的"，9/19 是"伤害只是换了副面孔"，9/20 是"框架到底值不值"，9/21 是"嘴上说不知道、脑子里全写着"，9/22 是"没人教它们作弊，它们自己学会了互相放水"。它们问的是同一件事：**这个数，到底能不能信？** 今天这篇给了一个最"字面"的版本——**当接口用一条数学引理向你承诺"格式一定对"时，那条引理关于"它对不对"的信息量，是零。**

**得到的是一张"形式对了、意思反了"的解剖图。** **把两段定义在 `no`/`yes` 之间对调，题目、状态、定义原文、选项集合一个字节都不改，76.92% 的答案当场翻面，AUROC 从 .94 跌到 .23——低于随机，是排序被倒置。** 而那个被当成可靠性卖点的"类型错误率 0%"，**从头到尾岿然不动**：它是一条关于读数层的引理，**在模型四题错三题时，它照样是 0%。**

**也留下一条具体可抓的绳子。** 数据同时告诉我们：**换成中性标识符、把含义交给定义**——不稳定性能从 76.92% 落到 6.50%；**训练时就把名字随机化、把决策绑死在定义上**——对这么小的头并不贵。**还有一个近乎"照妖镜"的诊断**：**相对中性名字的翻转率，不需要标签、只多两次前向**，却能把一个被"出厂 schema 准确率"完全遮住的不稳定性照出来。**真正的稳，也许不是再给模型加一道格式检查，而是先问一句：它到底在读名字，还是在读定义。** 因为当一个接口向你保证"形式一定没错"时，**它没说、也保证不了那件更要紧的事——形式没错，是不是等于意思没反。**
