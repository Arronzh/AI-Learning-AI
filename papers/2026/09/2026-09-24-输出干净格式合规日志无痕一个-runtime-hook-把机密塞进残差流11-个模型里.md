# 「输出干净、格式合规、日志无痕」：一个 runtime hook 把机密塞进残差流，11 个模型里 9 个被最简单的线性解码器以 91–100% 复原——输出分布 KL 只动 0.001–0.007，激活层探测器最高 AUC 0.56（逼近抛硬币）

📌 **核心摘要**：组织把大模型放进受限、甚至气隙（air-gapped）的环境里，只让**少量"诊断/审计用的中间激活产物"**越过边界交给审核方——输出文本被过滤、日志被审计、权重被校验、worker 的网络出口被掐死。这篇论文（arXiv:2609.27996v1，**NDSS 2027**；作者 **Mingyuan Li（芬兰 ELLIS Institute / 图尔库大学）、Yanna Jiang（澳门城市大学）、Guangsheng Yu、Xu Wang、Ren Ping Liu（悉尼科技大学）、Qin Wang（CSIRO）、Wei Ni（伊迪斯科文大学）**）指出一个被漏掉的攻击面：**一个被供应链攻陷的 runtime 扩展（恶意依赖 / 插件 / skill）根本不需要给自己开出口，它只要在前向过程里往"残差流"写一个码字**——信号搭着正常计算一路传播，被**本来就合法运行的激活记录器**写进产物、合法地越过信任边界，事后**离线用一个线性解码器就能把机密读回来**。代价是：**11 个模型（7 个架构族）里 9 个恢复率 91–100%**，输出分布 **KL 只动 0.001–0.007**，而 5 类激活层探测器**工作点最高 AUC ≤ 0.56（0.50 即抛硬币）**；试过的 6 种事后防御，没有一种能在可接受效用下把它关掉。论文那句总结最扎心：**这个产物"schema 完全合法"，却带着一段本不该越界的信息。**

## 一、研究背景与动机

**大模型早就不"以权重形式"交付，而是"以软件栈形式"交付。** 命令行接口、agent harness、skills、插件、诊断组件……论文专门点名了 **Kimi Code CLI、Claude Code、Grok Build**，以及可扩展 agent 平台 **OpenClaw**：推理过程里跑的，越来越多是供应商和社区提供的代码。供应链面扩大了，处理敏感信息的路径也一起扩大。

**一类很典型、也很克制的部署长这样：** 隐私敏感的组织在受限或气隙的推理域里跑模型，但同时允许**"选定的激活产物"**进入另一个受治理的审计 / 支持域。审核方可以检查模型行为，却**不该从推理流程里学到受保护的信息**。论文举的例子极其具体：一家医疗机构用"临床记录工作流"的内部标签做路由，而这个标签被**刻意排除在 prompt、生成输出、普通日志、审计记录之外**。组织该做的都做了——限制 worker 出口、审核生成文本、校验软件与模型产物、审计日志。

**但这些控制全都管不住一件事：信息待在一条本来合法的通道里。** 论文把一个"最少特权下的攻击者"画像摆得很清楚：一个被供应链攻陷的 runtime 扩展（恶意依赖、插件、skill 或服务配置），**能看见那个敏感标签、能注册一个前向 hook、能读能改残差激活**；但**不能发起外部网络连接、不能任意写文件、不能改请求日志、不能直接调用企业的导出器，也动不了模型权重与 tokenizer**。这些限制不是刁难——它们是零信任 / 最小特权该有的样子。也正因为如此，攻击者**无法直接外传**。

**于是它需要一个"载体"，论文给出的答案是：残差流。** 攻击者把瞬时出现的敏感信息**映射成码字**，在某一层注入残差流；信号随后**搭着正常的前向计算一路传播**，被一个**本来就合法的、固定策略的激活记录器**（用于调试、剖析、可解释性、安全分析）序列化进产物；这个产物再沿着**普通的诊断 / 监控 / 备份 / 支持工作流**越过信任边界，落入一个持有解码材料的**离线观察者**手里。论文把这条路径叫做 **ResidualMux**。

**最要命的一点是："形式控制"在这里是失效的。** 基于格式的管控可以验证产物的**类型、schema 和来源**，却**约束不了激活里编码了什么**。论文写下了一句直接接住整条主线的判词：**"产物因此 schema-valid yet policy-violating（格式合法，却违反策略）。"** 这里的授权错配非常干净——**策略允许的是"这种产物类型"，不允许的是"它里面任意携带的信息"。**

## 二、核心方法

**ResidualMux 是四段式：校准 → 运行期注入 → 传播与授权记录 → 离线恢复。**

**第一段，码本与校准。** 攻击者用一个伪随机种子生成 **K 个单位范数的高斯随机码字**，在高维残差空间里它们近似正交（d=1024 时两两内积方差约 1/d ≈ 10⁻³）。它用**本地模型副本 + 已知的记录流程**，在满足 `r ∈ L_rec 且 ℓ < r` 的候选 `(ℓ, r, α)` 上做脚本化搜索，按验证集恢复率与输出失真预算选出注入层 `ℓ`、读出层 `r*`、注入强度 `α`，并训练好一个**临时解码器**。**码本种子、消息映射、配置、解码器，全部在攻击执行前固定。**

**第二段，运行期注入。** 对这个请求对应的每次前向，hook 在 `ℓ` 层执行一次残差写：`h^(ℓ) ← h^(ℓ) + α·c_k`，其中 `k = E(m)`。**广播模式**把同一个码字加到该次前向的**每个 token 位置**（提供同一条消息的冗余观测，但**不增加容量**）。除此之外，hook **不改权重、不改 tokenizer、不改生成文本、不改日志、不改产物元数据、不调用导出器、也写不了产物**——"残差写"是它对推理做的**唯一**与消息相关的改动。

**第三段，传播与授权记录。** 注入之后，剩下的层**不再有任何攻击者干预**，信号跟着普通残差更新一起走。那个**本来就合法的记录器**按固定捕获策略把 `L_rec` 层的激活序列化进产物 `A`——**它不知道码本、不识别消息、不跑解码器、也不加任何消息字段**。消息因此是通过"记录器**本就获授权保留**的那个激活字段"进入产物的。**全程不需要第二个 hook、不需要攻击者控制的日志器、不需要攻击者自建的出口。**

**第四段，离线恢复。** 产物越过边界后，持有解码材料的观察者取出 `r*` 层的激活、平均池化，过一个**刻意限定为线性**的解码器 `m̂ = argmax softmax(W·h̄ + b)`。限定成线性是有讲究的：**成功恢复说明消息在经传播与记录之后仍然"线性可及"**，而不是靠一个高容量重建模型硬凑出来的。

**这里的核心构念是 SRR（signal-to-residual-norm ratio）：** `SRR_ℓ = α / ‖h^(ℓ)‖`。因为 Pre-LN transformer 的残差范数**随深度剧烈变化**，一个固定的 `α` 在不同层代表的相对强度天差地别。于是论文设计**深度自适应协议**：用非敏感校准 prompt 估计每层的代表性范数 `Ĥ_ℓ`，再令 `α_ℓ = SRR_target · Ĥ_ℓ`。**论文把这条经验规律总结成一句话：能不能恢复，主要由 SRR 决定，而不是由架构决定。**

**还有一个漂亮的通信论视角：** K 个码字就像 **CDMA 扩频码**，铺在 d 维残差空间里，**处理增益 `G = d/K`**；若防御方做分组混合，则 `G_mix ≈ d/(nK)`。d 越大越可分；而想把 `G_mix` 压到 1 以下，需要 `n > d/K` 组——**当 d=4096、K=16 时，要超过 256 组。** 这条式子几乎预告了后面"防御为什么跟不上"。

**容量上，** 每次独立编码注入的名义载荷是 **`log₂K` 比特**（K=16 即 4 bits）；计入解码误差后的有效互信息（I(M;M̂)）在工作点约 **2.8 bits**。论文还给了跨请求分片：K 为素数幂时，用 GF(K) 上"码字索引 ⊕ 已知偏移 s_j"把一条消息摊到 B 个连续请求上，离线减去偏移再取多数表决（RQ6 里用 B=15、K=8）。

**最后，方法明确划了适用边界：** 这条路径成立需要三件事同时具备——**① 残差流的写权限；② 一条授权的下游激活记录路径；③ 事后能拿到产物。** 缺任何一条，此路不通。

## 三、实验结果

实验覆盖 **11 个模型、7 个架构族、0.1B–27B、残差维 d ∈ [768, 5120]**；200 条 prompt × 4 类（陈述 / 指令 / 数学 / 代码），检测实验 3 个种子，H100 集群。

**RQ1——它同时"可解码、隐蔽、难检测、保效用"吗？** 九个模型在 K=16 下全部 **≥91%**：Qwen3.5-27B **100.0%**、Qwen3.5-0.8B 99.8%、Qwen3.5-4B 99.4%、……直到 Phi-4-mini 91.7%；**最优层对惊人地一致，大多是 1→3**。隐蔽性：α=0.25 时**输出分布 KL 只有 0.001–0.007**，logit 余弦 >0.999；**模型越大越隐蔽**（Qwen3.5-4B 的 KL 比 0.8B 低约 6×）。效用：MMLU/GSM8K 上，**≥4B 的模型在 α=0.25 时变动 ≤0.4pp，即便 α=1.0 也仍在 5pp 内**；只有 0.8B 在小模型端退化明显。难检测：**九模型五探测器，工作点最高 AUC ≤ 0.56；即便把注入强度加到 α=0.5，最好的也才 0.64，没有一种够到 0.70 的操作可用线**；工作点平均 TPR 仅 **3.3% @ FPR=1%、12.5% @ FPR=5%**。更狠的是那个 **oracle 探测器**——一个**全知 K、α 与码本**的 3 层 MLP，读出层 AUC 也只有 **0.501**：**扰动在几层之后就被"混没了"**。而且**探测能力随规模收敛到随机**：同一个 Qwen3.5 家族里，最好 AUC 从 0.64（0.8B）单调落到 **0.50（27B）**。

**RQ2——跨层、跨模型到底由什么决定？** 十个模型的残差范数**随深度增长 8.9×–158.8×**，固定 α 的恢复率就顺着这个方向塌下去；**改成范数归一化后，每一层的探针准确率都回到 ≥98.3%**。Gemma-3-1B 是最清楚的离群点：它初始范数极大（‖h₀‖=358.3 → ‖h_L‖=9826.1），在固定 α 下图"看起来很抗打"，**可一旦 α 跟着 ‖h^(ℓ)‖ 走，通道立刻回来**。论文的结论一句话——**"大多数表面上的抗性，是 SRR 失配，而不是架构防御。"** 对防御者的推论也很直白：**只监控少数几层是不够的，攻击者换个层就能把容量带走。**

**RQ3——事后防御能拦住吗？** 论文评了六种，**没有一种能在可接受效用下消除通道**。**高斯噪声**：σ=0.1 才把探针从 99% 压到 83%，代价却是 **KL 冲到 1.25（约攻击者的 50×）**；要真正毁掉通道得 σ=0.5，而那时 **KL > 12，模型已经不可用**。原因很清楚——**攻击是"方向性"的，防御却把噪声预算各向同性地摊到 d 个维度上**。**架构混合（mHC）**：多轮混合是最强的一种，但**只在小模型上有效**——4 轮把 Qwen-0.8B 压到 **11.7%**，对 Mistral-7B 却**纹丝不动（99.7%）**，规律正是那条 `d/(nK)`。**AttnRes** 实测几乎没用：训练后 8/11 个模型把 >98% 注意力放在最后两层，模块基本塌回标准读出，平均只差 1.05pp；**更糟的是它泄露了防御者偏好的读出层，反而帮攻击者选注入点**。**量化**非通用：INT8 无感，INT4 把 Phi-4 打到随机，却让 Mistral-7B 保持 98.8%。**子空间投影**是唯一直接打"空闲维度"的：取前 10% 主成分能把 Llama、Qwen-4B 压到距随机 7pp 内，**但 Qwen-0.8B 仍达 40.5%**。理论还给出一个防御下界：要把观测到的隐蔽速率压下去，读出子空间里的有效噪声得达到 **σ² ≈ [1.25, 1.38]×10⁻²** 量级——**而这正好解释了为什么 σ=0.1 一边部分破坏通道、一边已经把输出毁了**。论文的落点很硬：**只要有效维度大于码本大小，探针就保有处理增益；缓解必须移到工程控制——隐藏状态访问控制、可信执行。**

**RQ4——自回归生成与多轮对话里还活吗？** 五个模型上，通道**扛过 100-token 贪心解码和 50 轮对话**；**每 token KL 停在 5.7×10⁻⁴–6.6×10⁻³，且不累积**。多轮持久化里，**Qwen-4B 达 100%、Qwen-9B 95%、Qwen-0.8B 约 85%**，而且从第 5 轮到第 50 轮基本平移不衰减——**因为攻击者在每一轮都"重新注入"**，对话历史变长并不会稀释信号。论文一句很清醒的提醒：**token 一致率下降，并不等于分布漂移变大**；小的逐步偏移偶尔翻掉 argmax，就把生成带向另一条同样合理的续写。

**RQ5——比基线强在哪？** 对七种基线，**ResidualMux 是唯一能同时做到"有容量 + KL 贴地 + 检测贴地"的方法**：**3.4–3.9 bits/injection 下 KL=0.003、AUC=0.50**。最近的输出级对手（token 通道）要到 **KL 2.71、AUC 0.64** 才换来 3.35 bits；水印永远到不了 1 bit 还不被检测（0.97 bits 时 AUC 已 0.98）；定时、KV-cache 这类侧信道容量极小且本就改不了输出分布。**在同等 KL 预算下，ResidualMux 的容量高出 10–170×。** 机制解释也顺理成章：**token 级方法在词表瓶颈上硬打，残差级注入却写进 d=1024–4096 维中一片"很少被用满"的低秩子空间。**

**RQ6——真实服务栈里组得起来吗？** 论文用**真实的 vLLM** + RAG 工作流（K=8 个集合标签）跑了完整链路：模型执行 → 独立记录 → FP16 序列化 → 持久存储 → 产物重载 → 离线解码，**不改权重、不改输出、不改 schema、不用任何攻击者控制的导出机制**。**30 个码本 × 8 种强度 = 240 个配置、38,400 次成功请求**：编码投递在更低强度下就超过 85%（**Qwen@α=0.20 → 86.7%；Llama@α=0.35 → 93.3%**），未编码投递在更强工作点最高到 **99.6%**。论文也把范围讲清楚：**这个用例验证的是"沿产物路径的系统组合"，不是气隙部署的物理隔离边界。**

## 四、技术启示与发展方向

**第一，"监控输出"这件事，从根上就不够。** 论文给出的是一个**结构性**的论证，而非某个检测器不行：**输出分布只是隐藏状态的一个"有损投影"**；残差空间的容量**超过输出分布所消耗的自由度**；**相对于残差自身的范数能量很小的加性扰动，在输出层可以完全不可见**。于是共享推理部署的**安全边界必须延伸到内部激活**——记录和监控隐藏状态当然有工程与存储开销，但**替代方案是接受一个"带宽随模型规模增长"的未监控攻击面**。

**第二，这是一个"逆向缩放"的漏洞：模型越大，越好藏。** 论文测得一致的趋势——**容量更大、隐蔽更好**：KL 从 0.8B 到 4B 降 6×，≥4B 在工作点任务退化消失，检测 AUC 从 0.64（0.8B）单调收敛到 0.50（27B）。两条机制：**信道信干比 ~ Ω(d/K)，d 增大直接带来更多可分量**；**残差范数随深度与隐藏维增长**，让同一扰动占的比例更小。**防御者不因规模受益**：同样的噪声防御在高维需要按比例更多的噪声，而连带伤害照旧。论文因此下了一个很强的判断：**这不是小模型上的过渡性瑕疵，而是随规模部署而恶化的持久漏洞。**

**第三，出路在工程控制，而不在事后修补。** 论文的落点非常明确：当"有效维度 > 码本大小"时，**任何基于噪声 / 混合的后处理都留有处理增益**；能真正把关的是**隐藏状态访问控制与可信执行**——**谁能写残差、谁能记录、谁能把中间态带走**。落到工程清单上就是：**schema 校验必须补上"信息量"这一维**；跨域产物需要的是**"信息审计"而不只是"格式审计"**；不受信的激活写入、不必要的残差保留、产物长期留在原域，都是可以直接砍掉的攻击面。

**第四，SRR 这个构念本身值得被记住。** 它把"该注入 / 该监控哪一层"从一个玄学问题变成一个**可校准的标量**；对防御者最实用的一条推论是：**"守住几个特定层"是没有意义的，因为通道可以随层迁移而保持容量。**

**边界也要说清。** 论文明确列出：此法**需要残差写权限 + 授权记录路径 + 事后产物访问**三者齐备；**禁止不受信激活写入、不保留残差激活、或把诊断产物留在原信任域内**的部署，**不通过这条路径受影响**；**闭源黑箱 API 不在范围**；`vLLM` 用例**验证的是系统组合，不是气隙的物理隔离**；恢复率是**在每个模型各自的评测 prompt 分布上校准**得到的，**不代表跨工作负载的泛化**。

## 五、总结

这一篇，把本系列一路追问的母题，推到了它最"物理"、也最难辩解的一层。9/13 是"探针读到 0 分，真相未必被藏起"，9/14 是"秘密从基准里漏出来"，9/15 是"分数干净不等于证据在场"，9/16 是"榜单再也排不出名次"，9/17 是"动手前会不会去取证据"，9/18 是"共识是这样被吹大的"，9/19 是"伤害只是换了副面孔"，9/20 是"框架到底值不值"，9/21 是"嘴上说不知道、脑子里全写着"，9/22 是"没人教它们作弊，它们自己学会了互相放水"，9/23 是"格式一个错都没有、答案却反了"。它们问的是同一件事：**这个数、这个信号，到底能不能信？** 今天这篇把镜头从"模型说了什么"移到了**"通道本身"**——**当一个被攻陷的组件连网络出口都没有、日志里连一条痕迹都没有、产物 schema 一个字段都没改，它仍然可以把机密送过边界。**

**得到的是一张"形式合规、内容越界"的解剖图。** **一个 runtime hook 往残差流写一个码字，11 个模型里 9 个恢复率 91–100%，输出分布 KL 只动 0.001–0.007；激活层探测器工作点最高 AUC ≤ 0.56，全知的 oracle MLP 也只有 0.501。** 而那些"看起来能拦"的东西——**高斯噪声要在毁掉模型的前提下才有用，架构混合只在小模型上有效，量化和 AttnRes 都各管一半**——**没有一种能通用地把通道关掉**。更刺眼的是那个**逆向缩放**的事实：**模型越大，容量越大、越隐蔽。防御者不因规模受益。**

**也留下一条具体、可执行的绳子。** 数据告诉我们：**只要"有效维度 > 码本大小"，后处理防御就留着处理增益**；真正该收紧的是**谁能写残差、谁能记录中间态、谁能把产物带走**这三件事——**把安全边界从"输出"推到"内部激活"，把审计从"格式"推到"信息量"。** 因为**当你能验证"格式没错"时，你恰恰验证不了"内容没越界"；而当模型越大越好用时，它也同时越好藏。** 真正的边界，也许从来不在那行输出里，而在**"谁碰过中间那一步、谁把它带过了线"**。
