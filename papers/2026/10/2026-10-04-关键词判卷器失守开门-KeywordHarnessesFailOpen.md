# 「同一批测试里两个模型只差 0.01 分，现实却是 6/6 对 0/6」：给小型模型判「会不会调用工具」的关键词基准，会「失守开门」——一个从没真正发出过工具调用的小模型，凭着一口流利的行业黑话，就拿到了和真会调用的兄弟几乎一样的分；一把几分钟就能跑完的严格尺子揪出了这个假阳性，一次约 3.3 GPU 小时的对症修复又打赢了多花三个数量级 token 的失败工程；而最扎心的是，这个「失守」的坑，论文作者自己的评测流水线也踩了进去

📌 **核心摘要**：**「这个模型会不会调用工具？」——在当下这波 agent 与工具调用（tool use）的热潮里，这几乎是一个模型能力的入门考试**：**能不能正确地把「我要干什么」翻译成一段结构化、可执行的调用，被当成小型模型能不能上生产线的分水岭**。**而目前业界衡量这件事最省事、最流行的办法，是「关键词判卷器（keyword harness）」——拿模型输出的自由文本去匹配期望工具的名字、命令或关键词，命中了就得分**。**这篇论文（arXiv:2610.02142v1 [cs.CL]，2026-10-01 提交，作者 Juan S. Santillana，隶属 Globant，是「VectraYX 系列」小型模型工程记录的一环）用一对「同源对照模型」把这个惯用做法当场拆穿**。**两个模型共享同一套解码器、分词器和特殊 token，架构几乎是双胞胎**：**一个是 VectraYX-600M（6.616 亿参数，预训练语料约 65% 是代码与技术文本，单阶段预训练，没有专门的 SFT，训练在计划进度的 64% 处永久冻结）**；**另一个是 VectraYX-1B（11.09 亿参数，以网页文本为主的多阶段课程，还专门跑了约 60 亿 token 的工具 SFT）**。**在宽松的关键词判卷器上，两者工具调用（B4）分数分别是 0.660 和 0.650——只差 0.01，看上去是一对好兄弟**。**可换上一把严格的「逐字复现（verbatim reproduction）」尺子，两者立刻被彻底分开**：**600M 在 6/6 条真实训练样例上生成了格式合法、参数还能自己泛化的工具调用（6/6 全过）**；**1B 则在每一个修复前的检查点上都是 0/4–6——它从来没有真正「打开过」那段工具调用结构**。**论文顺着这条线走完了「测量 → 诊断 → 修复 → 定位」一整条链条**：**先用「首 token 概率探针」把病因定位到「1B 对 `<|tool_call|>` 这个触发 token 的先验几乎为零（约 10⁻⁴–10⁻⁵）」**；**再指出这个先验并不是没学过，而是被它「以网页为主」的第二个预训练阶段给「冲掉了」**；**然后用一次对症的 SFT（约 3.3 GPU 小时、单卡租用）把 1B 修好，269 条语料上的合法发出率从 0.100 拉到 0.959，在 238 条未见过的提示上以 0.536 对 0.428 反超 600M（McNemar p=0.0039）**；**最后用「嵌入漂移检查」证明这次修复动的是「网络怎么把隐状态路由此刻的 token」的布线，而不是 token 自己的表示——那张嵌入表 97.7% 的条目在修复前后逐比特完全一致**。**而论文自己给出的判词是：关键词判卷器会「失守开门（fail open）」——一个有一口流利行业黑话、却根本没有能力的模型，可以拿到和一个真有能力的模型一样的分。** **更妙也更扎心的是**：**论文收尾时披露，这个「失守」的坑，论文作者自己项目的评测流水线也踩了进去——评测脚本在解码时默认吞掉了特殊 token，于是一段完美的工具调用被判成「没调用」，直接从 0/8 变成 8/8**。**「命名了这个失效模式的论文，自己又踩了一次同样的失效模式」——这成了全文最有分量的一句自证。**

## 一、研究背景与动机

**先说清楚「判模型会不会调用工具」这件事，为什么会被一篇论文当成「评测有效性」问题来审。** **近几年，模型「调用工具」几乎从锦上添花变成了入门要求**：**能读懂一段需求、把它翻译成一个结构化的 JSON 调用，点名一个真实存在的工具、填好参数——这套「结构化输出」能力，被当成小型模型能不能真正当 agent 用的门槛**。**从 Toolformer 证明模型能从自监督示范里学会 API 调用，到 Gorilla、ToolLLM 把指令微调铺到 API 调用上、并给出 APIBench / ToolBench 这类评测集，主流范式一直是「拿一个强预训练底座，再在工具演示数据上做 SFT」**。**而衡量成不成功，最流行的做法就是「关键词判卷器」——在模型吐出的自由文本里，找一找有没有出现期望的那个工具名、那条命令、那个关键词**。**这套办法便宜、好写、跑得快，于是被广泛默认采用**。

**可论文要问的，恰恰比这套范式更往下沉一层的问题。** **前面那些工作问的是「模型有没有选中正确的那个工具」；这篇问的是更原始的一步——「那段结构化调用，到底有没有被生成出来」**。**论文点出一个被静悄悄假定、却可能经常不成立的前提**：**「先拿一个强预训练底座、再 SFT 工具演示」这套范式，暗中假定「底座本身已经带着结构化输出的先验」**。**但这个假定会失效**——**而一旦失效，一个「关键词判卷器」不仅测不出这个失效，还会因为模型「说得很像」，反而给出一个虚高的分数**。**换句话说：一个不会调用工具、但会大谈特谈工具相关内容的模型，在关键词判卷器眼里，和一个真会调用工具的模型长得一模一样**。

**这篇论文的切入点，正是把「评测本身」当成一台实验仪器来校准。** **它手里恰好有一对「同源对照模型」——同一个解码器家族、同一套分词器、同一套特殊 token 布局，只差「引导语料的成分（bootstrap composition）」：一个是代码为主的单阶段预训练，一个是以网页为主的、后期还专门补了约 60 亿 token 工具 SFT 的多阶段课程**。**这个对照关键就关键在**：**它让「训练数据成分」这个变量被单独拎了出来，同时把「架构差异、tokenizer 差异、特殊 token 差异」这些常见的混淆项一次性钉死**。**于是「到底什么决定了一个小型模型会不会默认调用工具」这个问题，第一次有了一个足够干净的读数**。

**这恰好落在本系列一路追问的那条主线上——「呈现出来的东西」和「它该对应的东西」之间，隔着多远。** **9/13 问「探针读到 0 分，模型是不是把真相藏起来了」；9/15 问「分数干净，证据在不在场」；9/23 问「格式全对，答案为什么反了」；9/24 问「输出干净，机密为什么从残差流溜走」；9/25 问「监控所依赖的轨迹，是不是攥在被监控者自己手里」；9/26 问「把图换成噪点，对齐分数为什么照样逼近 1.0」；9/27 问「一张排行榜，为什么唯一站得稳的是倒数第一」；9/28 问「一份不造假、不篡改的旧文档，为什么能把对的答案改错」；9/29 问「答对了，也可能是蒙对」；9/30 问「答案对了，那条写出来的推理成不成立」；10/1 问「演得像一个弱角色，能力是不是真的被压下去了」；10/2 问「模型看起来在自我修复，是不是真的在修复」；10/3 问「给 AI 想出来的点子打分的尺子，自己稳不稳」。** **它们问的始终是同一件事——一个「读数」，和它「本该对应的那件事」，隔着多远。** **而今天这一篇，把镜头对准了评测链路上最靠前的一环：连「它到底有没有产出这个动作」这一步，都可能被一把只认关键词的尺子读错——你以为它在量「模型会不会用工具」，可它量到的，可能只是「模型有没有把工具名念出来」。**

## 二、核心方法

**方法不炫技，它的分量在于「把一句只能靠经验感觉的『这个分数好像不太对』，变成一把几分钟就能跑完、层层加码的排查梯子（diagnostic ladder）」。**

**第一步：造出一对「只差引导语料成分」的同源模型。** **两个模型的共享部分被论文特意钉死**：**同一个解码器家族、同一套分词器、同一个特殊 token 布局**——**这意味着它们对 `<|tool_call|>`、`<|assistant|>` 这类结构标记的「口音」是一致的，比较不会被这些表面差异污染**。**不同的只有「bootstrap 成分」**：**VectraYX-600M 走的是单阶段预训练，语料里约 65% 是代码与技术文本，还掺了约 0.1% 的「in-mix 指令」信号；它没有专门的对话 SFT，训练则在计划 24 万步的 64%（第 15.4 万步）处永久冻结（因为训练用的机器和云账号都不在了）**。**VectraYX-1B 则是「以网页为主」的多阶段课程，还在第三阶段专门跑了约 60 亿 token 的工具 SFT**。**论文很克制地声明：这是一次「自然实验」，两个模型的血统、语料、规模都不同，已知存在混淆项**——**它不假装这是一次纯净的因果对照，而是把「成分决定的是默认还是需要工程化」这个结论，架在一整条互相印证的证据链上。**

**第二步：搭一把「宽松到近乎放水」的继承式判卷器，当成对照组。** **论文沿用了系列里那套 B1–B5 基准**，**其中 B4 就是「工具调用」这一项，判定方式就是关键词匹配**——**期望工具的名字只要在自由文本里出现过，就算命中**。**这套判卷器先被当成「宽松（lenient）尺子」摆上台面，用来先给两个模型量一个「表面分数」**。

**第三步：造一把「严格、便宜」的诊断尺子，作为梯子的上层。** **论文的核心仪器是一套四件的「廉价排查组合」**：**①「逐字复现（verbatim reproduction）」，用真实训练样例、精确训练时的前向、贪心解码，看模型能不能把那段结构原样开出来，并且要求「泛化」——参数要上下文合理、且不等于训练答案，而不是背出来的**；**②「首 token 概率探针」，直接读模型在助手回合起始处，对 `<|tool_call|>` 这个触发 token 赋予的概率**；**③「新实体泛化电池」，用一批实体池与语料毫无词汇重叠的提示（保留段 IP、CVE-2025-\* 编号、随机哈希、虚构域名）去考「换新词还认不认」**；**④「嵌入漂移检查」，比较修复前后触发 token 那一行嵌入向量动没动**。**四件仪器加起来只要几分钟 CPU 时间，论文主张把它们作为「小型模型工具调用声明」的常设闸门**。

**第四步：用探针把「病」定位，再开「对症的药」，最后回读「药到底动了哪」。** **诊断给出的结论很具体**：**1B 的问题是「先验缺席（absent prior）」，不是「先验含噪」**——**它对触发 token 的概率低到 10⁻⁴–10⁻⁵，几乎没有任何朝向这个格式的引力**。**这个诊断直接预言：「只是把工具样本在狭窄语境里重放一遍」的 SFT 会失败（格式上的概率质量太低，梯度撬不动）**；**「用足够多样的助手回合语境包住同样的样本、并把学习率抬到足以移动网络中层」的 SFT 才可能成功**。**论文据此设计了修复配方 C（多样语料 + 5 倍学习率 + 2,202 步），而且为了排除「背题」，专门用「新提示泛化电池」给结果定性**。**再往后，论文用「轨迹探针」把 38 个存档检查点连成曲线，把「某个时刻的快照对比」升级成「整段训练怎么演化」；最后用嵌入漂移把修复的落点钉在「路由」而不是「表示」上**。

## 三、实验结果

**结果一：宽松判卷器下，两个模型几乎不可区分——这正是问题的开始。** **B1–B5 表里，两个模型像一对双胞胎**：**B1 完全相同，B2/B3 各让两分，而关键的 B4 工具调用，600M 是 0.660、1B 是 0.650——分差只有 0.01**。**如果只信这张表，结论会是「两者工具调用能力相当」**。

**结果二：换成严格尺子，两者完全不重叠——一个 6/6，一个 0/6。** **逐字复现检查里**：**600M 在第 15.4 万步检查点上，6/6 条训练样例都生成了格式合法、且参数泛化（不是背来的答案）的工具调用**——**比如给一条日志排查的提示，它会自己拼出一条 `grep -i 'error\|critical\|fail' /var/log/syslog | tail -30`，而不是照抄训练里的 `tail -50 /var/log/syslog`**。**而 1B 在每一个修复前检查点上都是 0/4–6——它从来不「打开」那段结构，其典型续写是一段与工具毫无关系的西班牙语散文**。**首 token 探针把差距量化**：**在助手回合开始处，1B 对 `<|tool_call|>` 的概率只有约 10⁻⁴–10⁻⁵——这不是「差一点就调用了」，而是「压根没有朝向这个格式的任何先验」**，**尽管它专门跑过约 60 亿 token 的工具 SFT、还在这批测试样例所来自的语料上继续 SFT 过**。

**结果三：宽松分数是「失守开门」的产物，不是真本事。** **两张表不可能同时为真**：**一个在最有利条件下都发不出工具调用结构的模型，不可能「正当地」拿到 B4=0.650**。**论文给出的机制是**：**关键词打分器只要在自由文本里看到期望工具名，就放行**——**而 1B 恰是「流利、切题、满口安全术语的散文」这个失败模式，最擅长「薅」到这种分**。**于是论文宣布 1B 的 B4 不可信、在一切比较中弃用；同时保留 600M 的 B4=0.660，因为它被严格尺子独立佐证**。**这就是论文的题眼，也是「失守（fail open）」的含义**：**关键词判卷器在「模型没有能力」时不但不报错，反而因为「说得像」而给出高分——「一个流利但没能力的模型，得分像一个有能力的模型」**。**论文说，这已经是该系列记录在案的第二起同类事件（第一次是 Nano 的 B2 分类指标）**，**并给出通用教训：关键词判卷器会失守开门**。

**结果四：病程的真相由「轨迹」给出——先验不是没形成，而是被冲掉了。** **把探针回放到 38 个存档检查点上，端点对比就变成了曲线，而曲线改写了读法**。**先看 600M**：**它的「跳过空白后的触发概率」在第 1K 步就已经是 0.858，第 10K 步破 0.99，第 30K 步起稳定在 0.999 以上**——**30 万 token 之内，这个先验就已经装好了**；**但另有一条不光彩的伴生发现**：**那个「系统提示明确要求不要调用工具」的样例，在全部 15 个检查点上拿到的概率和「该调用」的样例几乎一样（均值比恒为 1.00），且 15 个检查点无一例外都把它也调用了**。**所以 600M 的默认，是一个「无条件的基率（unconditional base rate）」，而不是一个「看语境决定要不要调用」的闸门**。**再看 1B，这半段更关键**：**它在预训练第二阶段的第 36K 步，触发概率还有 0.432、还能 3/5 发出合法调用；但仅仅 2000 步之后掉到 3.0×10⁻³，到第 48K 步只剩 5.9×10⁻⁷，此后 14.4 万步再没离开过地板**——**这等于说，第二个阶段（其首个数据块 90% 是散文、只有 5% 是代码）在 12,000 步（约 31 亿 token）内，把一份「继承来的先验」抹掉了将近 5.9 个数量级**。**论文特意加密了第 38K–48K 的采样网格，确认这不是一个孤立的尖峰，而是一条平滑单调的衰减**。

**结果五：一个模型内部的「判卷器 vs 探针」直接对峙。** **1B 的第三阶段（专门的工具 SFT）有六个检查点同时留下了探针值和记录在案的 B4 分，而它们在两端朝相反方向动**：**第 14K 步 B4=0.085，是 1B 历史上最高的工具调用分，可同一时刻探针只有 5.7×10⁻⁵，是整个第三阶段里最低的值——比第 8K 步低了 201 倍**；**再往后 2000 步，B4 崩到历史地板 0.010，探针反而反弹 4.6 倍**。**论文的评语很克制也很锋利**：「**在宽松判卷器记录下它史上最佳工具调用分数的那一刻，这个模型朝向发出工具调用的先验，正处于最弱的状态——在最优条件下它发出了 0/5 次调用**」。**这一条是「模型内部、同一次训练内」的对峙，比跨模型的对照更硬**。

**结果六：换新词一考，两个模型各有胜负，而差异恰好落在「背题」和「填槽」之间。** **在 238 条「实体与语料零词汇重叠」的提示上（166 条该调用、72 条该抑制）**：**600M 的头条通过率是 0.428，修复后的 1B 是 0.536——两者答的是同一批题，所以是配对比较，修复版以 27:9 的独胜比胜出（精确 McNemar p=0.0039）**。**但把通过率拆成「选对工具 / 参数结构 / 提取新实体」几根轴之后，故事反转**：**600M 在「五选一选对工具」（0.776 对 0.717）和「参数结构完整」（0.855 对 0.819）上更强，却输在「提取一个从没见过的实体」（0.560 对 0.667）以及「软失误」（0.767 对 0.484）这两根轴上**。**翻译成人话**：**在语料内的题上，修复版 1B 基本是在「背」，600M 则是在「编」；而在语料外的新词上，修复版 1B 反而更可靠地把没见过的字符串抄了出来**——**「在分布内背诵」和「在分布外忠实填槽」不是同一种能力，这一对实验把它们分开了**。

**结果七：真正的共同软肋，是「什么时候不该调用」。** **两个模型都是在「抑制（suppression）」这一侧最差**。**在纯粹的、完全没有工具痕迹的安全问题上，600M 只有 0.354 的概率忍住不调用（其余 0.646 都过度触发了），修复版 1B 是 0.604**；**而在「近似陷阱（near-miss）」题上——句子提到一个 CVE、一个 IP 或一条 shell 命令，问的却是一个纯概念问题——两者一起崩**：**600M 通过率 0.087、过度触发 0.913；修复版 1B 通过率 0.174、过度触发 0.783**。**论文的一句话总结极其直白：在两个模型眼里，「提示里出现了工具形状的实体」几乎就足以触发一次调用，不管这句话到底在问什么**。**还有一处漂亮的逻辑陷阱被论文主动点破**：**修复前那个「从没调用过工具」的 1B，在抑制轴上「通过」了 0.562 的纯题和 0.565 的近似题，过度触发率精确为 0.000——它不是会抑制，而是 238 条提示里它只调用过 1 次**。**「一个从不调用工具的模型，在『不调用』这根轴上是满分」——这正是为什么抑制轴必须和一个「非退化作答」要求联合计分、绝不能单独看**。

**结果八：把修复配方拆成因子，所谓「多样语料」的功效没那么神。** **论文用 2×2 因子（语料窄/宽 × 学习率低/高）再加上一个同格子的种子重复，跑了五个臂**。**逐字复现完全分不开它们**（各臂都逼近满分）——**这本身是意料之中、也说明「逐字复现是分布内的仪器」**。**真正有意义的是泛化电池**：**高学习率下，语料宽窄没有可测量的差别**；**低学习率下，「宽语料」臂的抑制能力确实远好于「窄语料」臂——但用第二个种子重跑「窄语料」格后发现，两次运行的差距和要区分的效应一样大，于是论文把它降级为「假设（hypothesis）」而不是「发现（finding）」**。**更关键的一句是**：**五个臂、包括最弱的那个「窄语料 + 低学习率」角落，全都装上了调用格式**。**这直接推翻了论文早期草稿里那句「窄语料重训彻底失败」的强判词——那个「失败」从来没被有效测量过**（当时的判卷器既漏掉了系统提示、又默认丢掉特殊 token）。

**结果九：多花钱不等于更准——「专职判卷器」和蒸馏都没能兑现。** **论文对 600M 补做了一次工具 SFT（用或不用从更大模型蒸馏来的数据）**：**它确实抬高了「调用侧」的通过率，却没有给它装上任何「闸门」**——**在纯问题上，600M 的抑制率从 0.354 直接掉到 0**；**而那份蒸馏数据，则被证明「没有可测量的效果」**。

**结果十：论文顺手讲述了一个「自己也踩坑」的自证时刻。** **在收尾整理修复版检查点的 B1/B4 数字时，正式判卷器报告工具调用发出率为 0/8，而几分钟前严格诊断在同一个检查点上给的是 8/8**。**原因恰恰就是本文所讲的失效模式，只是换了一层**：**判卷器在解码生成 id 时用了一个默认会「静默丢掉特殊 token」的分词器库，于是那段完美的 `<|tool_call|>{...}` 在进入字符串匹配之前就已经被削掉了「工具调用」这几个字**；**一行「解码时不丢特殊 token」的修复，立刻恢复成 8/8**。**论文顺势审计了波及范围**：**同一套解码模式、加上一个把 `<|tool_call|>` 标成 CONTROL token 的 GGUF 导出器的镜像 bug，共同解释了该系列 1B 开发过程中反复出现、并被用来佐证一次语料重配的「0/3 字面发出」结论**。**论文把它作为「本文论点的第二个独立实例」照实录下**：**一个命名了「失守开门」失效模式的项目，自己又在三层（评测脚本、GGUF 导出、共享该模式的产线 agent 循环）里各踩了一次同样的坑，而每一次的修法都是同一类「一行代码」的错误，不是建模问题**。

## 四、技术启示与发展方向

**第一，这一篇最该被记住的一层：把「分数说它会」和「它真的会」拆成了两件事。** **论文的每个实验都在往同一句话上收**：**一个关键词判卷器给出的工具调用分，并不能被直接当作「模型会调用工具」来读**——**它可能只是「模型把工具名念出来了」的反映**。**对照本系列的主线，这句话可以缩成一行**：**呈现（B4 分）≠ 对应（真实的调用能力）**。**而更扎心的是**：**这两种读法，在「只跑一次宽松判卷」的实验里，长得一模一样**——**要区分它们，唯一的办法是「换一把不吃关键词的严格尺子」，让两种尺子的分歧把真相抖出来**。

**第二，「引导语料成分」决定的是「默认还是工程」，而不是「能不能」。** **论文修正了自己早期草稿里的强判词**：**代码为主的引导语料，让「结构化输出」这项能力「默认就来了」——由预训练装好、再由一丝 in-mix 信号点亮；以网页为主的引导语料，则让同一项能力「默认缺席」，只能靠后期一次对症干预补上**。**但它没有走向「网页为主的模型永远学不会」这个过度结论**：**修复演示了它是可以补上的，只不过要花对的设计信息**。**论文把它提炼成一条更锐利的规律**：**「SFT 的 token 体量，对未来哪种干预会奏效，几乎毫无预测力」**——**失败的那次专用阶段花了约 60 亿 token，成功的那次只用了约 10⁷（一千万）量级，差三个数量级**。

**第三，一条关于「花钱」的清醒结论：复杂度与成本，不等于效度。** **更大的 SFT 预算、更多样的语料、多一层蒸馏——这些「看起来更认真」的做法，在本研究里大多没能兑现**。**真正奏效的那次修复，贵的不是算力而是「诊断」**：**论文的一句话很值得抄下来**——**「对没有诊断能力的团队来说，理性的结论会是『这个能力遥不可及』；而事实是，『遥不可及』和『几美元的 GPU 时间』之间，只隔了一次正确的测量」**。

**第四，一条会直接改变工作流的工程建议：把廉价探针当成训练时的遥测。** **论文主张把「首 token 概率探针」这类近乎免费的读数，记进训练日志**——**因为它如果早被记录，会在 1B 第二阶段第 38K 步就把异常标出来，比实际发现问题早了约 400 亿预训练 token 和一整个约 60 亿 token 的工具 SFT 阶段**；**而且要同时记录「照字面位置」和「跳过空白后」两个版本，因为在某个检查点上两者相差了十三个数量级**。**另一条更锋利的建议是**：**任何工具调用基准的分数，都必须先过一道「严格结构检查」的闸门，因为关键词判卷器会失守开门**。

**第五，边界划得很清，而且划得异常诚实。** **论文承认**：**600M 永久冻结在进度的 64%、从未跑完余弦退火，所以它的每个数字都描述一个「未完成的工件」**；**对照对是自然实验、存在已知混淆**；**修复只有一个配方，其剩余两种成分只由一个「四格里三格只跑了一次」的因子来分离**；**泛化电池是论文自建的、不覆盖未见过的新工具和多调用序列**；**而且没有任何证据表明修复后的 1B 能有用回答普通对话问题**——**它修好的是工具调用，不是通用指令遵循**。**它还特别处理了一个「不体面」的细节**：**原始修复检查点连同它的父模型一起丢了，论文报告的是「同配方重跑」的复现版，并把「历史记录」明确标注为「不可用于承重」**。

## 五、总结

**这一篇用一对「同源对照模型」，把「小型模型会不会调用工具」这个问题，从一句口号拆成了一条可测量、可诊断、可修复、可定位的证据链。** **表面上，两个模型在宽松的关键词判卷器上只差 0.01 分；严格尺子下，一个 6/6、一个 0/6——同一批测试，描述的是两种完全相反的现实**。**1B 的失败不是「学得不够」，而是「先验被自己以网页为主的预训练阶段冲掉了」；它的修复也不是「喂更多样本」，而是一次约 3.3 GPU 小时的对症干预——比失败的那次省了三个数量级的 token**；**而嵌入漂移又证明，这次修复动的是「网络怎么把隐状态路由到那个一直就摆对的 token 方向」，不是 token 自己的表示**。

**论文留下的最核心一击，是那句「关键词判卷器会失守开门」**：**一个流利却没有能力的模型，可以拿到和一个真有能力的模型一样的分**——**而论文还诚实地补了一句：这个失效模式，它自己的项目也踩了三次**。**这句话几乎可以当作整个系列的一条注脚**：**你以为的「读数」，可能只是「这个读数被问成了什么样子」；而要分辨这两者，唯一的办法是让不同的尺子互相照一照。**

**对本系列的主线来说，这一篇把「测量有效性」的追问，又往前推进了一环**：**此前我们问「评分器稳不稳（10/3）」「归因工具可不可信（10/2）」，今天问的是更靠前的一步——「模型到底有没有做出那个动作」这件事，本身就可能被一把只认关键词的尺子读反**。**而当论文连「自己的评测脚本也偷走了那个动作」都愿意写进来时，它其实给出了最实用的那句忠告**：**「把一个动作，和一句关于这个动作的话，区分开来」——这应该是评测工具的最低门槛。**
