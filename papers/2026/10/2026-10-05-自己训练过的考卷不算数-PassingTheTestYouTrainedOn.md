# 「在一张榜上排第一、换一张榜掉到第十三」：给 LLM Agent 挑「提示注入探测器」，公开基准分测的其实是「输入形态像不像训练数据」——BIPIA 上抓到 95% 的榜首，到 AgentDojo 上 1% 误报率下只抓到 2.1%；会迁移的是误报率，不是排名；会迁移的是「输入的形态」，不是「攻击的字符串」；而最反直觉的一课是：你在自己训练过的那场考试上拿的分，预测不了你在真实岗位上打成什么样

📌 **核心摘要**：**当你想给一个 LLM Agent 挑一款「提示注入探测器（prompt-injection detector）」——也就是那个坐在工具和大脑之间、逐条检查工具返回内容、把可疑的「注入指令」拦下来的小分类器——你多半会去看公开榜单：谁在 BIPIA 上分高、谁在某个评测集上准，就选谁**。**这篇论文（arXiv:2610.03448v1 [cs.CR]，2026-10-02 提交，作者 Zhuowen Liu，日本北陆先端科学技术大学院大学 JAIST 网络安全实验室）把「按榜单挑探测器」这套沿用已久的做法，当场做成了一个可测量的实验**：**它评测了 15 款探测器（从 2023 年的 DeBERTa 分类器，到 Meta 的 Prompt Guard 2，再到 2026 年专为 agent 输入做的模型）外加 2 个「懂任务的 LLM 判官」，横跨两个 agent 基准（AgentDojo、τ-bench）和一个注入基准（BIPIA）**。**它要问的问题只有一句**：**「一个探测器在公开榜单上的分，能不能预测它在真实 agent 里的表现？」** **答案是不能，而且错得很系统**：**BIPIA 上的榜首 PIGuard 抓到 95.1% 的 BIPIA 注入，到了 AgentDojo 上、在 1% 误报率这个真实部署该用的工作点上，只抓到 2.1%——从 15 款里的第 1 名掉到第 13 名**；**一款在 AgentDojo 上抓到 72.2% 的探测器 Prismor，到 τ-bench 上只剩 15.2%；而 Sheltron 则从 20.1% 反过来涨到 95.2%**。**两两基准之间「探测排名」的相关性，Kendall τ 只有 0.01 到 0.31，全都不显著**。**真正稳定、真正会迁移的，是另一个东西**：**探测器在「无害工具输出」上的误报率——它从 0% 一路铺到 90% 以上，而且在不同 agent 基准之间高度一致（能互相预测），却跟「在普通文本上的误报率」毫无关系**。**论文把原因也钉死了**：**能决定一个探测器在哪好用的，不是「它见没见过攻击字符串」，而是「它训练输入的形态像不像它要筛的东西」**——**PIGuard 用 1,116 条完整 BIPIA 输入训练，于是它在 BIPIA 上封神；它也见过 53/62 条 InjecAgent 攻击指令，但那只是「178 字符的中位数短提示」，一旦这些攻击被裹进工具输出里，它抓「见过的攻击」有 52.1%、抓「没见过的攻击」有 55.8%——见了等于没见**。**而那个在两个 agent 基准上都夺冠的 Horizon-Labs，跟任何基准都没有一条重复数据，它只是「用 agent 风格的输入训过」**。**最扎心的是任务的另一半**：**两个「懂任务」的 7–8B LLM 判官在 agent 基准上只抓到 54%–78%，还不如最好的专用探测器；把用户请求喂给一个小分类器不但没帮忙，反而把误报率从 4.4% 抬到 69.7%**。**论文的结论朴素得像一句常识，却推翻了整条选型流程**：**「你在自己训练过的那场考试上考的分，测的是这张卷子像不像你的练习题，不是你会不会做题。」**

## 一、研究背景与动机

**先把这套「探测器」在真实世界里的位置讲清楚，因为它决定了一切评测该怎么设计。** **今天最流行的 agent 形态，是让一个 LLM 拿着工具去替你干活**：**读邮件、查日历、看网页、翻交易记录、读文件**。**而这些内容里，有很大一部分是「别人写的」——日历事件描述、商品评论、网页正文、表格单元格，都可以被第三方塞进一句话**。**「间接提示注入（indirect prompt injection）」说的就是这件事**：**agent 分不清「用户说的指令」和「工具返回的数据」，于是工具返回里那句被人精心写好的话，会和用户的话一样被当成命令执行**。**论文引了这条线的源头工作**：**Greshake 等 2023 年那篇《Not what you've signed up for》，证明了间接注入能把一个正常集成 LLM 的应用整个策反**。

**防御这件事有三条路，论文只挑第三条打。** **第一条是「模型级」**：**训练模型，让它学会忽略数据区里的指令（StruQ、SecAlign）**；**第二条是「系统级」**：**从架构上就把不可信数据挡在规划器之外（CaMeL）**；**第三条是「检测级」**：**在工具输出进入上下文之前，先用一个独立的小分类器筛一遍，疑似注入的直接丢掉——这就是探测器**。**探测器为什么最受欢迎？因为它最便宜**：**不用改模型、不用改 agent，挂一个过滤层就行**，**所以各类 guardrail 工具箱里都塞着探测器，工程师们也就习惯了拿它们来对比选型**。**这篇论文打的，正是这条最省事、也最容易被滥用的路**。

**那么，一个团队是怎么挑探测器的？答案是：看榜单分。** **论文把这种做法的来龙去脉点得非常具体**：**探测器论文通常报告「在一批提示词和带毒文档上的准确率」，往往包含 BIPIA 和那个专测「过度防御」的 NotInject 集合**。**2025 年有一份评测，拿 BIPIA 的邮件与表格任务比了 9 款开源护栏，从结论里就挑出了「PIGuard 能有效检测间接注入」**。**论文指出，这种沿用已久的做法里，有两个前提从来没被检查过**。

**第一个没被检查的前提：榜单上的「文本」，根本不是你 agent 的探测器要筛的东西。** **探测器论文和第三方对比用的，是提示词集合、是被注入了攻击的文档**；**可一个真实 agent 的探测器面对的，是「序列化的工具输出」——YAML、JSON、记录、列表、确认消息**。**这两者的差别不是体裁之别，而是「误报的代价」之别**：**在一个平衡的测试集上，误报只是让准确率掉一个百分点；可在真实 agent 里，一条被误拦的普通工具输出，意味着用户这一整个任务直接失败**。**论文给了一个极简的开场例子来说明这一点**：**AgentDojo 的一条银行任务里，用户让 agent「改密码、然后付一笔账单」，改密码工具返回一句最无害的 `{'message': 'Password updated.'}`——PIGuard 给这句话打出了 1.00 的注入分，一个「拦下即丢弃」的部署，会因为一个什么都没发生的任务而卡死**。

**第二个没被检查的前提：没有人在意「榜单和探测器的训练数据有没有重叠」。** **论文点出，此前的研究已经证明「同源切分（same-source split）会把自训分类器的分数吹高」，也早有人主张「评测应该报低误报率下的表现」**——**可这两条，既没有被用来审计「别人发布的、已经存在的探测器」，也没有人把它们放到「agent 真实会用到的地方」去评**。**换句话说，业界一边知道「用自己出的卷子考自己」会虚高，一边却照旧拿一张可能是「探测器训练分布内」的榜单选型**。

**于是这篇论文的切入点，就落在一句朴素到几乎不像问题的问题上**：**「探测器在公开基准上的分，能不能预测它在真实 agent 里的行为？」** **论文自己给出的中心观察，也是它想立的核心命题**：**「一个探测器，只会在那些『形态像它训练输入』的输入上工作；而基准分，测的主要就是这种『像不像』，而不是一种通用的、检测注入的能力。」** **这句话和本系列一路追问的那条主线严丝合缝**。**9/13 问「探针读到 0 分，是不是把真相藏起来了」；9/15 问「分数干净，证据在不在场」；9/23 问「格式全对，答案为什么反了」；9/24 问「输出干净，机密为什么从残差流溜走」；9/26 问「图换成噪点，对齐分为什么照样逼近 1.0」；9/27 问「一张排行榜，为什么唯一站得稳的是倒数第一」；9/28 问「过期的旧文档，为什么能把对的答案改错」；9/29 问「答对了，也可能是蒙对」；9/30 问「答案对了，写出来的推理成不成立」；10/1 问「演得像弱角色，能力是不是真的被压下去」；10/2 问「看起来在自修复，是不是真的在修复」；10/3 问「给 AI 打分的尺子，自己稳不稳」；10/4 问「分数说它会调用工具，是不是真的调用了」**。**它们问的始终是同一件事——一个「读数」，和它「本该对应的那件事」，隔着多远。** **而今天这一篇，把镜头再推前一步**：**前面问的是「一把尺子准不准（10/3）」「一把尺子会不会读错动作（10/4）」；今天问的是——你在「自己训练过的那间考场」里考出的高分，换一间考场、面对另一批题目，还算不算数。**

## 二、核心方法

**方法不炫技，它的分量全在「怎么造出一个能让分数露馅的考场」上。** **论文的核心方法论贡献，是一套「在 agent 真正会用到探测器的地方去评测它」的流程**：**用「干净重放」造出确定无害的工具输出，用「差分重放」给注入输出打上可靠标签，最后用「任务级拦截率」把误报翻译成用户真正会遭遇的代价。**

**第一步：造出「构造上必然无害」的工具输出——干净重放（clean replay）。** **这是整套方法的地基，也是最巧的一步**。**AgentDojo v1.2 为每一条用户任务，都随身带了「解开它的那串真实工具调用」**；**τ-bench 也一样**。**论文的做法是：在默认环境里、不接任何 LLM，直接照着这串真实调用执行一遍，把每个工具返回记录下来**——**因为这些调用本就是解题用的、环境里也没有任何注入，所以产出的每一条工具输出，都是「构造上必然无害（benign by construction）」的**。**这样得到了 AD-Clean（AgentDojo 四个套件、97 条任务、339 条工具输出）和 TB-Clean（τ-bench 675 条零售与航空任务、1,533 条输出）**。**这一步的意义在于**：**它把一个「大模型在不在环里」的变量彻底拿掉了——这些「无害样本」的标准答案，是环境结构给的，不是模型判的，因此可以放心地拿它去量误报。**

**第二步：用「差分重放」给注入输出打标签——因为字符串匹配会骗人。** **光有无害样本不够，还要有「确定被注入」的样本，而且要标得准**。**论文在每条任务的每个注入点上，塞进 AgentDojo 或 InjecAgent 自带的攻击**，**然后「重放同一串真实调用」**；**一条输出被标为「注入」，当且仅当它与「干净环境里同一次调用」的输出不同**。**为什么不用子串匹配？论文给了一个非常具体的理由**：**AgentDojo 会把输出序列化成 YAML，多行的注入文本会被重新折行（re-wrap），你拿原始攻击串去搜，会搜不到——于是漏标**。**用「差分」来标，就绕开了这层格式改写**。**由此得到 AD-Matched（585 无害 / 432 注入，用 3 个攻击模板）、AD-Shift（975 / 720，用另外 5 个模板）、TB-Matched（1,533 / 584，把 InjecAgent 的 62 条攻击全部用到商品目录名这个第三方可控的位置上）**。**这三套还有一层关键设计**：**AD-Shift 与 AD-Matched 用不同的攻击集，专门用来检验「换一批没见过的攻击还灵不灵」**。

**第三步：搭一个横跨三代、两个基准、外加「懂任务判官」的探测器阵列。** **论文从 Hugging Face 上「下载量最高、且标注为提示注入探测器」的文本分类模型出发，再补上 2026 年面向 agent 的新模型**，**最终得到 15 款探测器**：**6 款要过许可证（含 Meta 的 Prompt Guard 1 / 2，86M 与 22M、ProtectAI small v2、两款 Sentinel）**。**它们覆盖三个世代**：**2023–2025 的 DeBERTa-v3 分类器（ProtectAI、JasperLS、TestSavant、PIGuard、Prompt Guard）；2025–2026 的 ModernBERT 与 Qwen3 分类器（两款 Sentinel，以及模型卡明确面向 agent 输入的 Sheltron、Wolf Defender、Horizon-Labs）；还有一款微调过的 1.5B 生成式分类器 Prismor**。**评测严格照模型卡来**：**上下文长度（512 到 2,048 token）、长输入切分方式、输入模板，甚至 Sheltron 的角色 token 与来源 token 都照做**。**除此之外，论文还另设了 2 个「懂任务的 LLM 判官」**：**把「用户请求」和「一条工具输出」一起喂给一个指令微调模型，问它「这条输出是不是想让助手去做用户没让它做的事」，取首 token 上「是」相对「否」的概率**。**判官用 Qwen2.5-7B-Instruct 和 Llama-3.1-8B-Instruct（都 4 比特量化）**。**其中一个细节很关键**：**Llama-3.1-8B 的训练数据截止在 2023 年 12 月，比 AgentDojo 发布早了半年——它不可能「背过」AgentDojo 的题目和攻击模板**，**因此它的探测成绩可以当作一个「没有泄漏」的干净对照**。

**第四步：量什么、怎么量——把「误报」翻译成「任务失败」。** **论文报四个数**：**默认阈值（0.5）下的误报率 FPR、真阳率 TPR、AUROC，以及「1% 误报率下的 TPR」**。**为什么死盯 1% 误报这个点？论文的理由极其务实**：**一个逐条筛工具输出的部署，遇到的无害输出远远多于注入输出，所以「低误报工作点」才是真正要紧的那个点**——**这和会员推断、和可部署注入检测的既有做法一脉相承**。**更狠的一步是「任务级」翻译**：**对 AD-Clean，论文额外报「至少有一条输出被标记的任务占比」——因为只要一条无害输出被拦，用户整条任务就废了**。**这个设计让「误报率」从一个抽象的百分比，变成了「用户有多少比例的任务会莫名其妙地失败」**。**所有区间都是 1,000 次分层百分位自助法的 95% 区间**。

**第五步：审计训练数据，把「分数」和「它为什么会有这个分数」连起来。** **这是全文最能定案的一环**。**论文找到两款「公开了足够多信息」的探测器**：**PIGuard 公布了训练切分，论文把它的训练数据（归一化空白与大小写后）拿去搜「BIPIA 每条攻击串的前 80 字符、每条干净上下文的前 120 字符」；Horizon-Labs 公布了「从公开数据集拼训练集的脚本」，论文下载其中 5 个含 agent / 工具输出注入的源，去搜 BIPIA 攻击串、AgentDojo 模板标志（比如 `important_instructions` 的开场句）、以及 InjecAgent 的 62 条指令**。**论文特别声明**：**这种搜索只找「逐字拷贝」，所以它给出的是「重叠量的下界」——同义改写、同模板生成、未公开的数据，都逃得过这种审计**。**正是这层审计，让「BIPIA 榜首为什么到 AgentDojo 就失灵」从一句猜测，变成了一个可以直接读出来的因果**。

## 三、实验结果

**结果一：在「无害工具输出」上，探测器的误报率从 0% 一路铺到 90% 以上——而这一头才是用户真正会先撞上的。** **在 AgentDojo 上**：**Horizon-Labs 只标记 0.0% 的 AD-Clean 输出（只会打断 0.0% 的任务）、Wolf Defender 0.9%（3.1% 的任务）**；**而 ProtectAI v2 和 PIGuard 分别标记 30.1% 和 29.5% 的输出，会把 69.1% 和 59.8% 的任务拦死**（95% 区间：60–78% 与 51–70%）。**两款 Prompt Guard 2 分别只标记 0.6% 和 0.0%**。**τ-bench 的 JSON 输出上，画面重复**：**Horizon-Labs 0.7%、Wolf Defender 0.0%、Prompt Guard 2 0.0%、Sheltron 4.4%**；**ProtectAI v2 却标了 66.9%、Prismor 标了 46.2%**。**论文特意说明：这些被标记的输出里没有一条指令，图 1 那句「密码已更新」的确认就是典型**。**这里最反直觉的一点是**：**误报行为是探测器一个「稳定的性格」——它在 AgentDojo 上的误报排名，能预测它在 τ-bench 上的误报排名（Kendall τ 稳定且显著）**；**可它跟「在普通文本上的误报」不沾边**：**ProtectAI v2 只标记 0.5% 的网页、1.2% 的邮件，却标记 30.1% 的 AgentDojo 工具输出、66.9% 的 τ-bench 输出**。**论文据此给出第一条发现**：**误报率从 0% 到 90%+ 横跨两个数量级，跨 agent 基准高度一致，且「在普通文本上的误报」完全预测不了它。**

**结果二：把工作点挪到 1% 误报，排名不但低，而且「换榜即失效」。** **在 AD-Matched 上（1% 误报率）**：**三款探测器抓住大部分注入——Horizon-Labs 82.2%、Wolf Defender 73.8%、Prismor 72.2%；Meta 的 Prompt Guard 2 是 69.4%（86M）和 60.9%（22M）**；**其余 DeBERTa 系只抓到 0.5%–27.8%，PIGuard 只抓到 2.1%**。**在 TB-Matched 上**：**Horizon-Labs 100.0%、Sheltron 95.2%、Wolf Defender 90.8%；PIGuard 52.7%、Prismor 15.2%**。**排名迁移有多差？论文用 Kendall τ 量了三个方向**：**BIPIA 与 AD-Matched 之间 τ=0.01——PIGuard 在 BIPIA 上以 95.1% 排第 1，在 AgentDojo 上跌到 15 款里的第 13**；**两个 agent 基准之间 τ=0.28——Prismor 从 AgentDojo 的 72.2% 跌到 τ-bench 的 15.2%，Sheltron 却从 20.1% 涨到 95.2%，两者正好互换位置**；**BIPIA 与 τ-bench 之间 τ=0.31**。**论文特别强调：在 15 个探测器上，这些「探测相关性」没有一个是显著的**。**这就是全文的题眼**：**一款探测器的「探测能力排名」，在不同基准间几乎不迁移——BIPIA 的冠军到 AgentDojo 上只抓到 2.1%，AgentDojo 上抓 72.2% 的到 τ-bench 上只剩 15.2%。**

**结果三：训练数据是唯一的解释，而它揭示的规律是——迁移的是「输入的形态」，不是「攻击的字符串」。** **这一组是全文最硬的部分，论文逐款把「分数从哪来」挖了出来**。**先看 PIGuard 与 BIPIA**：**它的公开训练切分里，装着 1,116 条带标签的完整 BIPIA 输入（完整邮件、表格、代码回答，中位数 715 字符）**。**逐字重叠量大得惊人**：**BIPIA 训练半的攻击串，75 条文本攻击里中了 65 条、50 条代码攻击里中了 6 条；连 BIPIA 31% 的干净邮件、22% 的干净代码上下文都在里面**。**BIPIA 测试半的攻击一条都没出现**，**但因为测试半与训练半出自同一个生成器、又被塞进同类内容里，把评测限制到「测试半」后，PIGuard 的探测率也只从 97.9% 掉到 95.1%**——**论文一句评语很锋利**：**「用一半训练、另一半测试是标准做法，结果是『分布内分数』（in-distribution score）。」** **再看 PIGuard 与 InjecAgent**：**它训练切分里也确实有 53/62 条 InjecAgent 攻击指令，但形态完全不同——是 111 条「攻击 + 一句通用任务句」的短提示（中位数 178 字符），而不是「攻击被裹进工具响应里」**。**这就给了一个完美的受控对照**：**在 TB-Matched 里，每条注入输出形态完全一致**；**PIGuard 抓「训练见过的攻击」52.1%、抓「训练没见过的 9 条攻击」55.8%——见了等于没见**。**那为什么 Horizon-Labs 能行？** **它把 BIPIA 只当评测集、还专门把评测文本从训练数据里剔掉**；**论文审计了它那 5 个公开源，没找到任何 BIPIA 攻击串、任何 AgentDojo 模板、任何 InjecAgent 指令**。**可它偏偏在两个 agent 基准上都夺冠——它和这两个基准共享的，正是「输入的形态」：结构化的工具输出、里面埋着指令**。**最后是 Prismor 的解释**：**它是在两个「提示级（prompt-level）」注入数据集上微调的**；**而 AgentDojo 的模板是「直接对着模型说话」的显式指令（『ignore your previous instructions』『this is an important message』），看起来就像直接提示注入**；**InjecAgent 埋在 τ-bench 商品名里、BIPIA 藏在邮件和表格里的攻击，则完全不是这个形态——于是 Prismor 只抓前者，抓不到后者**。**论文的第二条核心发现就此落定**：**探测器只在「形态像它训练输入」的地方工作；决定它成败的，是训练输入的形态，而不是「攻击字符串有没有重叠」。**

**结果四：让判官「懂任务」，也救不了盲区；而给小型分类器喂用户请求，反而更糟。** **先说判官**：**在 1% 误报率下，Qwen 判官抓到 AD-Matched 的 57.4%、TB-Matched 的 54.3%；Llama 判官抓到 55.3% 和 78.3%**——**都低于最好的专用探测器**，**代价却是每条工具输出都要跑一次 7–8B 的前向**。**值得注意的是 Llama 判官那个 78.3%**：**它训练数据早于 AgentDojo 发布，所以它的探测不可能来自「背过 AgentDojo」，这反过来说明「懂任务的通用模型」确实带着一点真本事**——**但也就到此为止**。**再说「把用户请求喂给小型分类器」**：**论文试着把用户请求作为一个「可信段」喂给 Sheltron，结果 AUROC 从 0.86 涨到 0.91，可 1% 误报率下的探测率反而从 20.1% 掉到 9.0%，同时干净工具输出上的误报率在 AgentDojo 从 10.6% 涨到 26.0%、在 τ-bench 从 4.4% 暴涨到 69.7%**。**论文谨慎地补了一句**：**这种用法模型卡里没写，很可能本身就落在它的分布之外**。**最后是「攻击目标」这层**：**把 BIPIA 测试半按官方五组拆开看，除了「被 BIPIA 喂大的 PIGuard」能覆盖全部组，其余方法只能各抓一部分**。**最难的是「任务无关注入（task-irrelevant）」——那种让模型去干一件毫不相关的无害小事的攻击**：**除了 PIGuard 抓到 93%，最好的 Prompt Guard 1 也只有 39%，其余方法抓到的都不超过 20%**。**其余组则各有偏科**：**Sheltron 抓 87% 的任务相关、88% 的定向注入，却只抓到 16% 的主动代码攻击；Qwen 判官抓 69%/61% 的被动/主动代码攻击，却只抓到 1% 的任务相关**。**论文坦承**：**判官只用了单一提问模板、也没做变体，所以「判官的差距里有多少来自我们问的方式」无法回答**。**第四条发现**：**懂任务的判官抓到 54%–78%，低于最好的专用探测器；给小分类器喂用户请求不解决问题；而在训练分布之外，每个方法都会整类整类地漏，任务无关注入几乎把所有方法都筛掉了。**

**结果五：输入格式和元数据能「免费」帮你把误报砍掉一个量级，但它换不来泛化。** **论文最后量了「把工具输出换个呈现方式」的影响**。**PIGuard 之所以会误标那些 README，是因为里面全是 HTML 表格、徽章和链接，而不是指令**；**把标记剥掉，PIGuard 在 README 上的误报率从 24.6% 降到 5.6%，ProtectAI v2 从 9.8% 降到 4.2%**。**在 AD-Matched 上，把 YAML 的键去掉、只让 PIGuard 看到「值」，它的误报率从 20.0% 降到 6.7%，而真阳率几乎不动（73.1% vs 74.3%）**。**Sheltron 的「来源 token」效果最大**：**把一条工具输出声明成 `tool_result` 而不是 `other`，它在干净工具输出上的误报率从 AgentDojo 的 28.6% 降到 10.6%、从 τ-bench 的 85.6% 直接降到 4.4%**。**但论文立刻把这层「便宜的好处」和「根本的解药」分开**：**在低误报端，这些改动帮不上忙**——**去掉 YAML 键后，PIGuard 在 1% 误报率下只抓到 3.0% 的 AD-Matched 注入、ProtectAI v2 只抓到 13.2%**；**Sheltron 用了「特定来源 token」后抓 20.1%（用通用 token 是 30.3%），在 TB-Matched 上 95.2% vs 92.3%**。**第五条发现**：**「去掉序列化标记 / 声明输入类型」能把默认阈值下的误报降最多约二十倍，这是部署可以白拿的改善；但改完之后，PIGuard 和 ProtectAI v2 在 AD-Matched 上、1% 误报率下，谁也过不了 15% 的探测率——格式能挪动分数，救不活一个「分布外」的探测器。**

## 四、技术启示与发展方向

**第一，这篇论文最该被抄进选型流程的一条：把「榜单分」和「部署表现」当成两件事。** **它用 15 款探测器、3 个基准证明**：**基准分测的主要是「输入形态像不像训练数据」，不是「检测注入的通用能力」**——**所以在你按下「选 BIPIA 榜首」那一刻，你真正买到的，可能只是一张「它见过这张卷子」的证明**。**对照本系列的主线，这句话可以缩成一行**：**呈现（榜单分数）≠ 对应（部署行为）**。**而和 10/4「关键词判卷器失守开门」互补的是**：**10/4 的尺子是「干脆读错了动作」；今天的尺子不读错，它只是「只在它被校准的那张纸上才准」——你换一张纸，它就失灵。**

**第二，论文给出了四条可以直接照做的选型纪律，几乎每一条都在反对当前的惯例。** **①在 agent 自己的工具输出上量误报，并把它翻译成「被拦死的任务占比」——在散文上的误报率预测不了它**；**②固定在一个低误报率上报探测率——在平衡集上的默认阈值准确率，对两种错误都说明不了什么**；**③在信一个榜单分之前，先查「这个探测器是不是在那张榜单上、或用同一种方式生成的数据上训过」，并且优先用「它不可能见过」的评测数据**；**④优先选「训练输入就像它要筛的东西」的探测器**——**在本研究里，Horizon-Labs、Wolf Defender 和两款 Prompt Guard 2，在两个 agent 基准上都把误报压到接近 0、又各自抓到一半以上注入；而前两者（都为「不可信内容进入 agent」而造）抓到了 70% 以上**。**论文还留了一句更冷静的收尾**：**即便这些最好的探测器，也漏掉了大部分「任务无关注入」——所以探测器是一个「和系统级防御搭配使用的过滤器」，不是它们的替代品。**

**第三，一条会重塑「评测数据集」认知的结论：泄漏的形态，比泄漏的内容更隐蔽。** **此前业界对「训练/测试泄漏」的想象，多半停留在「训练集里出现了测试集的文本」**。**这篇论文给了一种更细、更难防的泄漏**：**PIGuard 见过 InjecAgent 的攻击字符串，但因为「形态不对」，见了也没用；反过来说，Horizon-Labs 一条测试文本都没见过，却因为「形态对」，照样在两个基准上夺冠**。**这等于说**：**「有没有重复文本」这种粗粒度的泄漏审计是不够的；真正决定泛化的，是「训练输入的构造形态」和「部署输入的构造形态」是否同源**。**对做数据集、做评测的人来说，这是一条该写进 checklist 的规律**：**审计的不是「你见过哪些句子」，而是「你的练习是用什么方式出的题」。**

**第四，一条能直接省钱的工程结论：「格式工程」是免费的午餐，但别指望它当正餐。** **论文证明，仅仅「把序列化标记去掉」或「声明输入类型」，就能把误报降最多约二十倍**——**这是一个几乎零成本、跟着模型无关的改善**。**但它同时证明**：**这层改善挪不动「分布外」这个根本问题**——**一个在错误分布上训练的探测器，改完格式，1% 误报率下的探测率依然过不了 15%**。**「先修格式、再谈换模型」的顺序，论文替你排好了。**

**第五，边界划得很清，而且划得异常诚实。** **论文承认**：**两个 agent 基准都是模拟环境（AgentDojo 返回合成的 YAML、τ-bench 返回合成数据库的 JSON），真实工具输出（HTML、API 响应、长文档）更脏，而格式又能挪动误报，所以绝对数字在部署里会变**；**在 τ-bench 里，注入点（商品名）和攻击集（InjecAgent）还是作者自己选的，换个位置可能利好别的探测器**——**但「相对结论」（谁爱误报工具输出、面向 agent 的探测器领先）在两个基准上都成立，才是它敢推的**。**它还承认：所有注入都来自基准模板，一个「知道探测器是谁」的适应性攻击者会把每个探测率都再压低，所以它报的是上界**；**商业 API 探测器是闭源的、没纳入**；**只有 PIGuard 和 Horizon-Labs 公开了足够审计的训练数据，其余只能信模型卡**；**判官只是诊断工具、不是防御**；**逐字重叠审计只是下界**。**文末还罕见地交代了 AI 使用情况**：**作者用 Claude 在本人「设定方向、选择假设、管理算力、审阅全部实验与文本」的前提下，实现了实验与分析代码、跑了实验、起草了初稿，并对全文内容负全责**。

## 五、总结

**这篇论文用 15 款探测器、3 个基准和一整套「干净重放 + 差分重放 + 训练数据审计」的方法，把「按榜单分挑探测器」这件业界习以为常的事，做成了一次可测量的证伪。** **表面上，同一个探测器在 BIPIA 上抓 95%、在 AgentDojo 上抓 2.1%，排名从第 1 掉到第 13**；**换个角度，真正稳定、真正会在不同基准间迁移的，是「无害工具输出上的误报率」，而不是「探测排名」**；**再往里挖一层，决定这一切的，是「训练输入的形态像不像要筛的东西」——见过攻击字符串不算数，见过「攻击被裹进工具输出」的形态才算数**。

**论文留下的最核心一击，是那个标题里的双关**：**「Passing the Test You Trained On」——你在自己训练过的那场考试上考得再好，也不能被读成「你会做这类题」**。**它甚至给了一个「干净对照」来钉死这一点**：**Llama-3.1-8B 判官的训练数据早于 AgentDojo 发布、不可能背题，却仍能靠「懂任务」抓到 78.3%**——**这说明有真本事是存在的，只是它和「榜单分」不是一回事**。**对本系列的主线来说，这一篇把「测量有效性」的追问又推进了一环**：**9/27 问「排行榜换个随机种子还稳不稳」，今天问的是更远的一步——「同一张榜上的第一名，换一张榜还算不算第一名；以及你在自己那间考场里考出的分，换一间考场还剩多少」**。**它给出的忠告，几乎可以当作任何一次「按榜单选型」的通用注脚**：**「在你训练过的那张卷子上拿高分，证明的是这张卷子像你的练习题；要证明你会做题，得换一张你没见过的卷子——并且，最好换一间你没去过考场。」**
